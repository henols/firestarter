## Accomplishments

- **D-11 (206-REVIEW IN-02):** `SerialCommunicator.setup_command` now runs `assert self.is_connected(), "setup_command requires an open link"` as its first statement, before the pre-existing comment block and `send_json_command` call. A call on a not-connected link now fails with `AssertionError` at this frame, not later as `send_bytes`'s `SerialError`. The docstring's old passage arguing against a second guard is rewritten to state the assert, its `AssertionError` type, `_probe_port`'s `except Exception` handling (log + `None`, port walk continues), `python -O`'s stripping behavior, and that both production callers (`_probe_port` on a just-constructed communicator; a lease's setup site after its own `is_connected()` check) are unaffected.
- **D-11 harness fix:** the three probe-harness fixtures that replace `SerialCommunicator.__init__` with a no-op (`_probe_with_identity` in `test_fw_update_path_gate.py` and `test_fwguard.py`, `_probe` in `test_hw_revision_gate.py`) each gained one line, `patch.object(SerialCommunicator, "is_connected", return_value=True)`, with a comment naming D-11.
- **D-05 (202-REVIEW WR-01):** Two new tests in `TestVerifyEpromReadAbort` — `test_timeout_just_inside_the_acceptance_window_is_the_intended_abort` (check_time = stop_time + window − 0.001) and `test_timeout_exactly_at_the_acceptance_window_is_the_intended_abort` (check_time = stop_time + window) — both assert `verdict == 1`, pinning the `<=` comparison's inclusive edge. `test_timeout_outside_the_acceptance_window_returns_two` is byte-unchanged. A new comment paragraph above `READ_ABORT_ACCEPTANCE_WINDOW_S` records that the window is derived (not measured under host scheduling/USB latency), names every caller path (`_drive_region_compare` → verify, blank, write blank guard, write --verify), and states the false-exit-2 outcome under extreme latency is accepted, with the write-guard path's false-2 being fail-closed.
- **D-10 (206-REVIEW IN-01):** `EpromOperator.lease()`'s "What a lease removes that is not only time" paragraph now says a lease removes the board reset for every `EpromOperator` call inside the block — on the order of twenty in a default `dev test` plan, a derived count and not a measured one (206-SESSION-COST.md § 3), and cites the measured 15.1% wall-clock saving (206-SESSION-COST.md § 5) — replacing the old unmeasured "roughly thirty calls ... roughly thirty board resets" sentence.
- 3 new tests added (`test_setup_command_asserts_the_link_is_connected_before_sending`, `test_timeout_just_inside_the_acceptance_window_is_the_intended_abort`, `test_timeout_exactly_at_the_acceptance_window_is_the_intended_abort`).
