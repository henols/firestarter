<domain>
## Phase Boundary

This phase gives every open item in the v1.41 close-time audit a final disposition before the
milestone ships. The item list is the `tech_debt` frontmatter of
`.planning/milestones/v1.41-MILESTONE-AUDIT.md`: 26 open items and one closed item kept for the
record (202 WR-02). Each item ends as one of three things:

- **fixed**: a code, record or housekeeping change, with a commit.
- **accepted**: an explicit statement of what is accepted and why, written in the phase record.
- **closed on evidence**: a status change that cites the existing measured record.

The phase carries no requirement IDs. v1.41 is 34/34.

The phase adds no new capability and changes no fingerprint key. The one item that would re-key
filed reports, run_count=1 on a raised step, is kept as it is (D-03).

**Repos touched:** `firestarter_app` (host fixes and tests), `firestarter_fw` (one `CLAUDE.md`
count), meta (`.planning/` records, `WINDOWS.md`, the gitlink advance, three SECURITY.md files).

**Bench:** none. Every item is closed from existing records or host-only tests.

**Push:** none. Nothing goes to `beta` or to the wiki in this phase. A push to `beta` publishes
(root `CLAUDE.md`). The push happens at `/gsd-ship`.

## Existing Code Insights

### Reusable Assets
- `_FakeTime` in `tests/test_eprom_operations.py`: an injectable `monotonic()` sequence. The D-05
  boundary leg reuses it with `[stop_time, stop_time + WINDOW - ε]`.
- `fake_serial.feed(build_frame(...))`: the frame-injection idiom for the read-abort tests.

### Established Patterns
- **Load-bearing docstrings and comments.** This codebase explains invariants at the site. See the
  `_REPEAT_POLICY_OPS` block and the `READ_ABORT_ACCEPTANCE_WINDOW_S` derivation. New comments
  (D-03, D-05, D-09) follow that density.
- **Empty-default discriminators.** `repeat_policy_tag` returns `""` for the default policy so
  filed fingerprints stay byte-identical. D-03 exists to protect exactly this property.
- **Syrupy snapshots are hand-edited, never `--snapshot-update`.** This applies if D-06 or D-07
  changes any pinned `--help` or output snapshot. The WINDOWS entry-2 precedent in
  `.planning/WINDOWS.md` shows how.

### Integration Points
- D-11's assert sits on the path shared by `_probe_port` and the leased `_setup_operation` branch.
  Both call sites have already confirmed `is_connected()`. The full suite must stay at ≥2365
  passed.
- D-13's gitlink advance comes after every app commit in this phase.
