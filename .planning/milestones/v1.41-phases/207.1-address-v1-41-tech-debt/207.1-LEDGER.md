## The D-04 count (for the record; D-03 stands)

Two read-only commands, run from a scratch directory (never comment, label, close or edit an
issue), with `XDG_CACHE_HOME` pointed at that scratch directory:

```
gh issue list -R henols/firestarter --state all --limit 1000 --json number,title,state,createdAt,body
gh api --paginate 'repos/henols/firestarter/issues/comments?per_page=100'
```

`henols/firestarter_prom` resolves to `henols/firestarter`, and a duplicate report is filed as a
**comment** on the prior issue, not a new issue, so comments were scanned too.

**Discriminator:** a report carries the degraded tag when some step with op in `{read, write,
write-partial, verify, erase}` has `run_count == 1`; it is a **default-policy** run when some other
step of that set has `run_count >= 2` (a `--fast` run has every such step at 1). Every matching
report's filed `dedup_fingerprint` was reproduced byte-for-byte from its own JSON, using the
`dedup_fingerprint` pre-image rule with `runs=1` included.

**Result:** 64 issues (40 `[dev test]`), 197 comments, 42 reports carry `steps`, 15 of those carry
`runs=1`. **Default-policy with a raised step: 7 issues, 9 reports** -- #65 (CLOSED), #66 (plus
comment 5698646617), #70, #71, #83 (plus comment 5713093962), #86, #90. The last six are OPEN. In
every one, `read` has `run_count 2` and the cycle-block steps have 1. 6 `--fast`-shape issues are
not counted (#42, #45, #46, #47, #48, #50), because every repeat-policy step in them is already at
1 and none raised. **Tagged through the audit-named `(SerialError, HardwareOperationError)` branch
on the per-step path: 0.**

**The D-03 refinement:** all nine filed reports are the cycle-block shape -- the `hardware_refused`
break plus `_aggregate_cycle_results`'s `if len(results) == 1: return results[0]`, not the per-step
path where the audit-named branch's hard-set `run_count=1` is itself the cause. The CONTEXT
reversal note ("set `run_count` to the nominal `runs` in both branches") would therefore re-key
**none** of the nine filed reports -- only a future default-policy report whose *read* step raises.
Reversing D-03 in full would need a separate change to the cycle-block path and its own declared
re-key record, the same D-11-style record Phase 177 used. **D-03 stands at this count, as locked**
by `207.1-CONTEXT.md`; a zero count would not have reopened it either.
