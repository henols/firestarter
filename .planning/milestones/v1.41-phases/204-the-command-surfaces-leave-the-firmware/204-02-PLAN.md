<objective>
Build the two instruments that make Phase 204's central claim measurable instead of asserted: that
removing the command surface did not remove the verification.

Purpose: FWCMD-04 and the amended FWCMD-05 are properties of different kinds and need different
instruments (D-04). "The call site still exists" is a source-contract property a grep-shaped gate can
prove, and this repository already runs seven of those with a shared, hardened shape. "Each site
raises its own id on failure" is behavioural, and no source scan can prove it — it needs a native
Unity test that drives the operation and reads the bytes that came out. Neither instrument exists
today: `MSG_ERR_VERIFY` is asserted by no test anywhere in the tree, and every native test that
reaches these paths asserts only a generic error response code.

Both instruments exist BEFORE plan 03 sweeps ordinal 4 out of the protocol files, so the sweep runs
with its safety net already committed and already proven to fail.

Output: `tests/test_verify_survival_source_contract.py` — the eighth member of the house
source-contract family — and `test/native/avr/test_verify_error_ids/`, a new Unity suite registered
in `[native_base]` with one filter line and one include line.
</objective>

<design_forks_resolved>
**Fork A — FWCMD-04 gets a NEW module, not a leg bolted onto an existing one.** CONTEXT.md leaves
this open. A new module wins for two reasons the executor should not re-litigate: the seven existing
gates each pin one named property and carry a reasoned census docstring about that property, so a
verify-survival leg inside, say, the write-path gate would make that module's docstring describe two
unrelated contracts; and the new module needs an environment seam of its own for the planted-RED run,
which would otherwise have to be threaded through a module whose other legs must not see it.

**Fork B — the id assertion mechanism is a Serial-capture seam, not a trace diff.** CONTEXT.md offers
both. Capture wins because it already exists, in `test_eeprom28c_sdp`, and because a golden trace
whose ids happen to match misses exactly the severity fork this instrument is for — a recorded trap
in this repository. The capture walks the log-id frame's fixed wire layout (magic, big-endian length,
id byte, parameters, checksum, anchor) and reads the id at a fixed offset, so it needs no lookup
table and cannot drift when a message gains a parameter.

**Fork C — `flash_util_verify_operation`'s timeout leg uses an advancing `millis()` through
ArduinoFake, not a new seam in the shared stub include.** CONTEXT.md worried that no `millis` seam
exists. That is true of `_shared/host_stubs_common.inc` and false of the environment: two suites
already install an advancing counter. Adding a seam to the shared include would change behaviour for
nineteen suites to serve one.

**Fork D — the planted RED is planted into the REAL file and then restored, not driven through the
environment seam.** The house docstrings record this preference and the reason: the seams bind at
import time, so a post-import monkeypatch does nothing and would produce a RED that proves the wrong
thing. The seam exists for other purposes and its non-vacuity legs must never read it.
</design_forks_resolved>

Create `firestarter_fw/tests/test_verify_survival_source_contract.py` as the eighth member of the
house source-contract family. Copy the family's shape element for element; do not invent a new
scanner. Seven analogues exist and they share every helper this module needs.

**Scan targets and resolution.** Resolve a repository root from the module file's own resolved parent
directory, then build every scan path relative to that root. The eprom source is the one target that
also honours an environment override, so the planted-violation run has a documented seam; the
parameter table and the shared-verify definition targets do NOT honour any override, and the
non-vacuity leg recomputes the default eprom path fresh rather than reading the seam. This split is
the family's convention and it is what stops a mis-resolved directory from turning the gate into a
no-op.

**Needles.** Build every literal this module searches for from at least two concatenated pieces, so
the module cannot match itself. The three this gate needs are the shared final-pass verify function
name, the plus-final verify-mode enumerator name, and the enumerator's own definition token for the
parameter-table leg. Carry the family's comment above them explaining that a gate quoting its
forbidden tokens verbatim matches itself and can never pass.

**Helpers.** Copy the shape-preserving comment stripper verbatim from the analogues — it replaces
each stripped span with whitespace of the same shape so line numbers survive — and copy the
brace-matching helpers from the region gate. Containment is proven by finding the plus-final arm's
opening brace, walking to its matching close, and searching only that span. Never use line proximity:
a proximity test is a guess, and this one is not.
