<objective>
Retire wire ordinal 4 from every remaining site in the firmware and from the host ladder, and
re-anchor every gate and golden the removal moves — in three commits, each of which leaves the tree
green.

Purpose: this is the expansion half of the sweep D-01 locks. Plan 01 proved the shape on ordinal 6,
including on silicon; this plan applies it to ordinal 4, which is the larger and riskier half. Eleven
source sites rather than six, five protocol handlers rather than one, two behaviour-bearing collapses
inside the region-scoped blank check, a whole emit-and-ack block in the single-step callback, four
native test files that stop compiling or stop meaning anything, three source-scan gates whose pinned
counts move, and a golden whose recorded line numbers all shift.

The three commits are ordered by what each one reddens, not by file type. The collapses redden
nothing, so they go first and alone — they are the only edits in this phase that change behaviour
rather than delete a reference, and they deserve an isolated commit a bisect can land on. The five
protocol handler arms redden the region-scoped census gate, the branch-inventory gate and its golden,
and three native suites; all of that lands with them. The two `#define`s go last, because a define
cannot be deleted before its references, and they take the wrapper, the declaration, the dispatch arm,
the admission arm, the two count-bearing gates, the two compile-driven native re-keys and the entire
host ladder with them — the last of those in a paired commit, per the standing rule that the two
constant ladders move together.

Output: a firmware that carries no retired ordinal anywhere, two reserved-ordinal records, a
re-derived golden, and a host whose COMMAND ladder matches.
</objective>

<design_forks_resolved>
**Fork A — the Phase 201-05 nine-site region gate is RE-ANCHORED, not retired.** CONTEXT.md leaves
this open and explicitly asks for the reasoning to be stated. Measured: only ONE of that module's
legs breaks — the function-pointer census, which goes from six assignments to one. The other legs
stay green, and one of them is the fence that keeps the region-scoped body at exactly one call site.
Retiring the module would drop that fence for the whole of Phase 204 into Phase 205, and Phase 205 is
the phase most likely to widen it. The re-anchor is one number plus a docstring correction;
retirement costs a real guarantee to save nothing. Phase 205 deletes the functions and retires the
module then, which is the phase where retiring it is free.

**Fork B — the SRAM case-group's blank-check assertion is DELETED, not re-keyed.** It asserts that
the SRAM configure handler leaves the operation-main pointer NULL for the blank-check ordinal, and
its own message records a disposition of KEEP from an earlier phase. After this sweep it is a
statement about an ordinal that does not exist and would pass vacuously. Delete the blank arm, keep
the erase and chip-id arms, and say so in the phase record — a vacuous assertion carrying a KEEP
rationale that no longer applies is worse than no assertion, because a reader trusts it.

**Fork C — the eprom validation suite's chunking test is RE-KEYED by assigning the whole-device
blank-check function to the operation-main pointer directly.** That test guards the chunking and
cursor-restore contract, which survives until Phase 205, so it must not be deleted. Assigning the
function directly is the smallest change that keeps the contract under test once the protocol handler
no longer assigns it, and it makes the test's dependency explicit rather than routed through a
handler arm that is about to disappear.

**Fork D — the NOR-unlock and 28C no-VPP tests are DELETED.** Each asserts that configuring the
blank-check ordinal engages no VPP. After the sweep that ordinal reaches no configure handler at all,
so the assertion is true for a reason that has nothing to do with what it was written to check. There
is no surviving ordinal for which the same claim is interesting on those two handlers — their other
ordinals already have their own coverage. Record the deletion and the reason.

**Fork E — three commits, ordered by what each reddens.** Research recommended one commit for the
whole sweep plus every re-anchor. Three is better and satisfies the same property: each commit
carries every gate its own edits redden, so each boundary is green, and a bisect landing between them
finds a coherent tree rather than a half-swept one. The one constraint research named that MUST hold
is that the eprom source and the branch-inventory golden land together; that is commit two.

  <action>
One commit, two files, and nothing else. This is the only task in the phase that changes behaviour
rather than deleting a reference, which is why it lands alone: a bisect that stops here finds a tree
where exactly one thing moved.

**In the memory source's region-scoped blank check.** Two command-keyed branches exist purely to
serve the standalone command. The first stashes the not-blank offset and value into the data buffer
instead of emitting, so the single-step callback can emit it later in communication mode; its else
arm does the direct emit. The second suppresses the progress emit for the standalone command only.
Collapse both: keep the direct error emit unconditionally, keep the progress emit unconditionally,
and delete the stashing arm and the suppression condition.

Rewrite each site's comment rather than deleting it. The reasoning it carries is still worth having,
and after the collapse it reads differently: the deferral existed because this function runs in
programmer mode where the logging entry point is gated on communication mode on the smaller board, and
the only caller that needed deferral was the standalone command, which no longer exists. State that
the surviving callers are write-init and erase-end, that both already took the direct-emit arm, and
that the deferral machinery went with the ordinal. Follow the house convention: state the reason,
cite by content or by function name with a line alongside, never a bare line number.

**In the operation-utilities single-step callback.** Delete the whole command-keyed block, from its
opening condition through its closing brace, including the deferred error emit, the deferred progress
emit and the acknowledgement wait inside it. The acknowledgement wait's long comment records a real
defect — a one-way emit loop that never consumed its acks and desynced the port — so do not simply
drop that knowledge. Leave a short note in its place recording that the block existed to keep one
frame balanced by one ack for the standalone command's deferred emits, that the standalone command was
retired in this release, and that the remaining emitters on this path do their own acknowledgement
waiting.

**Prove the collapse, do not assume it.** D-01 requires this. Before committing, establish that the
surviving callers take the same path they took before: the direct emit, unconditionally. Drive the
chunking and cursor-restore test and the whole eprom validation suite, and record in the SUMMARY that
