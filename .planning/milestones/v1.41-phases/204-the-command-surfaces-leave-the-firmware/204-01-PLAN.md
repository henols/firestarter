<objective>
Retire wire ordinal 6 end to end, in one lockstep commit pair, and then watch a real published host
be refused by it on real silicon.

Purpose: this is the tracer slice for Phase 204. It wires every layer the phase touches — the
firmware CMD ladder, the admission predicate, the dispatch switch, the operation wrapper and its
declaration, the protocol `configure_memory` arm, a native Unity suite, a committed source-contract
gate, the host COMMAND ladder, the one live host consumer, the host test suite, and the bench — for
exactly one of the two ordinals. The thing it proves that nothing else can is that
`pio run -e leonardo -t upload` reaches the attached Leonardo from inside this devcontainer. That
assumption is load-bearing for every REL-02 and REL-03 leg in the phase and no upload has ever been
attempted here. Discovering it at wave 1 costs one commit; discovering it at wave 5 costs the phase.

The slice also buys a control the final four-role matrix cannot: with ordinal 4 still live, the
`3.0.0b49` host's `blank` is SERVED on the same board in the same session where its `verify` is
REFUSED. That is a positive and a negative control side by side, and it rules out "the old host
fails against this firmware for some unrelated reason" without argument.

Task 1 also makes the phase's instruments usable and its requirement true: `firestarter_app/.venv311`
currently holds a broken interpreter symlink into a deleted scratch directory, so every host verify
command in this phase is dead until it is rebuilt; and FWCMD-05 as written in `REQUIREMENTS.md` is
factually wrong about two of its three named sites (D-03).

Output: an amended FWCMD-05 and ROADMAP criterion 3, a working 3.11 host test interpreter, the
firmware and host commit pair that retires ordinal 6, and
`204-BENCH-TRACER.md` recording the flash, the refusal, the served control and the read-back
equivalence with the shas that produced them.
</objective>
