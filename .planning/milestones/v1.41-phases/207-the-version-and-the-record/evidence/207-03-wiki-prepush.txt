+## 3.1.0b1 — verify and blank check run on the host
+
+From CLI and firmware `3.1.0b1`, `verify` and `blank` read the chip with an
+ordinary read and compare on your computer. The firmware's own verify command
+(command 6) and blank-check command (command 4) are removed, and those two
+numbers will never be reused for another command. The CLI now also runs the
+check that a chip is blank before a write, which the firmware used to run;
+`write -b` still means "skip that check", and the erase still runs. See
+[Writing-and-Verifying](Writing-and-Verifying) for the full description of
+`write -b`, `--verify`, `--full`, `verify`, `blank` and `erase -b`.
+
+### An older CLI on 3.1.0b1 firmware
+
+**An older CLI's `write` no longer refuses a non-blank UV EPROM.** Before
+`3.1.0b1` the firmware refused that write; from `3.1.0b1` the CLI refuses it,
+and an older CLI has no such check, so the write starts on a chip that is not
+blank and fails partway, leaving it partly programmed.
+
+| Command | What happens |
+|---|---|
+| `verify` | Refused before the chip is touched, printing `ERROR: Unknown command: 6`, exit 1. |
+| `blank` | Refused the same way, printing `ERROR: Unknown command: 4`, exit 1. |
+| `erase -b` | Erases, then does not check, and reports success on the erase alone (from the code; not yet observed on hardware). |
+| `dev test` | Its verify and blank-check steps are refused, so the report describes the version mismatch rather than the chip, and must not be submitted. |
+| `fw` and `fw -i` | Offer to install `3.1.0b1` firmware, which must not be accepted before the CLI is upgraded. |
+
+### A 3.1.0b1 CLI on older firmware
+
+`verify` and `blank` work. `write -b` onto a non-blank UV EPROM is refused by
+the older firmware, quoting `ERROR: Not blank, at 0x000000, v: 0x11` (the
+address and value vary); `dev test`'s UV slot writes are refused the same way.
+Plain `erase`, without `-b`, on electrically erasable parts that use the
+UV-EPROM programming path (the W27C512, for example) now also runs the older
+firmware's blank check after erasing, so an erase that leaves stray bits fails
+where it used to report success (from the code; not yet observed on hardware).
+The fix for every row: `firestarter fw -i`.
+
+### What to do (from 3.1.0b1)
+
+**Upgrade:** upgrade the CLI first:
+
+```bash
+pip install --pre --upgrade firestarter
+```
+
+Confirm `firestarter --version` prints `3.1.0b1` or later, then flash the
+firmware:
+
+```bash
+firestarter fw -i
+```
+
+`firestarter fw` then shows the firmware version. To stay on an older CLI, pin
+the firmware instead:
+
+```bash
+firestarter fw -i --firmware-version 3.0.0b35
+```
