<objective>
Give verdict 2 an honest landing, and fix the fold that would otherwise turn it into a false green.

Purpose: DEVTEST-01's routing already happened. Phase 202 moved `verify_eprom` and `check_eprom_blank`
onto `COMMAND_READ` plus the host `CompareAccumulator`, and Phase 204 retired the firmware ordinals 4
and 6 they used to compose. What Phase 202 deliberately left behind are two one-line adapters that
flatten the new int verdict back to the old bool, each carrying an in-source marker naming this phase
as its owner. So the remaining work is a **verdict-vocabulary migration**, not a routing job: give
verdict 2 (transport / hardware refusal) somewhere honest to land, so a triager is pointed at the cable
when it was the cable and at the chip when it was the chip.

That migration cannot land first. `_aggregate_cycle_results` builds its folded `StepResult` with nine
keywords and no `status=`, so `STATUS_ERROR` is erased for every step inside the cycle block — and
`VERDICT_SKIPPED` contributes exit code 0. Routing verdict 2 to SKIPPED before fixing the fold would
make a transport-failed `dev test` run exit 0 and print a clean pass. That defect is already reachable
today through `_run_step_untimed`'s `SerialError` arm; the migration makes it routine.

Output: a transport fault that exits 2 end to end, and two dispatch arms that tell the three outcomes
apart.
</objective>

## Decisions

There is no `206-CONTEXT.md`. The user was offered discuss-phase and chose to plan without it, so every
design fork below is a planner decision, recorded here so verify-phase and the phase record can cite it
rather than reconstruct it. `206-RESEARCH.md` § Open Design Forks enumerates the alternatives.

- **D-01 (fork F3, and RESEARCH Open Question 2): verdict `2` lands on `VERDICT_SKIPPED` + `STATUS_ERROR`, not `VERDICT_BAD`.** Reason: this is the two-axis vocabulary `_run_step_untimed`'s `SerialError`/`HardwareOperationError` arm already uses for exactly this class of fault; it needs no new constant, and a sixth verdict is forbidden by the ROADMAP constraint quoted at `cli_handlers.py:2647-2650`. **This is the classification whose meaning changes, and DEVTEST-03 requires it be stated rather than absorbed:** a blank check or verify that failed on transport used to report `BAD`; it now reports `SKIPPED` with `STATUS_ERROR`. **Consequence, recorded deliberately:** those runs' `dedup_fingerprint` per-step triple moves from `blank-check=BAD:` to `blank-check=SKIPPED:`, so that narrow population — rig faults, never chip findings — stops grouping with its pre-206 self. That is the intended direction of DEVTEST-02's "no two mechanically different runs silently merge", not a regression, and it is stated here rather than discovered later. The rejected alternative, keeping `BAD` and adding only `STATUS_ERROR`, would re-key nothing but would leave a cable fault contributing exit 1 and counting as a step that "ran" — the exact defect the pending todo names.
- **D-04 (fork F1): `OP_VERIFY`'s fingerprint keeps its current source** — the gated `_read_region` read-back on failure, `_synthesized_match_fingerprint` on a pass. Reason: sourcing it from the verify's own `CompareResult` is strictly better information but requires `full=True`, which forfeits the abort's saving on every failing verify and changes behaviour on the abort path that DEVTEST-01 does not ask about. Filed as a todo naming this phase's record as its evidence.
- **D-09: the `FP_TRANSPORT` classification bucket stays dead, and the phase record says so.** Reason: `_run_cycle_block` calls `_run_step` with `runs=1`, so `repeat_divergent` is permanently `False` and `classify_streamed` can never select that bucket. A reader of "transport failure now has its own verdict" will reasonably infer the bucket became live; Phase 178 already made that inference and it was false on arrival. Making it live means re-plumbing `runs` through the cycle loop, which is a separate change with its own fidelity argument.
- **Deferred again: CMP-F1**, the `DONE`-based clean stop in `op_wait_for_ack`. `205-CONTEXT.md` named this phase as its home. It is a firmware change and the ROADMAP marks Phase 206 `Repo: app`; no requirement of this phase names it. Deferred explicitly rather than silently omitted.
