Finish FWBLANK-05's measurement and annotate the two catalog ids the sweep orphaned on one side but not
the other.

Purpose: FWBLANK-05 asks for a number rather than an estimate, and this is where the number becomes
final. Three measurements now exist on three different trees — phase entry from plan 02, post-sweep from
plan 05's task 1, post-fix from plan 05's task 2 — and the record has to state which arithmetic produces
which claim, because the phase both removed code and added some. The removal's reclaim is the
requirement's subject; the fix's cost is a separate, smaller line that must not be netted into it
silently in either direction.

`mem_util_blank_check_region`, so the firmware stops emitting it — but it is not orphaned on the host. A
post-205 host still receives 0xB0 from pre-205 firmware, which is exactly the skew plan 07 puts on
silicon, and retiring it from the host's catalog module would make that real refusal render as an
unknown id. It stays, and its comment records why. `DBG_FLAG_SKIP_BLANK` becomes the third orphaned
debug id and takes the plain annotation Phase 204 executed twice.

Output: a completed FWBLANK-05 record with twelve digests and three shas, and a meta-repo-only docs
commit that reaches no generated artifact.
