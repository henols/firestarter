<objective>
Land the phase's tracer: one production-quality end-to-end path in which `firestarter verify
<chip> <file>` reads the chip with the read ordinal and compares on the host through a new streaming
engine, against firmware that still carries the verify ordinal.

This plan creates `firestarter/compare.py` (D-01), gives it the streaming accumulator that is the
phase's single divergence implementation (D-02), the pull-callback expected side (D-04), the
compare-versus-render separation every later consumer needs (D-05), the `Mismatch 0xSTART-0xEND
(N bytes)` line (D-13) and the retained-range cap (D-16) — then rewires `verify_eprom` and the
`verify` CLI command onto it under the exit-code contract D-10 locks.

D-15 is already applied upstream: CMP-04 and ROADMAP success criterion 3 were amended in commit
`81414f98` to drop the expected and actual byte values. Do not print byte values and do not re-open
that wording.

Purpose: prove the architecture end-to-end before any layer is built out, and prove the host half
stands alone while the firmware ordinals still exist (phase success criterion 1).
Output: a working host-side `verify`, exit 0 on match and 1 on mismatch, with the engine, its
result type and its renderer in place for plans 02 through 05 to expand.
</objective>

`CompareAccumulator` — the single streaming divergence implementation D-02 requires. Constructor
takes keyword-only `addr_base: int = 0` and `max_ranges: int = MAX_RETAINED_RANGES`.
`feed(address, expected, actual)` uses the three-tier per-chunk path RESEARCH.md measured: add
`actual.count(0xFF)` to a running `ff_count` and `len(actual)` to a running total, both at C level;
then test `expected == actual` and, when equal, close any open range and return without touching a
single byte in Python; only for a chunk that differs, build a list comprehension of the differing
absolute offsets, whose length is bounded by the chunk size and which goes out of scope at the end of
`feed`. Record `first_offset` if unset, add to `bad`, and for each candidate bit `k` add
`sum(1 for o in offs if (addr_base + o) & (1 << k))` to a per-bit `set_count`, with the bit loop
outside the offset loop and never nested per offset. Coalesce the offsets into `MismatchRange`
objects, extending the open range when the next offset is contiguous with it, retaining at most
`max_ranges` and counting every further range and its bytes into `extra_ranges` and `extra_bytes`.

This shape is load-bearing and is the plan's answer to a trap RESEARCH.md measured. A literal reading
of D-02 that avoids lists entirely produces a per-byte, per-bit nested loop costing 19.8 to 21.4
seconds over 512 KiB, in the test suite and in production. D-02 forbids a device-sized offset list; a
per-chunk list bounded by the chunk size and discarded at the chunk boundary is a different object,
and it is eleven times faster. The equality fast path takes a clean 512 KiB compare to 0.002 seconds.
Do not write the version that avoids lists.
