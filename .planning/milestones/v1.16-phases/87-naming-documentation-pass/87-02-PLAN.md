<objective>
Add ONE rationale header-comment block per firmware handler file (D-03/D-07, NAME-02) — placed
directly under the existing MIT license header — stating the *why* (timing / VPP routing / pin
behavior) with an anchored datasheet citation (filename + section/page), and naming the INV-0x ids
that handler owns so the PROTOCOLS.md matrix is greppable across doc + handler + test (D-05). Full
prose lives in PROTOCOLS.md; the inline block is the concise why+cite. Plain C comments only — no
PROGMEM/PSTR/LOG_ strings (D-10 zero-flash discipline).

Purpose: NAME-02 — each handler's rationale becomes legible and datasheet-traceable in-source,
and the INV ids become the SAFE-02 greppable contract the recompose phases consume.

Frozen-world enforcement (no executable code changed): this plan's `<verify>` carries a
comment-only diff guard — after edits, the `git diff` on each touched handler must add ONLY comment
lines (every added non-blank line matches a `//`, `/*`, `*/`, or `*`-continuation pattern). The
Plan 04 Leonardo flash-delta gate (now failable, anchored on the Plan 01 baseline) is the explicit
executable-change BACKSTOP — comments cost zero flash, so any non-trivial flash delta proves an
executable/PROGMEM change slipped past the diff guard.

Output: 10 firmware source files in the firestarter sub-repo with rationale header blocks.
</objective>
