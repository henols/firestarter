<objective>
Build the physical DIP24→DIP32 adapter per `firestarter/doc/AT28C04-ADAPTER.md` and validate it with
a DMM continuity check — ESPECIALLY the /WE reroute (chip pin 21 → socket pin 30 against
`DIP32_28C512_EEPROM`) — BEFORE any chip is inserted. This is the GATING hardware step (ADPT-01): the
rest of Phase 80 is hardware-blocked on it. Also establish the standing bench precondition (board,
shield rev, r1 readback, port identity) and confirm an AT28C04/AT28C16 chip is on hand for the later
bench proof.

Purpose: ADPT-01 — the adapter is the only hardware gate in this phase. The pin-map is VERIFIED
ground-truth (Phase 76 D-04). The /WE reroute is the single error-prone wire (chip pin 21 is D7 on a
straight DIP32 layout; it must instead reach socket pin 30). Because the 0x0D handler is VPP-free
(5V-only), a mis-wire degrades to NON-FUNCTION, not chip damage — the lowest hazard class in v1.14 —
but the graduation still requires this build + the FINAL bench proof (Plan 04).

Output: 80-01-SUMMARY.md with the hardware gate verdict and bench precondition record. If the adapter
cannot be built or no chip is on hand, the SUMMARY records a CLEAN DEFERRAL (mirroring Phase 78 FUT-01
and Phase 79's NOT CLEARED halt): no DB/code change, chips stay honestly `adapter-required`, Plans
02/03/04 are BLOCKED, and a FUT-04 item is recorded.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| AT28C04/AT28C16 DIP24 chip ↔ DIP32 ZIF socket | the physical adapter remaps every pin; a wrong wire (esp. /WE pin 21) routes firmware signals to the wrong chip pin |
| firmware 0x0D handler → socket | `configure_eeprom28c` is 5V-only; it never asserts the VPP rail, so the worst case of a mis-wire is non-function, not over-voltage |
