  <action>
Create `firestarter_app/tools/check_diagnostic_report_claims.py`. Module docstring: purpose (scans
`diagnostic_report.py`'s string literals — the `dev test` report text every community run produces —
against v1.30's forbidden-claim vocabulary; the surface `check_permitted_claims.py` in the meta repo's
Phase 137 directory does not and cannot reach); exit-code contract; explicit non-claim (this gate
catches literal forbidden phrases baked into the source NOW — it cannot catch a future f-string that
assembles a forbidden phrase at runtime from user data, and it is not a substitute for the meta-repo
gate or the CLOSE-06 operator review, both of which cover different artifacts).

Module-top path constant, mirroring the analog:
- `_HERE = os.path.dirname(__file__)`.
- `_DEFAULT_DIAGREPORT_SRC = os.path.join(_HERE, "..", "firestarter", "diagnostic_report.py")`.
- `FIRESTARTER_DIAGREPORT_SRC = os.environ.get("FIRESTARTER_DIAGREPORT_SRC", _DEFAULT_DIAGREPORT_SRC)`
  — env-override seam (mirrors `FIRESTARTER_DISP01_REPORT`), lets the paired pytest point this checker
  at the committed planted-violation fixture without editing the real source.

**Vocabulary:** copy `FORBIDDEN_PATTERNS` (all 14 entries) and `REQUIRED_CAVEAT_PATTERN` verbatim from
`.planning/phases/137-close-honesty-ledger-claim-gate-gh12-followup/check_permitted_claims.py` (plan
137-01) — same labels, same regexes, `re.IGNORECASE`. **Do not require the caveat sentence's presence
in this file** — `diagnostic_report.py` is a rendering module, not a claims essay; it is scanned only
for the ABSENCE of forbidden phrases, never for the PRESENCE of the caveat prose (which would have no
natural home in a report renderer's string literals). Record this asymmetry explicitly in the
docstring so a future reader does not "fix" it into requiring a caveat here.

**Extraction:** `ast.parse` the source, walk with a fresh `ast.NodeVisitor` subclass collecting every
`ast.Constant` node whose `.value` is a `str` (Python 3.8+ `ast.Constant`, not the deprecated
`ast.Str`) together with its `.lineno`. Concatenate all collected strings (each on its own line, so
line numbers stay meaningful in the FAIL summary) into one scan buffer; run `FORBIDDEN_PATTERNS`
against it exactly as `check_permitted_claims.py`'s `scan_text` does (no proximity window needed here
— every string literal in this file is already SDP/diagnostic-report context by construction, so
windowing would add complexity with no signal).

**`main(argv)`:**
1. Resolve target: `argv[0]` if given, else `FIRESTARTER_DIAGREPORT_SRC`.
2. If the resolved path is not `os.path.isfile`, print `FAIL: scan target not found on disk -- <path>`
   and return 1 (fail-closed, mirrors the analog's mandatory-target discipline).
3. `ast.parse` it; on `SyntaxError`, print `FAIL: could not parse <path> as Python` and return 1 (never
   silently skip an unparsable file).
4. Extract all string literals, scan for forbidden matches.
5. On any match, print a `FAIL:` bucket (label, matched substring, line number) capped at 20, return 1.
6. Otherwise print `PASS: scanned <path>, N string literals checked, zero forbidden matches` and
   return 0.
Guard with `if __name__ == "__main__": sys.exit(main(sys.argv[1:]))`.
