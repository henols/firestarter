the token check, but the self-verifying rule needs the OR explicitly — see below). Record in a comment:
this is a recorded, accepted false-negative risk (a genuinely bad sentence on a line with no nearby
SDP/AT28C/0x0D token would be missed) — deliberately accepted because all four of this phase's real
target artifacts are entirely about this milestone's SDP work, matching v1.23's own accepted trade-off
for its `py32` window.

**`self-verifying` rule specifically:** a hit is a violation only if `_SELF_VERIFYING_PATTERN` matches
AND neither the literal word `"emission"` NOR `REQUIRED_CAVEAT_PATTERN` appears within the same
`[i-1, i, i+1]` window. (I.e. "self-verifying" is permitted when qualified by "emission" or already
carrying the caveat nearby — e.g. "a self-verifying SDP lifecycle for lock EMISSION" is fine; bare
"the new SDP lifecycle is self-verifying" with no nearby qualifier is not.)
