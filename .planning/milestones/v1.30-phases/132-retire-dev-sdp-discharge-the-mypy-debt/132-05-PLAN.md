<design_decisions_resolved_at_plan_time>
132-PATTERNS.md flagged two unresolved risks and instructed the planner to decide them rather than defer.
Both are decided here, with reasoning, so the executor implements a choice instead of improvising.

**Risk A -- the error-relocation trap. Decision: narrow inside the factory, once, with an explicit
per-field cast at the point where a double is admitted.**

The trap is real and measured. Callers pass a spec'd `Mock`, whose *static* type is `Mock`, not the real
class. Annotating a parameter as the real class or `None` therefore does not remove 25 errors -- it
**moves** them to roughly 25 call sites. `tests/test_dev_test_cmd.py` alone has 23 call sites passing
doubles.

The tempting alternative -- retype the modules' mock builders so the casts live there, e.g. making the
clean-operator builder return the real operator class instead of `Mock` -- is **rejected**, and the
rejection is measured rather than aesthetic. Those variables are then used for mock assertions, and a
variable typed as the real class does not have the mock assertion methods, so every assertion-called
site becomes an attribute error. The tree already carries the receipt: `tests/test_validate_family_cmd.py:221`
has a `# type: ignore[attr-defined]` on exactly that shape, and `tests/test_dev_test_cmd.py:597-598`
carry two live errors of exactly that class today. Casting at the builder trades 25 argument errors for a
comparable pile of attribute errors -- relocation, not discharge.

So: each parameter is annotated to accept the real type, or a `Mock`, or `None`, and each of the six
values handed to the `AppContext` constructor is narrowed with an explicit `cast` to the real field type,
inside the factory. Six casts, one file, one function.

What this buys, stated precisely so nobody overclaims it: a wrong-typed **non-double** argument -- a
string, an int, the wrong manager class -- is still rejected at the call site, which the `object` splat
never did. What it does not buy: the factory does not verify that a double's spec matches the field.
The spec argument is the runtime check for that and it stays where it is. Both halves go in the factory's
docstring. Do not describe the factory as making the container type-safe.

**Risk B -- does `tests.conftest` join a mypy strict island? Decision: NO, and the reason is mechanical
rather than a judgement call.**

`check_untyped_defs` governs only the bodies of **unannotated** defs. A fully annotated function's body is
always checked, at any setting. That is precisely why the 30 errors exist today: all five modules carrying
them are in **no** strict island, yet their annotated factories' bodies are checked and their errors
counted. The new factory will be fully annotated, so **it is type-checked from birth with no
`pyproject.toml` change at all** -- the guarantee RETIRE-05 asks for is already mechanical.

Adding `tests.conftest` to the Phase-36 test island would additionally switch on body checking for
conftest's *unannotated* defs -- the serial-communicator factory fixture and its inner closure, which
assign a dozen attributes onto an object created via `__new__`. That plausibly **adds** errors, buys
RETIRE-05 nothing, and expands scope into a file this phase is only extending.

The honest residual, to be written into the factory's docstring and the plan summary rather than left
unexamined: conftest's pre-existing unannotated fixtures remain unchecked, so RETIRE-05's guarantee is
specifically "the typed factory's own body is checked, and a new module importing it cannot reproduce the
30-error pattern" -- **not** "everything in conftest is type-checked". Anyone reading RETIRE-05's wording
as the latter is reading more than this phase delivers.
</design_decisions_resolved_at_plan_time>
