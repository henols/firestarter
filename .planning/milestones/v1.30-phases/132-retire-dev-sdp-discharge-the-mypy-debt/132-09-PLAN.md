<objective>
Certify the `ci` job green, read the evidence rather than computing it, run the parity recipe on the far
side of the change, and write the phase record with its residuals stated plainly.

Purpose: this is RETIRE-06 and ROADMAP criterion 4, and it is the phase's durable value. `firestarter_app`'s
primary `ci` job has been red for two months, and it went unnoticed because the workflow's push trigger is
main-only so the gate was invisible outside pull requests and manual dispatches. Green here is not cosmetic:
it is what makes every later phase's "green suite" claim checkable at all. It is also the run that discharges
Phase 131 D-11's deferred promise that this phase's own dispatch would be the hardened-gate-in-CI proof.

This plan is **not autonomous**. The milestone branch does not exist on origin and the workflow triggers on
pushes to the default branch only, so certification costs exactly two privileged operator actions -- one
branch push and one workflow dispatch -- and the dispatch is additionally blocked for agents by Claude
Code's auto-mode classifier regardless of the project allowlist. Everything downstream of the dispatch is
automatable: read-only run inspection works.

record, and the final requirement tick.

requirement was completed by an earlier plan -- RETIRE-01 by 132-04, RETIRE-02 and RETIRE-03 by 132-03,
RETIRE-04 and RETIRE-08 by 132-08, RETIRE-05 by 132-05, RETIRE-07 by 132-07. Do not re-tick any of them and
