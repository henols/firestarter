Create `firestarter_app/tests/test_sdp_recovery_wording.py`. It must run in standalone CI: no syrupy
capture, no firmware-sibling decorator, no `requires_fw` marker, no network, no hardware.

**A. Vocabulary constants.** Define `_REQUIRED_RECOVERY_WORD = "rewrite"` and
`_FORBIDDEN_RECOVERY_WORD` set to the five-letter word for bulk clearing (spelled `e`,`r`,`a`,`s`,`e`).
Note in the module docstring why the forbidden word matters: protocol `0x0D` has **no** bulk-clear
operation at all, so naming one is not a style issue — it is actively wrong advice to a user holding a
locked part.

**B. `_scan_recovery_constants(named_values: dict[str, str]) -> None`** — the gate. For each
`(name, value)`:
1. it must contain `_REQUIRED_RECOVERY_WORD` (case-insensitive) when the constant describes recovery —
   apply this to every name in `SDP_RECOVERY_CONSTANT_NAMES` and to `_ALWAYS_WRITES_NOTICE`;
2. it must **not** contain `_FORBIDDEN_RECOVERY_WORD` (case-insensitive) as a standalone word;
3. it must contain no hyphenated op literal — check membership of every value in
   `chip_test._SDP_LEG_OPS | chip_test._SDP_OPS` as a substring (this folds RESEARCH OQ-5's hazard into
   the same place, so one gate covers both).
Raise `AssertionError` naming **every** offending `(name, rule)` pair, not just the first — mirror
`_assert_op_parity`'s aggregate-then-raise shape.

**C. Fail-closed legs.** Two, mirroring `test_check_sdp_capability.py`:
- `_scan_recovery_constants({})` — a zero-symbol scan must **raise**, never pass. A gate that scans
  nothing and exits clean is exactly the defect this project shipped in v1.23 P129/P130.
- a resolver leg: resolving a name that does not exist on `firestarter.cli_handlers` must raise, so a
  future rename cannot silently empty the scan set.

**D. The target-resolution legs.**
- Assert `SDP_RECOVERY_CONSTANT_NAMES` is non-empty and that every name resolves to a **non-empty
  `str`** attribute on `firestarter.cli_handlers`.
- Assert the scan set has at least the expected number of members, so a silent shrink of the tuple is
  caught.

**E. The positive control, FIRST.** A test that runs `_scan_recovery_constants` over the **real,
unmodified** constants and asserts it does not raise. State in its docstring why it opens the module:
without it, every leg below could pass by always failing regardless of input.

**F. Hand-off note to Phase 137.** A module-level comment stating that CLOSE-03's `tools/check_*.py`
string-literal scanner should **extend** `SDP_RECOVERY_CONSTANT_NAMES` rather than duplicate this
pytest, and that this module deliberately scans **named constants only** — a whole-report grep is RED on
