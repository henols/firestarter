<objective>
Add a fourth deny bucket to the existing orchestrator gate — broad exception handlers — with the one
exemption the real source legitimately needs, guarded so the exemption cannot become the fail-open hole
it would otherwise be.

Purpose: criterion 2 requires proof that a bare `except Exception`/`BaseException` was **not** used, and
the behavioural half of that proof (plans 133-02 and 133-04) only covers the sites those plans touched. A
broad handler added later, anywhere in this module, would go uncaught until something breaks. Measured:
ruff catches bare `except:` via E722 but catches `except Exception:` and `except BaseException:` with
**nothing** — this repo's `select` is `["E","F","I","UP"]`, so `BLE` is off and the
`# noqa: BLE001` comment already sitting on `chip_test.py`'s sampler handler is **inert**. That is the
precise gap this bucket closes.

The trap this plan exists to disarm: `chip_test.py`'s `_sample` **already contains** a broad handler.
The deny-rule as specified in D-09 therefore fires RED on clean, legitimate, pre-existing source the
moment it lands — and the existing `test_checker_exits_zero_on_clean_source` leg goes RED with it. D-14
settles the mechanism (an exemption table keyed on `(file, function)` with a mandatory reason and a
stale-row guard) and requires it to land **in the same task** as the rule, so the gate is never committed
RED even for one commit.

Output: `visit_FunctionDef` + `visit_ExceptHandler` + `_BROAD_EXCEPT_NAMES` +
`broad_except_violations` + `_BROAD_EXCEPT_EXEMPTIONS` + `_validate_exemption_table`, wired into
`main()`; and ~6 subprocess legs proving each form RED, the exemption GREEN, and both guards RED.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| source text -> build gate | The gate reads source it does not control. Its own docstring commits to never being "a hollow declared-empty detector", which is why the rule is an `ast` walk and not a regex — `chip_test.py` has more docstring/comment mentions of the word than it has real handlers. |
| env seam -> gate target | `FIRESTARTER_DEVTEST_SRC`/`_HANDLER`/`_SUBMIT` let a test point the checker at a planted fixture. | exemption table -> gate verdict | An exemption is a hole by construction. Its reason, its `(file, function)` scoping, and its stale-row inversion are the three controls that stop the hole from widening. |
| gate -> firmware sibling | `_assert_host_only` mechanically refuses a scan target resolving into the firmware repo. Preserved unchanged. |
