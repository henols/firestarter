## Corrections that amend locked decisions

The phase's six corrections are tabled in full in `131-01-PLAN.md`. Two govern **this** plan:

**F-05 — amends D-02 layer 3 (the end-to-end leg).** D-02 layer 3 says to assert exit in {0,1,2}
*and* that stdout carries the `mypy errors: N (watermark: M)` line. After 131-01's hardening that is
**unsatisfiable in this devcontainer**: an ambient numpy PEP-695 stub truncates the run, mypy exits
2, and the hardened gate exits 2 from `classify_mypy_result` **before** any count is printed — and
printing a count there would be exactly the lie this phase removes. The leg is therefore rewritten
as a two-shape mutually-exclusive assertion (task 1, leg 6), which is strictly stronger than the
original because it also forbids the fail-open shape. Record the substitution and its reason in the
SUMMARY; do not quietly relax the leg to an exit-code-only check — exit-code-only criteria lie.

**F-06 — planner-added, in scope.** `tools/check_no_exists_proxy.py`'s `_DEFAULT_TARGETS` is an
explicit non-glob list of 78 test files (measured). A new test module not added to it escapes that
gate silently — P-07's fail-open-against-additions class. Task 1 adds
`tests/test_check_mypy_watermark.py` to that list, in alphabetical position, **in the same commit
that creates the module** (the same discipline RETIRE-02 imposes in Phase 132), because the checker
hard-fails on a listed-but-missing target.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| test suite → gate correctness claim | A green suite is the only evidence anyone will look at that the gate can fail; a hollow leg converts absence of evidence into apparent evidence. |
| test process → checker module | The test imports and monkeypatches a production module; a patch that leaks outside the module namespace would alter behaviour for the rest of the session. |
| `_DEFAULT_TARGETS` list → proxy-gate coverage | A new test module absent from the explicit list is silently unscanned. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-131-08 | Spoofing | a pre-authored but unreachable gate leg | critical | mitigate | Task 2's D-03 RED-preserving proof: the truncated-run leg is seen to fail, and the failure *reason* is read and recorded verbatim, before the fix is re-applied. |
| T-131-09 | Tampering | `monkeypatch` of `subprocess.run` | medium | mitigate | Patch is scoped to the checker's module namespace via `monkeypatch.setattr`, never globally; pytest's monkeypatch fixture unwinds it per test. |
| T-131-10 | Repudiation | exit-code-only assertions | high | mitigate | Every fail-closed leg asserts the *message* alongside the code, naming the specific cause. Exit-code-only criteria are a recorded false-green trap in this project. |
| T-131-11 | Elevation of Privilege | a test seam becoming a production bypass | high | mitigate | No env var and no `PATH` stub. The classifier is pure and called directly; the argv probe patches a stdlib name inside the module under test and adds no production seam. |
| T-131-12 | Information Disclosure | canned mypy output in a committed test | low | accept | The constants are synthetic diagnostic text plus one real site-packages path already visible in CI logs. No secret. |
