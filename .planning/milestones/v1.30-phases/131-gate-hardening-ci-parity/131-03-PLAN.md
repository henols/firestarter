Close P-10's hole: the missing gate is against **narrowing** the SDP allow-set for convenience, not
against widening it.

Purpose: when the `dev test` SDP leg reports BAD in the field on, say, an AT28C256, the cheapest way

names any chip that moved, the literal 43/41/84 triple asserted separately, and a non-vacuity proof.

## Corrections that amend locked decisions — both govern this plan

The phase's six corrections are tabled in full in `131-01-PLAN.md`. **F-01 and F-02 change what this
plan builds**, and both must be recorded in the SUMMARY as explicit corrections with their reasons —
never silently applied.

**F-01 — amends D-06 leg 1.** D-06 leg 1 says: *"Recompute the partition from `chip_database.json` +
the committed `flags` bit-15 decode and assert it equals what `sdp_capability()` computes."* That is
**not implementable in this repo**, measured 2026-08-03:

- `firestarter/data/chip_database.json` contains **zero** occurrences of the string `"flags"`. Its
  per-chip keys are `datasheet`, `electrical`, `part_number`, `pinout`, `programming`, `provenance`,
  `source`, `support_status`, `unsupported_reason`, `verification_note`, `verification_status`; the
  `programming` sub-keys are `algorithm`, `chip_id_check`, `chip_id_value`, `page_size`,
  `pulse_duration`. There is no per-chip protection metadata in the shipped DB. (There is an open
  todo, `decode-infoic-flags-bits-14-15-protect-metadata`, to put it there — it has not landed.)
- `tools/infoic.xml`, the bit-15 source, is **gitignored** (`.gitignore:29`, pattern
  `tools/infoic*.xml`) and **absent from the working tree**.

So the independent-derivation side does not exist. Implementing leg 1 literally would recompute the
partition using the very function under test — **self-parity**, which passes whenever both sides
drift together, and which is precisely the hole D-06 exists to close. A test that passes on drift is
worse than no test, because it reads as coverage.

**The triple itself is real and unchanged**: measured live 2026-08-03, ALLOW **43** / REFUSE **41** /
total **84**.

**Replacement, which preserves exactly what D-06 was built to protect:** the independent side becomes
a **committed, sorted, 43-entry ALLOW list** checked into the test module. The measured side comes
from `sdp_capability_for_entry()`. A chip moving ALLOW→REFUSE reddens the element-wise leg, and the
only diff that greens it is a **visible edit to a named committed constant** — which the change
protocol then governs. D-06 legs 2 and 3 survive unchanged.

**F-02 — amends D-06's placement.** D-06 says to extend **both** `tests/test_sdp_db_invariant.py`
and `tests/test_sdp_table_parity.py`. Measured: `test_sdp_table_parity.py` imports `fw_path` and
`requires_fw` from `tests.fw_presence` at `:55` and resolves firmware paths at module scope
(`:62-63`), so the whole module is `requires_fw`-skipped under CI-parity recipe leg 1
(`FIRESTARTER_FW_ROOT` pointed at an empty directory) and in standalone CI. Any 43/41/84 leg placed
there is **invisible exactly where it matters most**. `test_sdp_db_invariant.py`'s own docstring
(`:23-28`) states it deliberately carries no FW skip marker for this reason. **All DB-only legs go
in `test_sdp_db_invariant.py`; `test_sdp_table_parity.py` is not touched.** This also mechanically
discharges D-18's negative criterion. D-06's "do not create a third module" instruction still holds.

| test constant → reviewer | The committed ALLOW list is the only human-visible record of the partition; if it can change without a visible diff, the gate is decorative. |
