<objective>
Prove the whole override mechanism end to end on one row: a datasheet number written into a JSON
file beside the generator reaches the generated database, through the generator's own derivations,
and answers gh#70's measured defect.

This is the phase's `type="tracer"` slice. It touches every layer the phase will modify — the
override data file, the loader, the applier, the pre-derivation insertion point, the hoisted decoded
values, the generalised ceiling check, the `chip_entry` literal, the generated database, and a test
module in `tests/` that puts `tools/` behaviour under CI — and it wires exactly ONE path through all
of them: `FUJITSU/MBM27C1000`'s program pulse, 100 µs to 500 µs.

It is production-quality, not a prototype. The three per-field fail-closed legs (stale recorded prior,
unknown field path, no-op) land here because they are inherent to the substitution loop. The two
whole-file legs (an override key that matches no row, two keys resolving to the same row and field),
the sort-order gate, the datasheet-path-exists gate and their tests are additive and land in plan
`197-03` without changing this architecture.

**Known-red window.** After this plan exactly two tests in `tests/test_wire_dict_equivalence.py` go
red, because one wire value moves and no 197 delta layer exists yet. That is expected, measured and
closed by plan `197-06`. The verify legs below assert that the failure set is exactly those two and
nothing else.

Purpose: make a datasheet value able to correct an infoic decode, and prove it on the pulse width
gh#70 measured.
Output: `tools/datasheet_overrides.json` with one entry, a loader and applier in `tools/build_db.py`,
a hoisted and generalised decode path, and a regenerated database whose only changed row is the one
the override names.
</objective>
