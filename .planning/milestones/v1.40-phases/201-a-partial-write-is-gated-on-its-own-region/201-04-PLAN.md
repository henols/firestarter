<objective>
Bound the data-transfer loop the same way the blank check is now bounded, and keep `0xE0` to one
meaning while doing it.

Plan 201-03 proved the region reaches the blank check. This plan is the expansion: the same
resolved end now bounds `_process_incoming_data`'s done-condition and its out-of-range refusal —
which, because that function is shared by `eprom_write` and `eprom_verify`, bounds verify too and
makes write and verify agree on where the operation ends — and it replaces the per-byte write
loop's progress denominator.

The one gate CONTEXT.md never named lives here. `test_progress_emission_is_leonardo_only.py:607`
asserts the emit's second argument is the string `handle->mem_size`, verbatim, and carries a
design argument in its own failure message about `0xE0` keeping exactly one payload meaning. That
argument is not wrong, it is now expressed differently, and this plan restates it rather than
swapping the string in silence. Its capture group also cannot match parentheses, so the resolved
end must arrive at the emit as a bare identifier — which is why plan 201-03 put the resolution in
`memory.cpp` and why nothing inline is permitted here.

Purpose: complete D-06 and D-07 without moving either of the two denominators BLANK-02 protects.
Output: an `op_end` local at two call sites, a retargeted and re-argued progress gate, and a
second golden re-derivation in the same commit as its source change.
</objective>
