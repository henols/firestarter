<objective>
Make the defect expressible, and freeze the behaviour that must not move.

Two things block every later plan in this phase. First, the native suite **cannot say
"non-blank at address A"** — its readback model recovers the byte index as `address & 15`
across 16 slots, so seeding one address aliases across the whole address space and lands
inside any region a test tries to protect. A D-16.1 regression test written against that model
would go RED for the wrong reason and stay RED after the fix. Second, BLANK-02 freezes the
whole-device behaviour of the other two callers, and a characterization test written **after**
the split characterizes the split, not the contract.

This plan therefore writes no production code at all. It extends the harness so an absolute
address can be seeded, proves the extension actually works with a positive control, and then
pins the multi-call chunking contract and the erase-end arm against **unmodified** firmware,
both GREEN.

This plan contains no expansion task and no tracer. It is harness groundwork plus two
characterization tests whose value depends entirely on landing before anything changes; the
phase's leading `type="tracer"` vertical slice is plan `201-03` Task 1.

Purpose: give plan 201-02 a harness that can express the defect, and give plans 201-03 and
201-04 a tripwire that fires the moment the split disturbs the two callers BLANK-02 protects.
Output: an address-keyed readback model in `host_stubs.cpp` and three new cases in
`test_val_eprom.cpp`, all green on both native envs.
</objective>
