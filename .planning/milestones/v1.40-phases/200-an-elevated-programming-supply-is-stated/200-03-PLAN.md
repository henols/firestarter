<objective>
Bound the population, and prove the boundary can fail.

The phase's other two plans deliver and pin what one operator sees for two parts. This one answers
the question those cannot: how many parts does this apply to, is that number the one the phase was
designed around, and would anyone notice if it changed. The answer is 284 of 746 — measured twice,
once during the discussion and once during research, both times to the unit — and it is asserted here
as an equality against the SHIPPED predicate rather than against a copy of it, so the test breaks if
the rule and the claim ever drift apart.

Three properties beyond the count earn their place. All 284 are `UV-EPROM` with zero exceptions, so
a decode change that swept a 5 V EEPROM into the warned set would be caught by something. Phase 198's
deliberately-untouched 28-row VOLT-03 group is fully disjoint from the 284, so the guarantee D-03
intended is structural and not merely hoped for. And exactly 3 of the 284 carry a datasheet-cited
`vdd_mv` while 281 carry a decoded rail slot — the measurement that made the operator amend D-04's
verb on 2026-09-19. Pinning that 3-versus-281 split means a future override giving a fourth row
datasheet backing turns the wording question red instead of leaving it to be rediscovered.

D-06's fail-open branch has no live data to exercise it: all 746 rows carry a non-zero integer
`vdd_mv` because the generator decodes through a `.get(..., 5000)` default. It is tested with
synthetic in-memory records, never by hand-editing a generated file, and the module says in its own
docstring that the branch is reachable in production through the `~/.firestarter/database.json`
override seam so a reviewer does not delete it as dead code.

Purpose: make VCC-01's scope a measured, falsifiable claim rather than a number in a planning
document.
Output: one new test module, eleven legs, every count proved capable of failing.
</objective>
