<objective>
Move the VPE-as-VPP routing decision into the firmware, where the hardware is, and make its
independence from the voltage monitor something a test can falsify.

`dim20` proposed the mechanism in gh#71: the standard VPP rail cannot reach these parts, the VPE
rail can, so route VPE as VPP. Phase 199 first built that as a host rule. The operator reversed it
on 2026-09-19: it is not the app's responsibility to control the VPE flag, and if VPE routing is
needed it is much safer for the firmware to control when it is used (**D-21**). The host and the
firmware ship independently — separate repos, separate channels, PyPI against GitHub releases — so a
host pinned at an old version, or carrying a ceiling measured on a different shield, would silently
mis-route a high-voltage rail onto socket pin 1. A decision that must match the hardware belongs
with the hardware.

The firmware already owns routing. `eprom_hv_route_mask` already reads the protocol-keyed
`eprom_params` table's `vpp_path` column and already returns the undropped rail for a
`VPP_PATH_DIRECT_VPE` row. This plan extends a decision that function already makes, by one
comparison, against one new shield-property constant.

The one thing that must be got right is **D-22**. The naive firmware implementation triggers on the
ADC, and the bench pair proves it would silently fail for nine of the ten rows this phase exists to
rescue: the monitor reads about 7.6% high, so for a part needing 18000 mV the existing
`adc < required * 95/100` comparison stays false while the socket is genuinely 620 mV short. Routing
therefore triggers on **path capability** — whether the drop path can reach the part's requirement at
any pot setting — and the ADC comparison is left exactly as it is to keep verifying whatever was
routed (**D-23**). That also keeps backlog 999.38's calibration decoupled: it lands later and
improves only the verification leg, never a precondition for routing to be correct.

Purpose: satisfy RAIL-04 on the side of the system that owns the hardware, and leave RAIL-03's
existing report pointed at the rail the part actually receives.
Output: one constant, one comparison, one native suite that proves the decision reads no voltage,
and one notes artifact carrying the provenance and the three stale documentation sites that the
no-comments rule forbids fixing in place.
</objective>
