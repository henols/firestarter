<objective>
Take gh#71's voltage from a vendored datasheet all the way to the operator's screen.

`FUJITSU/MBM27128` is the part gh#71 reported. Its own datasheet, already git-tracked and already
cited in this part's existing override entry, specifies VPP 21.0 V plus or minus 0.5 V. The database
asks for 18.0 V, because upstream's VPP low byte `0xF0` is a cap rather than a requirement. This plan
moves that one number and every layer it passes through: the override file, the decoded input, the
generated database, the wire dictionary the firmware receives, the rendered `21.0v` an operator
reads, and the golden fixtures that pin all four. Then it records the regeneration as evidence.

This is the phase's tracer. It is the only slice that traverses the whole data path in one pass, and
it is deliberately scheduled first, in parallel with the bench session, so the regeneration, delta
layer and snapshot work is de-risked away from bench time.

**Edge-probe accounting for this plan: 0 of the phase's 8 probe-surfaced items.** All eight are
carried by plans `199-02` (2), `199-03` (3), `199-04` (1) and `199-05` (2).

**Known-red window, by design.** Task 1 reddens `tests/test_wire_dict_equivalence.py` and Task 2
closes it by name. This mirrors 197-02 to 197-06 and 198-01 Task 1 to Task 2 exactly. Do not attempt
to keep that module green across Task 1 — attempting it would mean re-baselining the golden, which
is the one outcome the delta-layer discipline exists to prevent.

Purpose: satisfy the database half of RAIL-02 on the row the community reported, and prove the whole
host data path end to end on one real correction before anything else in the phase moves.
Output: one corrected Fujitsu row, a one-record wire delta layer that has been seen to fail, a
one-line snapshot re-record, and a committed regeneration record.
