<objective>
Quantify the Phase 6 flash impact and confirm the firmware still builds on both boards. The Leonardo is the constrained board (98.7% at v1.1 close per ROADMAP) — Phase 6 ADDS code (CRC8 table = 256 bytes, frame emitter helper, messages.c PROGMEM table = 256 bytes, messages.h ID constants, the convenience-macro tower) WITHOUT removing any old code (LMIG-01 coexistence). RESEARCH estimates the additive code at 600-900 bytes; Leonardo's pre-Phase-6 headroom is ~520 bytes.

If the additive code tips Leonardo over 100%, the plan must NOT delete the old text path (that's Phase 9's job). Instead, the measurement run uses a conditional-include macro `-D NO_TEXT_LOGS` to TEMPORARILY exclude the old path, capture the would-be flash number, then revert. This proves the Phase 9 endpoint is reachable.

Purpose: This is a verification/measurement plan (no production code change). The output is documentation that anchors Plan 09's flash-savings claim.

Output: `.planning/phases/06-logging-infrastructure/06-FLASH-MEASUREMENT.md` with raw `pio run -e leonardo` + `pio run -e uno` outputs, delta vs v1.1 baseline, and (if needed) the fall-back measurement under `-D NO_TEXT_LOGS`.
</objective>
