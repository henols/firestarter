## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pyserial stream → host application | Anyone (or any noise source) can inject bytes. The decoder is the gate that decides whether bytes become a `Response` consumed by upstream business logic. |
| catalog file → decoder lookup | `messages.py` is generated; a tampered catalog could re-route severity (e.g. force an ERROR to render as OK). |
| Unknown / future IDs from a forward-compat firmware | The host may receive an ID it doesn't know about. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-10 | Spoofing | Random bytes from the wire happen to match the 4-byte magic preamble + plausible length | mitigate | CRC8 over `[id, params]` rejects ~99.6% of spurious random data (1 in 256 false-accept rate). For PORTD ghost bytes — which are correlated bus toggles, NOT random — the alternating-bit magic (D-02 rationale) makes the false-positive rate effectively zero. `test_crc_mismatch_rejected` pins this behaviour. |
| T-06-11 | Information Disclosure | Decoder logs param values at WARN level on shape mismatch — could leak addresses / programming state | accept | The same risk exists in the current text-format path (`logger.warning` of any line). No new exposure; logging stays at WARN. |
| T-06-12 | Denial of Service | Endless stream of malformed frames (e.g. magic followed by `len=255` but only 4 bytes follow) | mitigate | `self.connection.read(frame_len)` honours the serial timeout. If `len(body) != frame_len` the decoder logs a warning and `continue`s to the next byte (does NOT re-throw or exit the read loop). The outer `_read_and_parse_lines` timeout terminates the read after a configurable window. |
| T-06-13 | Tampering | Generated `messages.py` hand-edited to remap severity | mitigate | Plan 05 adds the CI drift gate — `python3 tools/catalog/codegen.py && git diff --exit-code firestarter/messages.py` fails CI on any post-codegen edit. |
| T-06-14 | Forward-compat | Firmware sends an ID not in the host's catalog | accept | `_decode_id_frame` logs `logger.warning("Unknown message ID 0x{id:02x} — catalog out of date?")` and returns None; the read loop skips it. Locking the lockstep upgrade (Plan 04) is the operational defense — the fw-version refuse guard prevents older host vs newer firmware mismatches at probe time. |
