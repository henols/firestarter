<objective>
Land the CI drift gates that protect the generated artifacts from silent corruption. Three workflows in three repos:

1. `firestarter/.github/workflows/build.yml` — MODIFY: add codegen + diff + catalog-validity steps before `pio run`. Drop `'tools/**'` from paths-ignore so catalog edits trigger CI.
2. `firestarter_app/.github/workflows/ci.yml` — NEW: host sub-repo's first real test workflow (codegen drift + catalog validity + pytest). Triggers on push:main and pull_request:main.
3. `.github/workflows/catalog-sync-check.yml` — NEW (meta-repo): cross-sub-repo byte-identical assertion on the vendored `tools/catalog/messages.toml` copies (the load-bearing assertion that catches sync-script drift per RESEARCH §"Authority Assertion").

Purpose: This is the lockstep enforcement layer. Without these gates, a developer could (a) edit `messages.h` by hand to add a new entry without updating the catalog, (b) sync the catalog into only one sub-repo, or (c) regenerate locally but forget to commit. All three failure modes become CI failures visible in the PR.

Output: Three workflow files committed in their respective repos. The drift gate is empirically demonstrated by deliberately mutating a generated file and confirming CI would fail (manual one-shot pre-merge verification).
</objective>
