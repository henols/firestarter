Counted form (POSIX-portable — preferred for clarity and shell-portability):
```
count=$(grep -rnE "log_info_const|log_info_format|log_warn[^_]|log_error_const|log_error_format|log_error_P|log_info_P|firestarter_(error|warning)_response_format|firestarter_(error|warning)_response" firestarter/src/ firestarter/include/ firestarter/lib/ 2>/dev/null | grep -v "//" | grep -v "^[^:]*:[[:space:]]*\*" | grep -v "^[^:]*:[[:space:]]*#define" | wc -l)

```

Must exit 0 (zero matches). The `grep -v "//"` filter strips comment-only lines; the `#define` filter strips macro definitions in `logging.h` which Phase 9 deletes (Phase 7 leaves those intact for OK/DATA path); the `^[^:]*:[[:space:]]*\*` filter strips lines starting with `*` (block-comment continuation lines like `* see legacy log_*_const`).

NOTE on shell portability: this counted form works under both `bash` and POSIX `sh`. A bare `! pipeline` negation prefix (e.g. `! grep ... | grep ... | grep -q .`) is bash-only and silently misbehaves under POSIX `sh` — DO NOT use that form here.

NOTE on filtering: The `log_info(...)` and `log_data(...)` calls inside `_check_response`'s OK + DATA branches use a different function signature (take a `handle->response_msg` argument, not a const string) — they are NOT `log_info_const` / `log_info_format`, so the SC#1 grep regex correctly excludes them.
