<objective>
Wave 7 — single-sweep conversion of every firmware `debug()` and `debug_format()` call-site to the `MSG_DEBUG + sub_id` ID-frame channel (B-01..B-04). The conversion preserves the existing `#ifdef SERIAL_DEBUG` production-stripping behavior — release builds (no SERIAL_DEBUG flag) emit ZERO debug-related bytes on the wire and pay ZERO Flash for debug-only code. Development builds with `-D SERIAL_DEBUG` emit MSG_DEBUG frames carrying a 1-byte sub_id (allocated from the [debug] section in messages.toml from Plan 01) plus that sub_id's declared params.

Why this is a separate wave (not folded into Plan 04 / 05): the debug sweep touches ~46 call-sites across most firmware source files (firestarter.cpp, hardware_operations.cpp, eprom_operations.cpp, operation_utils.cpp, dev_tools.cpp, every proms/*.cpp). Many of those files were already modified by Plans 04 and 05 for their state-machine-ack conversions; folding the debug sweep into the same commits would have made each commit larger and harder to review. Doing the sweep last lets each touched file's diff be small and reviewable per plan.

This plan depends on:
- Plan 01 (catalog declares MSG_DEBUG 0xF0 + the [debug] section enumerating every DBG_*).
- Plan 06 (response_msg field deleted before this sweep so the sweep doesn't accidentally generate a debug() that references the dead field).

Purpose: complete the "no string is built at runtime by production firmware" objective from CONTEXT — after this plan, every wire byte from production firmware is either an ID frame or the LFW-05 bootstrap text response (MSG_OK_FW_VERSION 0x03). All other state-machine/log/debug emit paths are catalog-driven.
Output: 1 logging_id.h commit (debug macro family) + ~12 per-file conversion commits (one per source file with debug() calls — files with zero debug() calls obviously have no commit).
</objective>

<interfaces>
LOG_DEBUG_ID_SUB family (this plan's Task 1 adds to logging_id.h):
- LOG_DEBUG_ID_SUB(sub_id) — zero-param debug emit. Wire: MAGIC | len_u16 | MSG_DEBUG | <sub_id_u8> | crc | 0x0A.
- LOG_DEBUG_ID_SUB_U8(sub_id, p1) — one-u8-param.
- LOG_DEBUG_ID_SUB_U16(sub_id, p1) — one-u16-param.
- LOG_DEBUG_ID_SUB_U24(sub_id, p1) — one-u24-param (top 8 bits of u32 dropped).
- LOG_DEBUG_ID_SUB_U32(sub_id, p1) — one-u32-param.
- LOG_DEBUG_ID_SUB_BYTES(sub_id, b, n) — caller-supplied bytes.
- LOG_DEBUG_ID_SUB_ASTR(sub_id, s) — ascii_str (for debug() calls with "%s" — packs the length-prefix + N bytes the same way LOG_OK_ID_U8_U8_ASTR does).

All families wrapped in `#ifdef SERIAL_DEBUG ... #else (empty) #endif`. The reference pattern is the existing FLAG_VERBOSE-gated LOG_INFO_ID_* family but with `#ifdef SERIAL_DEBUG` instead of `is_flag_set(FLAG_VERBOSE)`.

debug() / debug_format() existing call-site shape:
- `debug("literal string")` → `LOG_DEBUG_ID_SUB(DBG_NAME)` (where DBG_NAME is the sub_id allocated for that literal in Plan 01's [debug] section).
- `debug_format("Address: 0x%06lx", addr)` → `LOG_DEBUG_ID_SUB_U24(DBG_ADDRESS, addr)`.
- `debug_format("Token count: %u", count)` → `LOG_DEBUG_ID_SUB_U16(DBG_TOKEN_COUNT, count)` or U8 depending on the catalog declaration.
- `debug_format("name: %s", str)` → `LOG_DEBUG_ID_SUB_ASTR(DBG_NAME, str)`.

The DBG_* mapping table from Plan 01's audit (`/tmp/ph8-debug-audit.txt`) is the canonical lookup. Executor MUST reference that file for the literal→DBG_* mapping; do not invent new DBG_* names.

- Default `pio run -e uno` builds WITHOUT `-D SERIAL_DEBUG`. The LOG_DEBUG_ID_SUB* macros expand to nothing. Flash usage MUST be measurably smaller than the Plan 06 close baseline — every legacy debug() PROGMEM string literal is replaced by an empty macro, so the per-file debug string overhead disappears from the binary.
- Development build `pio run -e uno -D SERIAL_DEBUG` builds the debug emit path. Flash MAY be larger than production but should still fit (Phase 7 close left ~6 KB free on Uno; debug emits cost ~3-5 bytes per call-site).
