<interfaces>
Catalog entry shape (existing — Phase 7 Plan 02 established this template):
- Each `[[messages]]` entry has fields: id (u8), name (MSG_*), severity (OK|INIT|MAIN|END|INFO|WARN|ERROR|DATA), format (Python-style format string), params (TOML inline array of `{type = "u8|u16|u24|u32|i8|i16|i32|ascii_str|bytes"}`), wire_format ("text"|"id_frame").
- Severity bands (W-02 authoritative): OK 0x00-0x0F · INIT 0x10-0x1F · MAIN 0x20-0x2F · END 0x30-0x3F · INFO 0x40-0x7F · WARN 0x80-0x9F · ERROR 0xA0-0xDF · DATA 0xE0-0xFF.

codegen.py existing emit surface:
- emit_cpp_header → loops over sorted-by-id `messages` array, emits `#define MSG_* 0xXX` block.
- emit_python → emits `CATALOG: dict[int, MessageDef] = {...}` with one entry per message.
- validate_catalog → enforces unique id, unique name matching `^MSG_[A-Z][A-Z0-9_]*$`, well-formed params, non-empty format.
- VALID_SEVERITIES tuple includes "DATA".

Extension required for [debug] section:
- New top-level TOML table `[debug]` with `[[debug.messages]]` array entries (same shape as `[[messages]]` but without `severity` or `wire_format` — both are implicit: severity from MSG_DEBUG main entry, wire_format always id_frame).
- DBG_* name pattern: `^DBG_[A-Z][A-Z0-9_]*$`.
- Validation rules mirror the main-catalog rules but the id-uniqueness namespace is the [debug] table only.
- emit_cpp_header gains a `// --- Debug sub-IDs (sorted ascending) ---` block emitting `#define DBG_* 0xXX` after the main MSG_* block.
- emit_python gains a `DEBUG_CATALOG: dict[int, MessageDef] = {...}` block emitting one entry per [debug] message after the main CATALOG block.
</interfaces>
