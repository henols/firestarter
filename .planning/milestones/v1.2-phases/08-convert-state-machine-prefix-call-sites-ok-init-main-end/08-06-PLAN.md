<objective>
Wave 6 — eliminate the `response_msg[96]` scratch buffer and its associated `copy_to_buffer` helper macro, AND surgically strip the two log emits inside `_check_response`. Plans 04 + 05 converted every populate-site that used to write to `handle->response_msg`; now the buffer field has no callers, no dependencies, and can be deleted outright. The R-01 SRAM win is ~96 bytes per operation invocation (Uno: 4.7% of 2 KB; Leonardo: 3.8% of 2.5 KB).

The R-03 _check_response surgical strip removes the legacy `log_info(handle->response_msg)` at line ~312 and `log_data(handle->response_msg)` at line ~317. The switch's other behavior is preserved: rurp_communication_write in the DATA branch (raw chip-byte stream for backward-compatible data-buffer flow — though after Plan 05, the actual chip-byte stream is wrapped in MSG_DATA_CHUNK at the eprom_operations.cpp call-site, not in _check_response), return false in the ERROR branch, op_reset_timeout + RESPONSE_CODE_OK reset at the bottom.

This plan does NOT delete the surrounding legacy `logging.h` macros (`log_info_const`, `log_data_format`, `send_ack_const`, `send_ack_format`, `send_main_done`, `send_init_done`, `send_end_done`, `firestarter_response_format`, etc.). Phase 9 (LFW-03/04) owns that deletion. This plan deletes ONLY `copy_to_buffer` because it's the single helper whose every caller was eliminated within Phase 8 itself.

Purpose: collapse the response_msg indirection — the entire round-trip of "populate-site writes to scratch buffer → _check_response reads from scratch buffer → log_*(buffer)" disappears. After this plan, the firmware emits go directly from populate-site to wire, with `_check_response` driving operation flow without any log-emit side effects.
Output: 4 files modified, the SRAM win is measurable, both AVR builds + native suite + host pytest all green.
</objective>
