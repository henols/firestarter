## A3/B2 delta 1 — no chip-out gates, and the Leonardo's own flash path

Standing bench rule 2 exempts the Leonardo: it is flashed **and read back with the chip seated**.
So this cell has **no `P-03` gate on either arm and no chip-out gate before the `P-11` teardown
probe**. Inserting one would be an artificial park prompt and would contradict the rule. The
operator handovers here are `P-01`, `P-05` + `P-06`, `P-08`, then `P-05` and `P-08` again on the
second arm, and one final `P-11` swap that D-11 requires — and nothing else.

The flash path: PlatformIO's `leonardo.json` owns the 1200-baud touch on the **upload** side, so
`pio run -t upload -e leonardo` needs no manual touch. `touch_1200.py` exists only for the
**direct-avrdude read-back** side, in **bare settle-only** mode — never `--wait-new-port`, which
polls for a node this board never produces and burned ~5.27 s of the ~8 s Caterina window when it
was tried.

## A3/B2 delta 2 — `P-02` follows plan 161-02's established sequence, not A1's

`capture_provenance.py` shells to `probe_board.py` first and treats a non-zero return as a hard
failure, and `probe_board.py` performs no 1200-baud touch — a Leonardo running its application
firmware was measured to reject the avr109 handshake. Plan 161-02 established the working
sequence on this board and wrote it into
`bench/cells/BRINGUP-leonardo-provenance/PREPROOF.md` as an ordered, copy-runnable command list,
along with any tool seam it required. **Follow that list.** An A3/B2 `P-02` that is a copy of
A1's is the documented warning sign.

## A3/B2 delta 3 — the only valid v1.31 timing comparison in the milestone, and what it may not say

v1.31's **0.37 s** is the **spread (max minus min)** across three full 64 KiB write cycles'
**app-reported, success-only** figures — 106.06 / 105.69 / 106.06 s — measured on **Leonardo +
Rev 2.0**, firmware `ebe9cb3`. **It is a spread, not a duration**, and Phase 145 drew no
comparative claim from it.

Three things follow, all of which must appear in this cell's record:

1. v1.34's judged measure is **wall-clock**, a different quantity by a different method. The
   directly comparable v1.34 quantity is the **app-reported** figure, and even that comparison is
   valid **only on this cell**, the one rig shared with v1.31.
2. v1.34 takes **one** write per position, so there is **no v1.34 spread** to set against v1.31's.
   The honest statement is: two app-reported figures (control, v133) whose **difference** is the
   A/B signal, presented beside v1.31's three-cycle spread with the method difference named —
   never a single figure "compared to 0.37 s".
3. Both arms' app-reported W27C512 figures will land far below 106 s. That is **PR #55's
   per-byte VPE-settle amortisation** (105.9 s to 33.35 s, merged as fw `3.0.0b22`), which is in
   the **control** arm's merge base as well as v1.33's — `rig-pins.json` records the same PR as
   the reason the control hex is the *larger* of the two. **Both arms carry the fix.** Stating the
   figures next to 0.37 s without this sentence would read as a spectacular v1.33 improvement that
   is nothing of the kind. Say it explicitly.
