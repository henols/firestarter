## Shared conventions for every task in this plan

- **Paths are per-position** (Amendment 3 clause 3):
  image `$CELL_DIR/reads/$POSITION_ID/written.bin`, read set
  `$CELL_DIR/reads/$POSITION_ID/run_NN.bin`, verdict
  `$CELL_DIR/WRV-VERDICT_$POSITION_ID.json`, provenance
  `$CELL_DIR/provenance_$POSITION_ID.json`. Everything under `reads/` is gitignored by
  `cells/*/reads/`; the two JSON records are committed. Never a shared `$CELL_DIR/reads` and
  never a shared `written.bin` — `judge_wrv.py` globs `run_*.bin` and would judge the previous
  position's files.
- **Logs** are `$CELL_DIR/logs/NN_<verb>.stdout.log` and `.stderr.log`, zero-padded from `00`,
  sequential across the whole cell, one pair per invocation, the suffix naming the verb.
- **Recorded argv is absolute.** `gate_record.py` only recognises a rig-tool invocation whose
  argv[0] is an absolute interpreter and whose argv[1] is an absolute script path containing
  `/.planning/v1.34/tools/`. The procedure's literal blocks show relative paths for readability;
  what gets recorded must be absolute.
- **`FIRESTARTER_CONFIG_DIR` is inline**, never exported: `config.py` computes `HOME_PATH`,
  `DATABASE_FILE` and `PIN_MAP_FILE` at import time, so a session export is a partial fix that
  looks complete. A shell `FOO=bar cmd` prefix never reaches argv, so no argv check can detect a
  missing prefix — the `P-11` `~/.firestarter` baseline assertion is the only detector.
- **`pio` runs only with cwd `/workspaces/firestarter`.** The gitignored
  `/workspaces/platformio.ini` has a duplicate `[platformio]` section that aborts `configparser`;
  the identical command succeeds or fails on cwd alone.
- **Stall ceilings (D-08).** W27C512: **165 s** (4x the measured healthy 41.010 s wall-clock from
  `bench/cells/BRINGUP-wrv/WRITE.md`). W29C020: **600 s absolute** for position 2 only, recorded
  explicitly as *a fallback, not a derivation*, because A1's own control figure is what the
  derivation needs and it does not exist yet; from position 4 onward the ceiling is **4x A1's
  control-arm W29C020 measured wall-clock**. Kill with
  `timeout --signal=INT <N>` writing stdout and stderr to the numbered log pair, record the
  wrapper's exit code (124 on timeout) next to the elapsed wall-clock, and record the outcome as
  `timed out at N s against a measured baseline of M s`. Never pipe the killed command's output
  through anything that would swallow it. Write-progress emission is time-keyed **per block with
  the clock restarting each block**, so there are zero intra-block frames — the last captured
  frame names the block, never a byte offset.
- **Write duration (BOARD-04).** The judged measure is **wall-clock around the write command** —
  the only measure that exists for every arm, target and outcome. Capture it with `date +%s.%N`
  immediately before and after (or around the `timeout` wrapper) and record to three decimals.
  The app's own success-only figure is a second, **unjudged** datum: extract it by grepping the
  write's stdout log for the success string, never by line number — the identical string sits at
  `eprom_operations.py:1934` on the v133 arm and `:2045` on control.
- **`judge_wrv.py` exits 1 on a non-match, after writing the artifact.** A non-clean position is
  a normal, expected outcome. Capture the exit code as a datum; never let it fail the step.
- **Append and render are one pair.** `render_evidence.py --append` returns before the render
  path, and `run_gates.sh`'s fourth live leg compares `EVIDENCE.md` byte-for-byte against a fresh
  render. Every `append_evidence.py` call is followed in the same step by
  `render_evidence.py --jsonl … --target …`.
- **The N=3 escalation rule, stated once.** The control arm takes a single read normally,
  escalating to the three-run form **only where the v1.33 arm's three reads for that position
  disagreed**. Because control runs first, that escalation is always retroactive. When it is
  needed: the v133 row's `anomalies` names the disagreement and points at the escalation
  artifact; the escalation itself runs at `P-11`, producing
  `$CELL_DIR/ESCALATION_<control_position_id>/` with its own three-run read set and a
  `WRV-VERDICT_<control_position_id>__escalated.json`, and a paragraph in `CELL.md` stating its
  cost. **No second `EVIDENCE.jsonl` row is ever written for an existing `position_id`** — rows
  are append-only and never rewritten. A disagreement is recorded, never retried away.
- **One clean re-seat per position** is permitted (standing bench rule 8) if a contact fault is
  suspected. Both the discarded attempt and the re-run are recorded; the discard is never silent.
- **`vpp`/`vpe` monitors do not route to the socket** — a blank or `0x303` reading is a contact
  fault, not a rail fault.
- **Nothing is fabricated.** A blocked reading is recorded as `not measured — <reason>` on the
  same line, never as a blank; `gate_record.py` treats that exact shape as a valid non-null. A
  wrong record is marked SUPERSEDED and kept visible, never erased.
