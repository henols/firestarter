## A2 delta 1 — Pitfall 4: `judged_match` is the only verdict on this target

`judge_readback.py` computes `judged_match` with an **exclusion-aware byte compare** but records
`sha_actual_judged` and `sha_expected_judged` as plain SHAs of the **raw** spans. On `uno328pb`
8 bytes are excluded, so a **correct** flash yields `judged_match: true` with two unequal SHAs —
visible today in the committed `BRINGUP-uno328pb/READBACK-VERDICT.json`. Any leg comparing those
two fields produces a false RED on **every** A2 flash, twice. Assert `judged_match == true`,
`judged_span_bytes == hex_span_expected_by_arm[flashed_arm]` read at assertion time, and
`vector_exclusions_applied` carrying both entries.

## A2 delta 2 — the expected symptom, and how it is recorded

The prediction, from the source rather than from a summary: *even with VPP correct, a write hangs
**deterministically on the FIRST program block** (6 attempts including reflash, reseat, and
random and zero payloads); the firmware stops responding the instant it drives program current
(VPP 12.7 V / VCC 5.3 V — suspected VPP-regulator brownout under load). The READ and blank-check
paths work.* Observed at Phase 54 UAT, 2026-06-04, on a **Rev 2.0** shield — the same shield this
cell uses.

Three consequences for how this cell is run:

1. **It is a hang, not a fast error.** The D-08 ceiling is the mechanism that ends it. Expect to
   hit 165 s on the W27C512 positions rather than to see a clean non-zero exit.
2. **The last progress frame will name a block, never a byte offset.** Write-progress emission is
   time-keyed per block and the clock restarts each block, so there are zero intra-block frames.
   Capture the last frame verbatim and record which block it names.
3. **The read path works on this board**, so a `read` after a failed write is still informative
   and `judge_wrv.py` can still produce a real verdict artifact.

**Producing a non-blank record for a failed position.** `judge_wrv.py --reads` requires the
directory to exist but happily counts zero files; with `--app-verdict 2` and `read_count == 0`
the judged verdict is `incomplete-read-set`. So: create the position's reads directory even when
nothing will land in it, run the judge, and capture the exit-1 as a datum. Every one of the four
positions then holds a real `WRV-VERDICT`, which is what SC#1's "no position is blank" and
`append_evidence.py`'s refusal contract both need.

**A completion is a finding.** If a write **succeeds** on either arm — and W29C020 has never been
tried on this board — record it as an observation **against** Backlog 999.2, in the position's
`verdict` prose, with the measured durations. Do not discard it as noise and do not soften it.

## A2 delta 3 — the D-07 safety carve-out

D-07 runs all four positions, with one carve-out from Claude's Discretion: **if A2's W27C512
failure turns out to physically damage or endanger the W29C020** — for example if the brownout
leaves a rail in a state that is unsafe for a 32-pin part — **stop and report.** Safety outranks
coverage. Nothing currently on the record suggests this, and the judgement belongs to the
operator at `P-08`.
