<objective>
Create the chip sweep's record shape and the tool that writes it: a sibling
`bench/CHIP-EVIDENCE.jsonl` with its own `_schema`, and `append_chip_evidence.py`, which derives
every machine field from the position's own artifacts and copies the `dev test` report out of the
frozen config dir before removing the source.

Purpose: ten parts plus up to six control re-runs, at ~70 fields each, is over a thousand
opportunities to transcribe a field from the wrong position. Phase 161's D-05 answered that with a
deriving writer, and the argument is **stronger** here because `dev test` already emits
machine-readable JSON — every machine field is derivable, so none is transcribed. The copy-out is
not a convenience: RESEARCH proved empirically that one `dev test` report inside
`FIRESTARTER_CONFIG_DIR` changes the pinned tree digest from `77adfdd2…` to `2fcae67d…`, which reds
`check_arms.py` inside the per-wave gate **and** makes every already-appended row's recorded
`config_dir_sha` mismatch at the next gate run. Copy out then remove restores the digest exactly.

Output: `bench/CHIP-EVIDENCE.jsonl` holding only its `_schema` line, and
`tools/append_chip_evidence.py` with a `--selftest` carrying seven positive and eleven negative
legs, each named after the defect it prevents. `run_gates.sh` at 13/13.
