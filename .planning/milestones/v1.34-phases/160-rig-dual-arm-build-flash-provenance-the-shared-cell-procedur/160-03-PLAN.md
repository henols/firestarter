**Change 2 — resolve the stamp width.** Phase 145's stamp encodes only the low 16 address
bits (`stamp(N) = (N & 0xFF)` for even N, `((N >> 8) & 0xFF)` for odd N), so on the
262144 B W29C020 the pattern repeats every 65536 bytes and an A16 or A17 aliasing fault
would be invisible to address attribution. That is the exact fault class that root-caused
Phase 97's pin-31 A18 aliasing defect, so it is resolved rather than inherited.

Add a `--stamp-width` flag with two values. `16` reproduces Phase 145's behaviour exactly
and is the default for a 65536 B image, where 16 bits covers the whole address space and
attribution is complete. `32` uses a 4-byte rotating word stamp: the byte at offset N
carries the address byte selected by `N & 3`, i.e. bits `[8*(N & 3) .. 8*(N & 3)+7]` of N,
XORed with the mask. That carries all 18 address bits of the 262144 B part, so an A16 fault
is visible at offsets where `N & 3 == 2` and an A17 fault likewise. `32` is required for a
262144 B image; the tool must refuse a 262144 B size with `--stamp-width 16` rather than
silently producing an unattributable image.

Extend the decode helper symmetrically so a differing byte at a known offset resolves back
to the address bits it encodes under either width, and preserve its role as the thing that
makes a mismatch attributable rather than merely counted.

Extend the printed verdict line to carry the width:
`<path>: <size> bytes, mask=0xNN, stamp_width=<16|32>, sha256=<hex>, 0xFF_count=<n>`. The
mask remains the recorded seed (8 bits, 256 distinct images, covering the 21 needed).

**Change 3 — add `--selftest`.** Positive legs: a 65536 B image at width 16 and a 262144 B
image at width 32 each decode back to their source address at a spread of probe offsets
including `0x00000`, `0x0FFFF`, `0x10000`, `0x20000` and `0x3FFFF`; and two images
generated with different masks have different SHA-256 values. Negative legs: a 262144 B
size with `--stamp-width 16` is refused; and a single-byte A17 alias injected into a
width-32 image (copying the byte from `N` to `N ^ 0x20000`) is both detected and attributed
to the aliased address line, whereas the same injection into a width-16 image is detected
but **not** attributable — that asymmetry is the measured justification for the change and
must be asserted, not asserted-away. `--selftest` returns 0 only if every positive and
every negative leg behaves as specified.
