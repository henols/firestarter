Read the avrdude binary, conf and the per-target parameters from `rig-pins.json`; refuse a
binary listed in `forbidden_binaries`.

The read. Invoke the pinned avrdude with `-A` explicitly on **every** target, `-C` with the
pinned conf, the target's `-p` / `-c` / `-b`, `-P <port>`, and a single
`-U flash:r:<out-dir>/flash_readback.bin:r`. The `-A` is not optional and not decorative:
avrdude truncates a flash read to strip trailing 0xFF, so without it the file is a variable
length that depends on where the last programmed byte sits and its SHA is not a stable
provenance datum. `-A` is engaged by default only for the `arduino` programmer, so passing it
explicitly is what normalizes all three chains to one 32768-byte artifact and one step text.
Assert the resulting file size is exactly the target's `flash_size` (32768) and fail with a
named `FAIL:` line if it is not. Capture raw stderr to a file and record its path.

The normalize. Resolve the reference `.hex` from `--expect-arm` and `--target` through
`rig-pins.json` `image_naming`, then run the pinned `avr-objcopy -I ihex -O binary` to
produce a binary of exactly the hex's contiguous address span. The objcopy binary is not on
PATH, which is why its path is pinned rather than assumed. Cross-check the resulting size
against that image's `hex_span` in `BUILD-MANIFEST.json` and against the target's
`hex_span_expected` in `rig-pins.json`; a disagreement is a `FAIL:`, because it means the
image is not the artifact the manifest describes.

The judge. Because every target's hex begins at 0x0000 and contains no gaps, the comparable
region is the plain `[0, span)` prefix of the read-back — no offset arithmetic. Take that
prefix, compute SHA-256 of it and of the objcopy output, and set `judged_match`. On a
mismatch, report the count of differing bytes and the first 20 differing offsets with both
values, following the in-repo compare-and-report precedent, and exit non-zero.

Separately compute the SHA-256 of the whole 32768-byte read-back and record it as
`sha_whole_flash_unjudged`. It is never used to pass or fail anything: because
`board_upload.maximum_size` is 32768 on all three envs the linker no longer protects the
bootloader region, so a full-flash read spans regions the `.hex` never covers — optiboot
512 B, urboot 384 B, Caterina 4096 B. It is recorded because it costs nothing and leaves
Phase 165 something to examine if a bootloader-overwrite hypothesis ever arises.

The judged span is a **function of the pinned policy**, not a constant. Read
`targets.<target>.judged_span_policy` and `vector_exclusions`. When the policy is the
hex-extent value, judge `[0, span)`. When it names a vector-exclusion policy, exclude
exactly the recorded offset/length windows from both sides of the comparison and set
`vector_exclusions_applied` to the applied list, so the exclusion appears in the verdict
rather than only in the tool. When the policy is still the placeholder value that plan 01
wrote for `uno328pb`, **refuse to judge**: exit non-zero with a `FAIL:` line stating that
the bootloader interrogation has not yet been recorded and that judging now would risk a
false mismatch at 0x0000 on every correctly-flashed board.

`--flashed-arm` and `--expect-arm` are separate arguments with the two arm names as closed
choices. For a normal cell flash they are equal. For the deliberate cross-flash they differ,
and that is the whole mechanism by which D-03 is expressible as one recorded invocation:
the other arm is on the board, the judge is pointed at the intended arm's hex, and the
mismatch is the deliverable. Record both values in the verdict so the record shows what was
flashed and what it was judged against.

`--readback PATH` judges an existing read-back file without touching a device;
`--no-read` is its explicit companion for re-judging. These are what make the tool testable
without hardware and re-runnable against a committed artifact.

Write `READBACK-VERDICT.json` atomically and also write the judged-span SHA and the
whole-flash SHA into a `sha256sum`-format file in `--out-dir`, so both data are re-checkable
with `sha256sum -c` rather than existing only in prose.

`--selftest` runs entirely without a device, in a temporary directory, using synthetic
Intel-hex fixtures and synthetic read-backs. Positive legs: a read-back whose prefix equals
the hex extent judges as a match, and the whole-flash SHA differs from the judged SHA
(proving the two data are distinct). Negative legs, each producing a non-zero exit with a
message naming the check: a read-back shorter than the target's flash size (the truncation
symptom `-A` exists to prevent); a read-back whose prefix differs from the hex extent, with
the differing-offset report present; a `--expect-arm` pointing at the other arm's hex against
a read-back of this arm (the cross-flash shape, proven to produce a mismatch on synthetic
data); a target whose `judged_span_policy` is the placeholder value; an objcopy output size
that disagrees with the recorded `hex_span`; and a missing read-back file. Return 0 only if
every positive and negative leg behaves as specified.

Author `.planning/v1.34/tools/judge_wrv.py` to the pinned conventions, with a re-pathed D-16
boundary paragraph.

The tool judges a position, never a command. It takes `--written` (the image that was
written), `--reads` (the directory `dev consistency-check` filled), `--expect-size` (65536 or
262144, taken from `rig-pins.json` `chips.*.size_bytes` and required to match one of them),
`--app-verdict` (the exit code the app returned, recorded but not judged), `--position-id`,
and `--out`.

Glob `run_*.bin` in `--reads` and **count the files**. Do not assume N. On a hardware or
serial error the app returns 2 early from inside its run loop, leaving fewer than N files;
that state is the `incomplete-read-set` verdict, reported with the actual count and the
expected count, and it is not a retry trigger.

Assert every read file's size equals `--expect-size` exactly. A wrong-sized read file is a
`size_violations` entry and a non-zero exit — a short read compared by SHA would otherwise
look like a plain mismatch and hide its own cause.

Compute SHA-256 over the full `--expect-size` bytes of each read file and of `--written`.
The judged verdict is `match` only when every read file's SHA equals the written image's SHA.
This is the whole point of RIG-04's "never an exit code": the app's own
`Consistency check: PASS` is computed as one distinct SHA across the N reads and compares the
reads **to each other**, never to the written image, so a chip that reliably returns the
wrong bytes passes it. That is the specific false green D-12's distinct per-position images
insure against, on the arm whose entire premise is that nothing changed.

Set `distinct_read_shas` to the number of unique read SHAs. When it exceeds 1, the verdict is
`disagreement` — emitted as a recorded outcome, with every individual read SHA listed, and
never retried away. Set `n3_disagreement` true in that case so the conditional
control-arm arbitration D-11 prescribes has a machine-readable trigger.

Record `--app-verdict` as `app_verdict_unjudged` and compute `verdict_disagreement`: true
whenever the app's three-way code and the SHA verdict do not agree in direction — for
example the app reporting 0 while the SHA verdict is `mismatch`, or the app reporting 1 while
every read matches the written image. A disagreement between the two oracles is itself the
finding: report it on stdout, put it in the verdict JSON, and exit non-zero so it cannot pass
unnoticed. Follow the in-repo precedent where a contradiction between two recorded
observations is the reported failure rather than something the tool resolves.

Note in the docstring that the app's verdict block carries `Board: unknown-board` as a
hardcoded literal rather than a lookup, so nothing in that block may be used for provenance.

Write the verdict atomically and print one positive verdict line to stdout carrying the
judged verdict, the read count and the distinct-SHA count.

`--selftest` runs with synthetic fixtures in a temporary directory and no device. Positive

`size_violations` entry); an `--expect-size` that is neither 65536 nor 262144; an empty
`--reads` directory; and a missing `--written` file. Return 0 only if every leg behaves as
specified.
