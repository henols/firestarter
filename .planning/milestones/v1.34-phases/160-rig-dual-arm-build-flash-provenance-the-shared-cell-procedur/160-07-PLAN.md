Determinism is a contract, not an aspiration. Emit rows in a deterministic order derived from
the record (sorted by `position_id`), emit no timestamp, no hostname and no value that is not
derived from the JSONL, use LF endings explicitly, and format every hash and numeric field
identically on every run. State the contract in the docstring the way the in-repo codegen
precedent does. The reason is concrete: the prior milestone's evidence Markdown carries a
generation timestamp, and a timestamp would make `--check` permanently red.

`--check` re-renders from the JSONL in memory and byte-compares against the committed
`--target` without writing anything. Equal means exit 0; different means exit non-zero with a
unified diff of the first differing region, so a hand-edit is named rather than merely
detected. This is the leg that has no Python analog in the tree — the nearest precedent is a
bash byte-compare — so write it deliberately rather than by adaptation.

`--append` appends one row from a JSON file or stdin. Because the record is append-only,
implement it as read-all, validate the new row against the schema's `record_keys`, assert the
existing rows are unchanged, then write the whole file atomically via temp file plus replace.
A plain append is not atomic and a torn write mid-sweep would be unrecoverable; and asserting
the prefix is unchanged before replacing is what makes "append-only" enforced rather than
intended. Reject a row whose `outcome` is outside the schema's domain, whose `position_id`
duplicates an existing row, or that omits any declared key.

Fail closed: a missing or empty `--jsonl`, a line 1 without the schema header, or a zero-row
render with a non-empty JSONL each exit non-zero. Never write an empty target and exit 0.

`--selftest` uses fixtures in a temporary directory. Positive legs: rendering a two-row
fixture twice produces byte-identical output; `--check` against that freshly rendered target
exits 0; appending a valid row preserves the earlier rows byte-for-byte. Negative legs, each
a non-zero exit with a named reason: a target with one character changed fails `--check` and
the diff names the line; a fixture whose line 1 lacks the header; an empty JSONL; an append
whose row omits a declared key; an append whose `outcome` is outside the domain; an append
whose `position_id` already exists; and an append attempted against a file whose earlier rows
have been altered. Return 0 only if every leg behaves as specified.
