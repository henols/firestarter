**`## Scope`** — one cell run, both arms, both chips; the four positions a cell holds; the
statement that this document is executed unchanged by Phases 161, 162 and 163 and that any
change to it after the first cell must be recorded as a procedure amendment with the cells it
does and does not apply to.

**`## Standing bench rules`** — restate the rules that bind the steps, each as a rule rather
than a preference: port identity is re-verified for every cell because device node numbering
shuffles across replug and is never inherited from a previous task; the chip is out of the
socket before any sideload on the two Uno-class boards and the Leonardo is exempt and is
flashed with the chip seated; photography, multimeter readings, chip handling and pot
adjustment are operator-only and Claude drives serial and CLI only; the operator adjusts the
pot himself — state the target, wait, take exactly one confirming read, never a monitor loop;
the VPP and VPE monitors do not route to the socket, so a blank or nonsense reading means a
contact fault rather than a rail fault; board identity is by silkscreen and signature, never
by a firmware-reported revision field, because the three shields the operator owns cannot be
distinguished that way and two of them collide on the same resistor value; and this procedure
must not be executed under an auto-advance or chained mode, because those auto-approve the
human-verify gates the physical steps depend on.

**`## Arm substitution`** — the single arm-dependent token is `$ARM_BIN`, resolved to one of
the two absolute arm binary paths in `rig-pins.json`. No step text differs between the arms;
the arm enters only through that token's value and is therefore visible verbatim in every
recorded command line. State the reason plainly: both arms report the identical application
version and the boards report the identical firmware version, so the invoked path and the
device read-back are the only two places the arm exists at all. List the other substitution
tokens (`$PORT`, `$CELL_ID`, `$POSITION_ID`, `$SHIELD_REV`, `$CHIP`, `$TARGET`, `$MASK`,
`$CELL_DIR`) and state that none of them is arm-dependent.

**`## Step list`** — eleven numbered steps with the ids `P-01` through `P-11`, in the order
research derives from the colliding standing rules rather than inventing one. Each step
carries: its id, one line of imperative text, who performs it (operator or Claude), the
literal command shape where one applies, and the fields it contributes to the record.

- `P-01` Operator mounts the shield on the board and declares the shield revision from the
  silkscreen. Silkscreen is authoritative.
- `P-02` Claude re-verifies port identity for this cell: the signature probe as the
  authoritative board identity, plus the port's controller string as a separate
  port-identity datum. Both recorded. Never inherited.
- `P-03` Uno-class only: operator removes the chip and confirms. This window covers the
  flash **and** its read-back proof, because an avrdude read is the same electrical
  situation as a write.
- `P-04` Claude runs `capture_provenance.py` for this position, then flashes the arm via the
  PlatformIO upload path with the pinned working directory, then proves the flash with
  `judge_readback.py` against that arm's own hex extent, recording both the judged verdict
  and the unjudged whole-flash datum. D-05: this runs at every cell's flash, not only at
  bring-up.
- `P-05` Uno-class only: operator seats the 28-pin chip and confirms.
- `P-06` Pot: Claude states the target for the declared VPP value, the operator sets it and
  reports, and Claude takes exactly one confirming read. Set **once per cell**, not once per
  chip, because both bench chips declare the same VPP target — this is the single largest
  simplification available to the step list and it is why the pot step sits before the chip
  rotation rather than inside it. If the historical VPP-high init guard fires, the pot is
  adjusted until the reading is in band and the run restarts clean; the guard is never
  bypassed.
- `P-07` Claude generates this position's image from its recorded mask and stamp width, runs
  the write with no forbidden flag, times it by wall clock, then runs the read set and judges
  it over 65536 bytes with `judge_wrv.py`.
- `P-08` Operator swaps to the 32-pin chip and confirms. **No pot re-adjustment** — the
  declared VPP target is the same for both parts.
- `P-09` As `P-07`, over 262144 bytes.
- `P-10` Arm switch: return to `P-03` for the second arm. The arm order is control first,
  then v1.33, so the control arm is never the arm that inherits the other's chip contents.
- `P-11` Teardown: record the final board and arm state, re-verify the shared config
  directory's content SHA is unchanged, and append the position rows to the evidence record.

State the read-count rule inside `P-07` and `P-09` rather than as a separate step: three
independent reads on the v1.33 arm at every position; a single read on the control arm; and
the control arm's three-read set fires only at a position where the v1.33 arm's three reads
disagreed, so a read-stability finding on the headline arm can be attributed rather than left
hanging. A disagreement is recorded as a disagreement and never retried away.

Also state the one-clean-re-seat allowance carried from the prior bench phase: a single clean
re-seat is permitted when a contact fault is suspected, and both the discarded attempt and
the re-run are recorded — the discard is never silent.

**`## Outcome taxonomy`** — the two axes, stated as different axes rather than a reconciled
one. A cell outcome is two-state: validated, or skipped-with-reason. Anything that is not a
clean pass is a fail; anything not attempted is a skip; there is no third state. The
three-state axis — the one this milestone's triage requirement introduces — applies to a
*failure* after the fact, in Phase 165, and never to a cell result. Say explicitly that the
prior phase's ban on a third cell state is not being relaxed.

**`## Halt policy`** — the two branches, as `P-H1` and `P-H2`, so the distinction is not made
under pressure mid-sweep. `P-H1`, a **rig** failure — a read-back mismatch on a board that
was correctly flashed, a judge crashing, a provenance field missing, a gate that cannot read
its input — halts and is fixed in-phase, because the rig is this phase's deliverable and
every later cell rests on it. `P-H2`, a **cell** failure — a write that fails, three reads
that disagree, a chip that reds — is recorded with its observed symptom and carried to
Phase 165, and the sweep continues; that is what makes the later classification possible at
all. Note that the prior bench phase's policy of halting and handing to a debug session is
deliberately not inherited, because this milestone has a designated triage phase instead.

**`## Write-duration definition`** — wall-clock around the write command is the judged
measure. It is the only measure that exists for every arm, every target and every outcome,
which matters because one cell's write is expected to fail on both arms and the app emits no
duration line on failure, and because intra-block progress frames are compiled out on two of
the three targets so frame scraping is unavailable there. Record the app's own success-only
figure alongside as an unjudged second datum whenever it is present. State explicitly that
wall-clock includes process start-up and the serial handshake, so it is comparable arm to arm
but is not comparable to the v1.31 figure unless that figure was taken the same way. Resolve
which measure the v1.31 W27C512 0.37 s consistency figure was by reading the v1.31 bench
record; write the answer down. If it cannot be determined from the record, say so on the same
line and mark it as an honesty-ledger line for Phase 166 rather than drawing the comparison
anyway.

**`## Forbidden invocations`** — the flags and binaries that never appear in a bench command,
each with its reason: the force flag, whose standing permission was withdrawn in the prior
bench phase; the blank-check-skip and erase-skip flags, which have no place in a normal
position, with the note that the erase-skip flag corrupts a non-blank electrically-erasable
chip while still reporting success, and the correction that the superseded framing in which
the blank-check flag also skipped the erase no longer holds because the erase is now a
separate flag and the current help text says the erase still runs; the bare application name,
which resolves to an un-named third arm through a user-site editable install; the host app's
own firmware-install path, which needs a handshake, ignores its board argument and omits the
urclock no-metadata option so it writes different flash content on one target; the stale
avrdude on disk, which predates the urclock programmer entirely; and any `pio` invocation
whose working directory is not the pinned project directory, because the same command string
succeeds or fails depending on cwd.

**`## Recording discipline`** — nothing is fabricated. A reading that tooling blocks is
recorded as a not-measured value with its blocking reason on the **same line**, never as a
blank. A negative control is recorded as having fired, not as having been configured. The
judged verdict and the unjudged verdict are recorded separately and a disagreement between
them is itself a finding. Every recorded command is the literal argv with its working
directory. No SHA is transcribed by hand.

Keep every step's text free of any arm-conditional clause, and do not use the
`[arm: control]` / `[arm: v133]` annotation syntax anywhere in the real step list — it is
defined so the gate has something to detect, and its absence is what SC#3 asserts.
