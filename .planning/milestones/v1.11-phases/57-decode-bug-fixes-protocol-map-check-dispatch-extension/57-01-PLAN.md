<objective>
Fix the four confirmed decode bugs in `build_db.py` so the decode pipeline matches the minipro-source-grounded semantics documented in the Phase 56 field dictionary. This plan touches ONLY `build_db.py` (the decoder) plus a new focused test file; it does NOT regenerate `chip_database.json` (that is plan 57-03, in wave 2, after both wave-1 source edits land).

The four fixes are surgical, line-targeted edits already verified against minipro source commit `a8efaedc`:
- BUG-1 (DEC-04): `VCC_VOLTAGES` missing nibbles 0x02 (4V) / 0x03 (4.5V).
- BUG-2 (DEC-03): `interpret_timing()` applies a wrong x100 multiplier for protocols 0x07/0x0B; raw `pulse_delay` is already microseconds for all protocols. Also fixes the bare `except:` (ruff BLE001).
- BUG-3 (DEC-04): `vcc`/`vdd` field labels are swapped relative to the minipro bit-field layout.
- BUG-4 (DEC-05): `PROTOCOL_MAP` carries wrong/invented names; non-memory and phantom IDs must be removed or documented as excluded, and `KNOWN_PROTOCOLS` plus the second-pass `_etype` set must drop 0x35/0x39.

Purpose: DEC-02 (umbrella field-decode correctness) is satisfied by combining these four fixes with the Phase 56 dictionary review (which found no fifth bug). The corrected decoder is the prerequisite for the wave-2 DB regeneration and per-chip diff.

Output: A corrected `firestarter_app/tools/build_db.py` and a new `firestarter_app/tests/test_decoder.py` (or additions to it) asserting the corrected values. No DB regeneration in this plan.
</objective>
