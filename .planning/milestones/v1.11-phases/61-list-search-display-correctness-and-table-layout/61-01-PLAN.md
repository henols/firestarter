<objective>
Resolve the Phase 60 IN-01 `info`-vs-`list` divergence by routing the `firestarter list` / search table's Type label and VPP column through the same `electrical.type` ground truth that `firestarter info` uses (Phase 60), and enforce the table-layout rules: fit all columns without breaking, never render any column narrower than today's default width.

Purpose: The list view currently derives Type from the int `mem_type` (`get_chip_type_string(ic.get("type"))`) and gates VPP on `ic.get("type") == 1`, while `info` derives Type from `_ELECTRICAL_TYPE_LABEL` keyed on `electrical.type` and gates VPP on `vpp_mv > 0 AND electrical.type != "SRAM"`. The two views disagree on Type and VPP for the EEPROM-family chips reclassified in Phases 59/60 (W27C512, SST27VF512, SST27SF512, W27C257), and the list shows a spurious 12.0v VPP for SRAM. This phase makes the two views structurally incapable of disagreeing by extracting the label logic into one shared helper and carrying the raw `electrical.type` string into the mapped data the list consumes.

Output: One shared label helper on `EpromSpecBuilder`; `_map_data` carries `electrical.type`; `print_eprom_list_table` rewired to the shared helper + the `info` VPP gate + dynamic Name-width clamp and fixed VPP width; a parametrized list-vs-info parity test and a width-floor/no-break assertion.

HOST-ONLY. No firmware changes.
</objective>
