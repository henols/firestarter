**The 25 rows that started emitting `page-size` on the wire the moment plan 01 regenerated the database are now a named, provenance-carrying delta layer -- proven key-disjoint from the existing 149 page-size layer by the gate's own six-pair collision check, not by argument.**

## Accomplishments

- Generated `tests/golden/wire_dict_expected_deltas_194.json` programmatically. The script walked every manufacturer's chip list by positional index and kept rows where `programming.algorithm == 5`. It excluded any row whose frozen-baseline record already carries `page-size`. Exactly two rows were excluded this way: `WINBOND|W29C020,W29C020C,W29C022|7` and `WINBOND|W29C040,W29C042|8`. Each kept row's value came from the live wire dict, not the database field. Result: exactly 25 entries, with distinct values `{64, 128, 256, 512}`. Every value was then cross-checked against `programming.infoic_page_size_raw` in the regenerated database. This is an independent second route to the same numbers. A mis-keyed entry would show up there as a value mismatch, not pass silently. The `meta` block carries the same five keys as the 149 layer (`decision`, `honesty`, `how_to_update`, `phase`, `provenance`). `provenance` states the index suffix is generated programmatically. `honesty` states the layer proves emission, not value correctness -- that proof is the 27-row host leg's job and the native consumption suite's job.
- Confirmed the frozen baseline and all three existing delta layers are byte-unchanged. `sha256sum -c` against the plan's four pinned hashes reports `OK` for `wire_dict_baseline.json`, `wire_dict_expected_deltas_149.json`, `_153.json` and `_182.json`.
- Renamed the composition test to `test_live_capture_matches_golden_plus_the_149_and_153_and_182_and_194_deltas`. Reworded the module docstring's coverage list (items 1 and 6) to enumerate four layers, including the load-bearing 194x149 field-collision risk.
- Added the 194 layer's two non-vacuity assertions. The first requires every delta key to exist in the frozen baseline. The second requires the baseline's own record for each key to not already carry `page-size`. Added an exact-count guard at 25, kept as an equality, not a floor. This matches the rule the module already states for the 149 layer's own count.
- Extended `layer_pairs` from three pairs to six, adding `194x149`, `194x153` and `194x182`. The existing field-collision loop stayed unchanged. It now proves `194x149` is key-disjoint: 27 upstream-native `0x05` rows against 18 upstream-native `0x0D` rows. That is the only pair where both layers carry `page-size`. The proof replaces an argument in prose.
- Composed the 194 layer into `test_exactly_84_records_change_flags_and_no_other_field_moves`'s own `expected` side, alongside the pre-existing 149 and 182 layers. This keeps the leg's exhaustive-scope claim about the 153 layer exact: 84 changed records, one changed field (`flags`). Before this edit the leg reported 109 changed records across two fields. After, it reports exactly 84 across `{"flags"}`, as originally designed.
- Left two legs untouched, per the plan's STEP 5. The anti-laundering leg (`_GOLDEN_PAGE_SIZE_RECORD_KEYS`) and the nine-wire-key-union leg both describe properties of the frozen baseline or the live wire-key set. This layer does not move either property.
