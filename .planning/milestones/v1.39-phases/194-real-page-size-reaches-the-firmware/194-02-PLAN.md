## The measured geometry this plan drives

The 27 protocol `0x05` parts reduce to **7 distinct** `(mem_size, real_page)` pairs, which cover
them exhaustively:

| # | mem_size | real page | old derived page | verdict |
|---|---|---|---|---|
| 1 | 32768 | 64 | 64 | equal |
| 2 | 65536 | 128 | 64 | **under by 2x** |
| 3 | 131072 | 128 | 128 | equal |
| 4 | 262144 | 128 | 128 | equal |
| 5 | 262144 | 256 | 128 | **under by 2x** |
| 6 | 524288 | 256 | 256 | equal |
| 7 | 524288 | 512 | 256 | **under by 2x** |

Rows 4 and 5 share a `mem_size` and differ only in page size, which is exactly why a
capacity-derived value cannot serve both. After D-06 the handler never reads `handle->mem_size` for
page arithmetic at all, so the `mem_size` column is decorative to the oracle. That is itself a
finding worth asserting, and case 8 asserts it.

## The measured non-vacuity constraints

Three measured facts govern how these cases must be written. All three come from probes run against
this exact suite.

1. **The recorder saturates.** Density is exactly three records per written byte plus eleven for the
   SDP prefix. At the pre-change cap of 256 that is roughly 81 bytes. Plan 01 raised the default cap
   to 4096 and added `bus_recording_saturated()`. Every case here asserts non-saturation.
2. **`DATA_BUFFER_SIZE` caps one call at 512 bytes** on the native build. The 512-byte page
   therefore cannot be exercised as a multi-page write in a single `write_execute` call. Drive the
   handler twice with an advancing `handle->address` instead, which models the real chunked path.
   For a 512-byte page, call one at address 0 with `data_size` 512 and call two at address 512, where
   page-start detection evaluates 512 ANDed with 511 and yields a page start.
3. **Register-write elision is not modelled.** This suite gets the replica stub, so the recording
   holds writes production would elide. Key every oracle on the SDP unlock signature, whose three
   addresses differ from each other and from every data address, so no cache compare can remove the
   bytes the oracle reads.
