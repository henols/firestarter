<objective>
Refuse a protocol `0x05` write on the host, before any serial byte, when the resolved chip carries
no page size -- with a message that names the chip.

Purpose: D-07 requires the refusal in both layers, for different reasons. The firmware refuses
because it is the only layer that can protect the silicon from any caller. The host refuses because
it is the only layer that knows the chip's name, and because refusing before the port opens costs
the operator nothing and tells them what to do. Neither layer makes the other redundant. This plan
implements the host half of D-05 and D-07.

Output: a pure-predicate gate module, a typed exception with its own rendering arm, guard calls at
the operator layer and the CLI pre-flight, and a test module covering refusal, pass-through and the
non-`0x05` no-op.
</objective>

the property: the guard fires before any wire dict reaches the transport and before any serial byte
is emitted, so the host will not drive hardware for a protocol `0x05` chip whose page size is
unknown. Subclass `EpromOperationError` rather than a bare exception, because the CLI's typed-error
mapper already handles that family and task 2 gives this subclass its own rendering arm.

STEP 2 -- `firestarter/page_size_gate.py`, a new module. Two public functions and one message
constant, with no imports beyond typing, the exception and the existing protocol-id constant.

The predicate, `requires_page_size(programmer_data)`, returns whether this resolved wire dict
describes a protocol `0x05` part. Key it on the `algorithm` value and import `FLASH4_PROTOCOL_ID`
from `flash4_erase_gate` rather than writing the literal 5, so the `0x05` predicate stays
single-sourced. Do not key it on a capability flag: the flag is also clear for parts with no erase
command at all, so a flag-based predicate would silently widen the refusal past the parts this phase
examined.

The raiser, `require_page_size(chip_name, programmer_data, operation)`, returns `None` when the
operation is not a write, and returns `None` when the predicate says this is not a protocol `0x05`
part. Otherwise it raises `PageSizeUnavailableError` unless the wire dict carries a truthy page-size
value under the wire key spelling `constants.py` defines. This is the **fail-closed** direction, and
it is the opposite of the erase gate's documented fail-open polarity. Absent evidence that a real
page size exists means the part is not provably safe to write, because a guessed page size destroys
data in both directions and neither direction is a degraded mode.

The message names the chip, per D-07. Use the chip name upper-cased, followed by a statement that no
page size is recorded for it and that a protocol `0x05` write is refused. Follow the erase gate's
single-format-constant style so the wording has one home.

STEP 3 -- keep the module free of I/O. It must not open a serial port, probe for a programmer, or
