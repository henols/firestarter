<objective>
Expand the host half: make the two refusal layers agree on which page sizes are valid, cover the
alignment guard's full property matrix, and measure criterion 4's regression surface from the
shipped database rather than transcribing it.

Purpose: the tracer proved one refusal and one pass-through. Three things remain. First, the host
still accepts page sizes the firmware rejects -- 96, 1024, 65535 all pass the host gate and fail
deep inside the firmware state machine, which is a pending review finding on the exact module this
phase extends. Second, a refusal guard needs its pass-through twin at every page size the shipped
database actually carries, or "not a blanket refusal" is a claim rather than a measurement. Third,
the roadmap's criterion 4 names four validated parts, and one of them is not a protocol `0x05` part
at all -- that correction has to be asserted in code, not only written down, so a future reader who
re-adds it gets a red test rather than a vacuous bench run.

Output: the accepted-page-size test folded into `require_page_size` with its pending todo closed,
the alignment test module extended to the full matrix including both empty-edge legs, and a new
regression-surface module that reads the shipped database and pins criterion 4's real shape.

There is no `195-CONTEXT.md`. The operator chose to plan without one and delegated the fix-shape
decision to the planner, on the research evidence. These are the closures, each one line, repeated
verbatim in every plan of this phase.

| ID | Decision | Reversibility |
|---|---|---|
| D-01 | The fix shape is a two-layer **refusal**: a host pre-flight predicate `S % P == 0 && L % P == 0` that runs before the port opens, plus a firmware per-chunk guard. Read-modify-write is not built. | costly |
| D-02 | The new ERROR-severity message id is `0xC0`, extending the ERROR band past the exhausted `0xA0-0xBF` range; the convention is recorded in the catalog header and the pending band todo is closed in the same commit. | costly |
