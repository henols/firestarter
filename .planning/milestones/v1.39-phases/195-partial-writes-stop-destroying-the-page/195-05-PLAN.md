<objective>
Prove on real silicon that a partial write destroyed bytes it was not asked to touch, then prove
that with the fix in place the same two commands refuse and leave the device byte-identical.

Purpose: the milestone's own decision D-4 makes bench validation required rather than optional, and
states that a green native test is not sufficient for a defect found on a bench. WRITE-03 goes
further and requires **both** loss directions. The sequencing that follows is not a preference: once
the fix lands, neither direction can be produced at all, so the demonstration has to come from a
pre-fix build of this same tree. The bench session therefore flashes twice and runs the identical
commands against each.

Output: a committed transcript in the shape of this milestone's previous bench record, with the rig
identity re-confirmed rather than trusted, both firmware builds attributed by their size lines, both
loss directions captured verbatim, the post-fix refusal with a byte-identical read-back, and the
aligned no-regression write -- plus the requirement flips the evidence supports, and status notes on
anything it does not.

## Phase decisions closed by this plan set

There is no `195-CONTEXT.md`. The operator chose to plan without one and delegated the fix-shape
decision to the planner, on the research evidence. These are the closures, each one line, repeated
verbatim in every plan of this phase.

| ID | Decision | Reversibility |
|---|---|---|
| D-01 | The fix shape is a two-layer **refusal**: a host pre-flight predicate `S % P == 0 && L % P == 0` that runs before the port opens, plus a firmware per-chunk guard. Read-modify-write is not built. | costly |
| D-02 | The new ERROR-severity message id is `0xC0`, extending the ERROR band past the exhausted `0xA0-0xBF` range; the convention is recorded in the catalog header and the pending band todo is closed in the same commit. | costly |
| D-03 | No override flag ships in this phase. An override that proceeds and then prints the plain success line violates WRITE-02 literally, and its output contract is a separable usability decision. Filed as a todo by plan 04. | reversible |
| D-04 | The firmware guard **refuses**; it never warns and proceeds. With a passing host predicate no legitimate chunk is ever misaligned, so the guard has zero false positives and is the only defence against an old, third-party or downgraded host. | reversible |
| D-05 | The pending `host-page-size-gate-accepts-invalid-values` todo is folded in: `require_page_size` gains the same power-of-two and 512-ceiling test the firmware applies, so the two layers agree on which page sizes are valid. Plan 03 implements it. | reversible |
| D-06 | The third loss direction -- interior loss at a chunk boundary, derived from source and never observed -- is modelled in the native suite by plan 02 and attempted on the bench by plan 05, and its result is recorded either way, including "not attempted, with the reason". | reversible |
| D-07 | Scope correction: `SST39SF020` is `algorithm: 6` (PROTO_FLASH_NOR_UNLOCK), not protocol `0x05`. It never traverses `flash_5v_page.cpp` and cannot regress from this phase. Success criterion 4 therefore reduces to one bench part plus database and native checks, and the correction is recorded rather than covered by a vacuous bench pass. | reversible |
| D-08 | The host predicate extends `page_size_gate.py` with a second public function rather than opening a sibling module, so `_WRITE_OPERATIONS` and `FLASH4_PROTOCOL_ID` stay single-sourced. The module docstring's purity claim is narrowed in the same edit from "no I/O" to "no transport I/O", because the raiser performs one size probe of the payload path and fails closed on it. | reversible |
| D-09 | The `|| is_first_byte` and `|| is_last_byte` clauses stay in `flash_5v_page_write_execute`. The silicon commits the page by itself 200 microseconds after the last load, so deleting them removes the SDP unlock and the verify poll -- not the commit -- turning a loud corruption into a silent one. Under the guard they are provably redundant, not wrong. | reversible |
| D-10 | The new message carries two params so the operator can tell which clause fired: a `u24` address rendered as a hex address and a `u16` size rendered as decimal, emitted with the file's existing five-byte big-endian pack pattern. | reversible |
| D-11 | Bench evidence runs on `W29C020` on the Leonardo rig, and the loss reproduction leg runs on a firmware build made by reverting exactly one source file to its pre-195 blob -- because once the fix lands, the loss cannot be demonstrated at all. | reversible |
| D-12 | `dev test`'s 256-byte write region at address 0 is **not** changed. It stays aligned for `P` in {64, 128, 256}, which is 25 of 27 parts including all three protocol `0x05` validated parts, and becomes a refused partial page on the two `P = 512` parts, neither of which has ever been tested on silicon. Plan 03 asserts the consequence so it is visible rather than discovered, and plan 04 files the region-rounding proposal. | costly |

## The bench facts that govern this plan

| Fact | Consequence |
|---|---|
| `W29C020` records page size 128 and its derived page size was already correct before Phase 194 | A result on it isolates this defect from the previous phase's, which is exactly what the roadmap's third criterion asks for |
| Both reported defects were reproduced on this exact part, on a Leonardo with a Rev 2.0-class shield | Running the same part on the same class of rig is what makes a before-and-after comparison meaningful |
| The fix refuses, so it cannot produce the loss | The reproduction leg needs a pre-fix build of **both** halves: the host refuses before the port opens, so a post-fix host would mask a pre-fix firmware |
| The reported hardware revision cannot distinguish the shields the operator owns | Ask which shield is mounted. Never infer it |
| Serial device numbers shuffle across a replug, and the bootloader touch renumbers the node | Confirm the controller identity on the exact port before every operation, and re-identify after every flash |
| A plain write on this part does erase first, and the blank-check-skip flag also skips the erase | Run plain writes. The skip flag corrupts a non-blank chip and still reports success |
| Chip removal before a firmware sideload applies to the Uno class only | A Leonardo is exempt, so the part may stay seated across both flashes |
| A region read seeks to the absolute offset and hole-pads ahead of it | Read from zero with an explicit size covering the whole probe window |
| The pattern rule varies within a page and differs between adjacent pages | Any erased run shows as a `0xFF` block at a page-aligned boundary, which is what makes a misplaced boundary visible |
| The reproduction deliberately destroys data on the seated part | The part is a bench part and the baseline is re-applied between legs; the operator is told this before the run starts |

operator gave.

independently re-confirms the part's real page size.

result is as valuable as a positive one. If the rig or the time does not permit it, record that it
