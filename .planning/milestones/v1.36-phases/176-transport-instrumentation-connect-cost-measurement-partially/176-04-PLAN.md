## Flagged planner assumptions

- **PA-11 (CLI surface).** `connect-cost` is a third value on the EXISTING `--mode` choice of
  `dev fault-inject`, not a new `dev` subcommand. A new subcommand would require adding a row to
  `channel.BETA_ONLY_DEV_COMMANDS`, whose pinning test at
  `tests/test_dev_tools_channel_gate.py:152` asserts the exact tuple, AND would make the comment
  above that tuple -- which counts "seven" gated and "9" total subcommands -- stale. The standing
  project rule forbids writing or editing comments in source, so a stale comment could not be
  corrected. Extending `--mode` is also what `176-PATTERNS.md` recommends. The cost is that
  `dev fault-inject` now hosts a mode that is not a fault injection; that wart already exists for
  `--mode latency`.
- **PA-12 (clock choice).** `time.monotonic()`, following the one existing latency harness in this
  same file, rather than RESEARCH's suggested `time.perf_counter()`. Both are monotonic interval
  clocks and either is correct for a 2.5 s interval; consistency inside `eprom_operations.py` is
  worth more here than a marginally finer resolution nobody will use at three decimal places.
- **PA-13 (median tie-break).** Lower-median on an even sample count (`statistics.median_low`),
  never the two-sample average. The contract is that every number in the artifact is a duration that
  was actually observed. This is the concrete answer to the MEAS-01 precision edge probe.
