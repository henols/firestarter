<objective>
Wire the fourth instrumentation site -- `get_response`'s timeout -- and make it honest by scoping
it, then discharge the two requirements that are about recorded reasoning rather than new code.

`get_response`'s timeout fires once per failed port probe on every ordinary connect. Counted
globally, a healthy three-board rig crosses `_SUSPECT_THRESHOLD = 5` by the sixth wrong-port probe
and reports itself transport-suspect. Scoping the counter is what makes `5` defensible unchanged,
and "justified against real counts" is an explicitly legitimate MEAS-02 outcome. MEAS-03's
deliverable is likewise not code: it is the recorded end-to-end trace showing which of
`retries` / `timeouts` / `cobs_errors` / `crc_failures` are genuinely wireable, and WHY the
unwireable ones stay `not measured`.

Purpose: close the honesty half of this phase -- the half where the wrong choice makes the report
actively mislead a triager.

Output: `timeouts` and `probe_timeouts` wired and separated, the unchanged-rule proven in all four
of its senses, the threshold's basis recorded, and the three dead counters' reasons written where a
future "fixer" will read them.
</objective>

## Flagged planner assumptions

- **PA-5 (MEAS-02, unclassified edge-probe row).** The probe returned `unclassified` for MEAS-02 and
  it is NOT auto-resolved. Read manually, the live question is whether `5` is the right number at
  all. This plan does not move it; it makes the argument for keeping it and records that argument
  where the code lives. If the operator wants a different integer, the basis paragraph is the place
  to change and the 4 / 5 / 6 boundary test is the place that pins it.
- **PA-6 (MEAS-03, unclassified edge-probe row).** Likewise not auto-resolved. Read manually, the
  live question is where "the reason recorded" has to live to be durable. This plan puts it in the
  `TransportHealth` docstring and pins each reason with a substring assertion, so it cannot be
  silently deleted. The alternative -- recording it only in a `.planning` artifact -- was rejected
  because a future phase reading `retries: int | None = None` will look at the docstring, not at a
  closed phase's paperwork.
- **PA-7 (probe scoping mechanism, RESEARCH open question 3).** The scope is a module-level context
  manager in `transport_counters`, entered around the single `_probe_port` call site in
  `find_and_connect`, rather than a per-instance flag on `SerialCommunicator`. The per-instance form
  was rejected because `make_comm` bypasses `__init__` via `__new__` and hand-mirrors eleven
  attributes; every new instance attribute is a new mirror line and a new class-versus-instance
  shadowing footgun, in the same file that already has to hand-set `seen_message_ids` for exactly
  this reason. The module form needs zero `conftest.py` changes.
- **PA-8 (`timeouts` reuse).** The EXISTING `timeouts` field carries the established-connection
  count rather than a new `response_timeouts` sibling. RESEARCH's additive-siblings rule forbids
  REPURPOSING one of the four slots; wiring `timeouts` to a timeout count is not a repurpose, it is
  the field's own meaning. Leaving it `not measured` while an identically-shaped sibling carried the
  value would break RPT-C2's letter, which reserves the sentinel for counters genuinely not wired.
