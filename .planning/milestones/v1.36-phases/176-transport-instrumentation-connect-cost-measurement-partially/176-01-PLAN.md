## Flagged planner assumptions

There is no `176-CONTEXT.md`. Where RESEARCH.md leaves an open question no operator ruling covers,
RESEARCH's own recommendation was taken and is named here, never chosen silently.

- **PA-1 (counter lifetime, RESEARCH open question 2).** The sink is module-level, process-lifetime
  and explicitly resettable, and `dev test` resets it immediately BEFORE
  `read_programmer_identity()`, so the number means "this whole `dev test` command", including the
  identity read's own connect -- RESEARCH's recommendation and "the number a triager reading a
  filed issue will assume". Resetting immediately before `run_plan` ("the plan only") was rejected
  because the identity read's connect is part of what a triager is looking at. There is no
  module-level mutable state in this package today, so this is a new pattern; the lifetime analog
  is `ConfigManager` (`firestarter/config.py` lines 84-97), already written to from inside the
  connect path at `serial_comm.py:913`.
- **PA-2 (Site-C counter name, RESEARCH open question 4).** Named `decode_failures`, not
  `crc_failures`: `codec.decode_id_frame` returns `None` on five distinct causes, so a counter at
  that seam is not a CRC counter. `crc_failures` keeps `NOT_MEASURED`; `176-02` records the reason.
- **PA-3 (write-back shape).** `cli_handlers.py` assigns individual fields on the existing
  `report.transport` object rather than re-assigning a fresh `TransportHealth`. Both are idiomatic
  in that file; field assignment avoids re-listing the counters this phase leaves unwired.
- **PA-4 (RPT-C2, unclassified edge-probe row).** Deliberately NOT auto-resolved. Read manually,
  the live question is what `transport_suspect` does once real counters exist. This plan answers it
  only by keeping the present-AND-elevated rule byte-identical and extending its scanned DOMAIN;
  `176-02` carries the four assertable propositions and the 4 / 5 / 6 boundary.
