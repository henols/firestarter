<objective>
Export what the run already measured, and stop one `None` from meaning two different things.

RPT-A2 is a serialization change only: `Fingerprint` has carried `total`, `bad`, `bad_pct` and
`evidence` since Phase 108, and `_step_dict` throws all four away, emitting the classification string
alone. They become flat additive siblings beside it. RPT-A3 exports `steps[].divergence`, and D-11
completes it: an agreeing read now records a divergence result with `bad: 0`, mirroring PRUNE-03, so
that `None` finally means only what RPT-A3 says it means — no comparison was possible.

Purpose: a triager reading a filed body today sees `fingerprint: "blank/contact"` and cannot tell
whether that verdict rests on four bad bytes or forty thousand. The numbers exist; the report
discards them. And a `divergence: null` today conflates "compared and matched" with "never
compared", which is precisely the distinction a repeat-policy argument turns on.
Output: four flat sibling keys, one exported key, one changed dispatch branch, a moved key-list pin,
one edited test with its reason recorded, and two evidence transcripts.

**One trap this plan exists to avoid.** The read step's reason prose is currently
`"read runs diverged" if divergence else ""`. The moment a divergence result exists on an AGREEING
read, that expression starts telling every clean read that its runs diverged. The reason must key on
whether the runs actually disagreed.
</objective>
