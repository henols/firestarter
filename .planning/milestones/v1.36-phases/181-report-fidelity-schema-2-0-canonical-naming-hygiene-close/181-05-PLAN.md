<objective>
Give a filed `dev test` issue the chip's own database name, and prove the rule that picks it.

One value travels the whole stack: the matched database row's `part_number`, reduced by a selector
that mirrors `get_eprom_config`'s own matching ladder, stamped onto `AutoCapture` once, exported by
`to_dict()`, and read from there by all four canonical surfaces — the issue title, the issue body's
new `canonical_part_number` line, the console table title and the saved report heading (D-03). The
operator's raw token stays exactly where D-03 says it stays: in `ac.chip`, which `dedup_fingerprint`
hashes first, and in both artifact filenames, so the operator still finds the file under the name
they typed.

Purpose: this is the thinnest end-to-end slice of the phase's remaining work, and it is deliberately
first. It touches every layer the rest of the phase touches — engine-adjacent database read, model,
serializer, console render, filed-issue surface, the HYG-04 tooling gate and the frozen-hash
invariance re-proof — so if any of those seams is wrong, one plan finds it rather than five. It also
carries the only key-list pin in the phase that pins an ABSENCE (`_AUTO_CAPTURE_KEYS`'s
`canonical_part_number not in keys` assertion), which no other plan faces.
Output: one pure selector with a stated rule, one additive `auto_capture` key, four canonical
surfaces, a 953-alias sweep, the HYG-04 registration and three evidence transcripts.

`chip="m27c512"` to `chip="M27C512"` produces `776846bf2dc8`, which is already frozen as a DIFFERENT
registered shape.
