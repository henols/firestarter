defaulting to `None`, and `_auto_capture_dict()` gained one corresponding key. It sits
OUTSIDE `dedup_fingerprint`'s explicit five-entry allow-list (`chip` | `protocol` |
`op=verdict:classification` | `repeat_policy_tag` | `coverage_tag`), which is not a
filter that could accidentally widen -- it is a fixed list with no reflection over
dataclass fields, so a field's absence from it is the whole exclusion mechanism.
`ac.chip`, the pre-image's FIRST component, is untouched: none of this plan's edits
write to it, and the whole-database sweep in tests/test_canonical_part_number.py never
calls `_canonical_part_number` in a way that could reach `ac.chip`. So no registered
shape and no already-filed report can re-key. The gate that would redden if that changed
is `test_dedup_fingerprint_is_frozen`'s 19-way parametrization in
tests/test_blast_radius_invariance.py, whose failure message carries the two-commit
review rule verbatim: "If deliberate, land the behaviour change and the re-key of this
literal as SEPARATE commits, so the re-key stays a reviewable unit." All 19 pins are
green (Section 3) and zero twelve-hex literal lines moved since app base 04fd982
