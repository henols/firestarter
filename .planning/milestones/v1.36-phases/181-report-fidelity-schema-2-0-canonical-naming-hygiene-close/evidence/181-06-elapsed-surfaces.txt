## Section 10 (Task 3): what the removed row excluded -- one comparison,
## recorded as evidence of the exclusion, not as an acceptance threshold
## (the milestone's house rule is operation counts, never seconds)

The removed row summed only the per-step durations, so it excluded the
connects (EpromDatabase load, hardware-identity read), plan derivation, the
console render, the artifact write and the submit prompt. `elapsed` covers
CLI entry through immediately before the first serialization -- it INCLUDES
the connects, the database load, the identity read and plan derivation the
old row silently left out, and (like the old row) still excludes the
render, the write and the submit prompt.

One real `dev test` run against a clean-path mock operator (chip M8720, no
live hardware):
  elapsed=0.066
  old_would_be_sum=0.004 (sum of the run's own steps[].duration_s, the
    exact computation the removed row performed)
  elapsed_covers_more_than_old_would_be_sum=true

This is the shape the old row's own removed comment already conceded --
`elapsed` is larger because it counts real setup cost (the identity read
and plan derivation) the summed row never saw. The absolute numbers are
mock-timing artifacts of this one CliRunner invocation, not a threshold;
what is asserted (Task 1's test suite, `_run_step`'s wrapper, and this
section) is the RELATION, per the milestone's operation-counts-never-
seconds house rule.
