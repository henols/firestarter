## Verdict (177-READBACK-INVENTORY.md form)

VERDICT: `divergence: null` now means exactly one thing -- no comparison was
possible (a single-run `--fast` read, or a read whose runs all produced
empty bytes). An agreeing read now says so explicitly with a zero-bad
mapping carrying the same five keys a disagreeing read uses, mirroring
PRUNE-03's rule for the fingerprint.

EXCLUDED, and why: the per-byte diff primitive is never called on the
agreeing path (sha equality already proves the zero-mismatch fact); no
second divergence implementation exists anywhere in this module; the read
step's verdict is never flipped by a divergence result and never becomes
`marginal` (that gate is `test_read_step_disagreement_is_divergence_metric_not_marginal`,
byte-unchanged and green).

GATE that would redden if this regressed:
`test_read_step_agreement_records_a_zero_bad_divergence_mapping` (the
declared-cost test's stronger replacement),
`test_agreeing_and_diverging_divergence_mappings_share_the_same_key_set`
(a ragged shape), `test_a_single_run_and_an_all_empty_read_leave_divergence_none`
(the None-means-no-comparison property), and
`test_aggregate_cycle_results_preserves_a_zero_bad_divergence_mapping` (the
truthiness-filtered fold silently discarding a zero-bad mapping).
