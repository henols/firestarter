<objective>
Stop the report from recovering a number by reading its own prose, and stop two surfaces from
describing a write that never happened.

RPT-A5 makes the detected chip ID a structured `StepResult` field, fed by the value
`operator.check_eprom_id` already hands `_dispatch_id` and currently discards on a pass (D-23).
RPT-A1 then populates `chip_id_actual` on a passing id check rather than only on a mismatch, with
`_chip_id_fields` reading the field instead of parsing `reason.rsplit("0x", 1)`. The console row is
deliberately left exactly as the 2026-08-21 operator decision set it (D-10).

Beside them, the two folded residuals that share one predicate (D-21): a UV run whose slots are all
spent currently reads `blank-check`/`write`/`verify` as SKIPPED and `build_db_diff`'s fourth arm
proposes the same disposition a verified PASS proposes; and a run that spent a slot printed the slot
count it started with. One "did a write actually run" predicate, two call sites, both defects closed.

Purpose: both halves of this plan are the same failure — a surface asserting something the run did
not establish. The scrape is one reword away from silently returning `None`; the ladder arm is one
refused write away from proposing a chip for community-reported status on a run that wrote nothing.
Output: one additive `StepResult` field, one structural read, one shared predicate, two corrected
surfaces, a moved key-list pin, two todo dispositions and two evidence transcripts.

**One honesty ceiling this plan must state rather than paper over.** On a PASSING id check the
firmware's OK reply carries no id back, so the value `check_eprom_id` returns is the host's own
expected id echoed out of the command dict. `chip_id_actual` on a pass therefore equals
`chip_id_expected` and records the id the check was verified AGAINST — not an independent read-back.
RPT-A1 forbids a provenance key or qualifier string, so that distinction lives in the docstring,
which is where this project puts its reasoning.
</objective>
