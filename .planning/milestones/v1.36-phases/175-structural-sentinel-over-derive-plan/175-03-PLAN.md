<objective>
Build the frozen half of D-10's no-drop proof: a committed pin of every plan shape the shipped database
produces, its generator, and a drift test that regenerates and compares byte-for-byte.

D-10 requires both halves because neither alone is sufficient. The execution half plan 175-04 builds
cannot catch the change PRUNE-05 forbids: if a future phase prunes unsupported steps inside
`derive_plan`, both sides of `len(results) == len(plan.steps)` shrink together and alignment still
holds, while the six SDP ballast steps on 637 chips silently vanish from the dedup hash. This pin is
what reddens in that case.

The pin is at the `(op, supported)` grain — 8 chip-level families over the 16 distinct sequences — not
the op-only grain of 4. That is a deliberate strengthening of D-10 rather than a departure from it:
D-10's "4 distinct op-sequences" is a correct measurement of the op-only grain, and the finer grain
costs nothing in artifact size while catching an SDP `supported` flip on 40 chips, which is squarely
inside PRUNE-05's concern. D-11 makes the artifact route the right one: the whole point of the pin is
to make a generator change legible, and a per-chip family map produces a three-line diff naming the
three chips that moved instead of a one-line opaque hash change or 677 lines of churn.

Output: one generator, one committed artifact, one drift test, and one committed evidence transcript.

**Step token rendering.** A step renders as its op string, or as the op string followed by the literal
`(NA)` when `supported` is False. So a supported write renders `write` and an unsupported SDP lock
renders `sdp-lock(NA)`. This is the third of the three prototypes measured in `175-RESEARCH.md`
section F: 38,646 bytes, 940 lines, and a one-line diff when a single chip's shape moves.

**Family identity.** A family id is four hyphen-joined tokens derived from a chip's `full`-scope plan,
in this order:

1. `id` when the plan carries a supported `OP_ID` step, otherwise `noid`.
2. `nobc` when the plan carries no `OP_BLANK_CHECK` step at all; otherwise `bcpre` when the blank-check
   sits at a lower index than the first write-shaped step and `bcpost` when it sits at a higher one,
   with the literal `NA` appended when that blank-check is unsupported.
3. `nonerase` when the plan carries no `OP_ERASE` step; otherwise `erase`, or `eraseNA` when it is
   unsupported.
4. `nosdp` when the plan carries no `OP_SDP_LOCK` step; otherwise `sdp`, or `sdpNA` when it is
   unsupported.

This scheme was measured against the shipped database this planning session and is bijective on it:
exactly 8 distinct tokens, each mapping to exactly one distinct `(full, partial)` shape pair, and a
chip's `full` and `partial` plans always produce the same token because they differ only in `write`
versus `write-partial`. `validate` asserts that bijection rather than assuming it, so a database change
that made two shapes collide on one token fails loudly instead of silently merging them.

**`derive()`.** Build the corpus, compute each chip's family token from its `full` plan, group the
chips, and return a payload dict with exactly four top-level keys:

- `_generated_by` — the string `tools/measure_plan_shapes.py`. JSON has no comment syntax, so this key
  is the do-not-edit banner, exactly as the analog's is.
- `aggregate` — the six keys `rows`, `distinct_part_numbers`, `plans`, `distinct_shape_families`,
  `total_steps`, `unsupported_steps`, computed from the corpus and from `all_rows(REAL_DB)`.
- `shape_families` — a map from family id to an object with `chip_count`, `full` and `partial`, where
  the two lists are the rendered step-token sequences.
- `chips` — a map from `part_number` to family id, one entry per unique part number.

Key by `part_number`, not by database row: 746 rows collapse to 677 unique names because 65 part
numbers appear on more than one row and `derive_plan(name, db)` resolves them all to the same plan, so
a row-keyed artifact would carry 69 duplicate values that can never diverge. State that merge rule in
the docstring; it is the "two elements compare equal" case for this artifact and it resolves as a
merge, deliberately.

Raise `DerivationError` if the corpus is empty or the database cannot be read, which is the exit-2 path.

**`validate(payload)`.** Raise `ValidationError` when any of the following does not hold: `chips` is
non-empty; every value in `chips` is a key of `shape_families`; every family's `chip_count` equals the
number of `chips` entries pointing at it; the family ids are bijective with their `(full, partial)`
shape pairs; `aggregate["distinct_part_numbers"]` equals `len(chips)`;
`aggregate["plans"]` equals twice `len(chips)`; `aggregate["distinct_shape_families"]` equals
`len(shape_families)`; and `total_steps` and `unsupported_steps` recompute from the corpus. The
non-empty check first, because an empty `chips` map is the vacuous-pass shape this whole phase exists
to close.

**`render(payload)`.** One line: `json.dumps(payload, indent=2, sort_keys=True) + "\n"`. That single
line is what makes byte-identity a usable gate, and `sort_keys=True` is also what makes the output
order specified and stable — the chips map iterates in sorted `part_number` order and `shape_families`
in sorted family-id order, so two chips that compare equal on shape have a fixed relative position and
a regeneration produces a readable diff instead of reordering churn.

**`--planted-fault`.** An `argparse` choice among `chip-count-skew`, `orphan-family` and `empty-chips`,
defaulting to `None`, applied to the derived payload immediately BEFORE `validate` is called. This is
the override seam the drift test's fail-closed leg needs; the analog plants its fault through an
external `--issues` input, and this generator has no external input other than the shipped database,
which must not be mutated. The three faults: decrement one family's `chip_count` by one; repoint one
chip at a family id that is not a key of `shape_families`; and replace `chips` with an empty map. Each
must make `validate` raise, so `main` returns 1 and writes nothing. Give the flag an argparse `help=`
string saying it exists to prove the validator can fail and must never be used to produce a committed
artifact.

**`main()`.** Derive, then validate, then render, then either `--check` or write — validation strictly

that does not exist prints a `DRIFT:` line and returns 1; it must never return 0. On a successful write,
print an `OK:` line naming the path. End with `if __name__ == "__main__": sys.exit(main())`.
