<objective>
Machine-lock the DISP-01 no-auto-graduate invariant: add an AST audit checker
`tools/check_no_community_support_status_write.py` that proves NO code path writes a chip's
`support_status` as a result of parsing a community report, paired with an anti-hollow test that
plants a violation and confirms the gate goes red.

Per D-05, mirror the shipped SAFE-03 pattern precisely (`tools/check_devtest_orchestrator.py` +
`tests/test_check_devtest_orchestrator.py`): an AST scan (not substring grep), an env-override
fixture-injection seam, a fail-closed empty-scan guard, a PASS line that names every scanned file,
and a paired subprocess test with planted-violation fixtures. Per D-02, the report/parse path must
only READ `support_status` (via `db.get_eprom_config`), so ANY write of it there is a violation; the
sole allowed write locus stays the human-authored `tools/build_db.py` (which this checker does NOT
scan). Per Pitfall 1, `eprom_info.py:150` (a display-dict copy of a value read FROM the DB) must NOT
be flagged -- scope the scan targets to the report/parse modules only.

Purpose: A permanent, anti-hollow CI backstop (running via `pytest tests/`, NOT a new CI YAML step)
that fails the build if anyone ever wires a community report into a `support_status` write.
Output: `tools/check_no_community_support_status_write.py` + `tests/test_check_no_community_support_status_write.py`.
</objective>
