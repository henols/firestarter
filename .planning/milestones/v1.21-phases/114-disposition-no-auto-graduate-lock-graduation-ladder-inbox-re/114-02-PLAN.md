<objective>
Ship the INBOX-01 stdlib triage parser `tools/parse_devtest_issue.py`: it detects a community
`dev test` GitHub issue (via the `[dev test]` title marker + a fenced-JSON block carrying a
`schema_version`), extracts the embedded diagnostic report JSON, surfaces the current-vs-proposed
DB-diff, and counts matching `dedup_fingerprint`s across a set of issue bodies to report the
"N agreeing" count (GRAD-01's cross-report N>=2 signal, D-03).

Per D-04 the parser lives in `firestarter_app/tools/` (survives `gsd update`), is stdlib-only and
unit-testable via saved-JSON fixtures, targets `henols/firestarter_app`, and is INVOKED by the
maintainer / gsd-inbox during triage -- the installed `.claude/gsd-core/workflows/inbox.md` is NOT
edited. Per D-03 the N-agreeing count reuses the shipped `dedup_fingerprint` (read from each report's
embedded JSON), and MUST NOT be conflated with Phase-108's internal per-run N>=2 (Pitfall 5).

Purpose: Give the maintainer an actionable DB-diff + agreement count at triage time without
re-deriving it by hand -- while performing zero state writes (advisory only, DISP-01/D-01).
Output: `tools/parse_devtest_issue.py` + `tests/test_parse_devtest_issue.py`.
</objective>
