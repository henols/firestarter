<objective>
Machine-enforce `dev test`'s orchestrator-only contract (SAFE-03) with a genuinely-populated,
build-failing AST checker plus its mandatory anti-hollow test. Create
`tools/check_devtest_orchestrator.py` — mirroring the `tools/check_dispatch.py` tool SHAPE
(module structure, env-overridable path constant, buckets → per-bucket `FAIL:` →
`sys.exit(1)`, `PASS:` line + exit 0, `if __name__ == "__main__": main()`) but with a NEW
`ast.parse`-based visitor (no `import ast` tool exists in this codebase — the AST walk is fresh
per D-02). The checker scans `chip_test.py` and DENIES: VPP-set call sites, raw command-dict /
wire-JSON construction, and `force=True` / `--force` pass-through; it asserts the firmware is
untouched (host-only framing). Then create the paired pytest
`tests/test_check_devtest_orchestrator.py` (mirroring `tests/test_check_dispatch_invariants.py`)
that subprocess-invokes the checker and asserts exit 0 on the clean real source AND non-zero on
a deliberately-violating fixture injected via an env-override path — the anti-hollow contract
(D-03) and the real enforcement point (it runs under ci.yml's `Run pytest with coverage`).

Purpose: The operator wants the orchestrator-only contract machine-enforced with a real
negative test — a direct response to v1.12's hollow GATE-03 tech debt. A VPP-set / raw-command
/ --force call sneaking into the host orchestrator must fail the build.
Output: `tools/check_devtest_orchestrator.py` (AST checker) + `tests/test_check_devtest_orchestrator.py`
(clean-pass + planted-fail subprocess tests).
</objective>
