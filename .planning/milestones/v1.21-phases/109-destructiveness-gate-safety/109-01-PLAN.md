<objective>
Evolve `chip_test.py`'s `derive_plan()` from Phase 108's annotate-only contract to the
Phase 109 structural gate (SAFE-01, D-01): when `destructive=False` the executable `steps`
list literally OMITS write/erase, and those omitted steps are recorded on a new advisory
`Plan.locked_destructive` field that `run_plan` never touches. Additionally replace the
Phase-108 `_WRITE_REGION_START=0 / _WRITE_REGION_LENGTH=256` stand-in with the UV-EPROM
small-region cap (PATT-03): for UV-EPROM chips the write/verify pattern is generated over a
small, engine-capped, top-anchored high-address window `[mem_size - _UV_WRITE_REGION_LENGTH,
mem_size)`; non-UV chips keep the engine default region. The cap length is an engine module
constant — no DB field can widen it.

Purpose: A non-destructive run has no code path that could iterate a destructive op
(structural safety, not runtime skip), and an eraser-less UV tester can safely retry a tiny
top-of-address-space write that exercises the upper-address decode (the Bug-A read-path fault
surface).
Output: `Plan.locked_destructive` advisory field; the strip-when-non-destructive logic in
`derive_plan`; the `_UV_WRITE_REGION_LENGTH` engine constant + a per-chip UV region selector
feeding `generate_pattern`/`classify_fingerprint`; updated + new unit tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI invocation -> derive_plan destructive kwarg | the ONLY source of the destructive decision; must not read config/env |
| DB entry (untrusted / possibly malicious) -> engine write-region width | a bad DB entry must not be able to enlarge the UV write window |
| plan derivation (guard-bypassing) -> plan execution (guard-honoring) | destructive ops must not exist in a non-destructive plan's executable list |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-109-01 | Elevation of Privilege | a destructive op runs in a non-destructive invocation | high | mitigate | derive_plan structurally OMITS write/erase from Plan.steps when destructive=False; run_plan iterates only steps, never locked_destructive (SAFE-01, D-01) |
| T-109-02 | Tampering | malicious/misconfigured DB entry widens the UV write region | high | mitigate | UV region WIDTH is an engine module constant (_UV_WRITE_REGION_LENGTH); memory-size is a placement bound only; no DB field is read for width (PATT-03 SC4) |
| T-109-03 | Spoofing | destructive flag sourced from persistent state (config/env) | medium | mitigate | destructive read only from the derive_plan call kwarg; no os.environ/config read added (SAFE-01) |
| T-109-04 | Elevation of Privilege | engine sets VPP / builds raw command / passes --force | high | mitigate | no new VPP-set / wire dict / --force in chip_test.py; execution still composes existing operator methods via resolve_chip (SAFE-02 preserved; Plan 03 CI-enforces) |
| T-109-SC | Tampering | pip installs | n/a | accept | No package installs (edits an existing in-repo module); no legitimacy gate required |
