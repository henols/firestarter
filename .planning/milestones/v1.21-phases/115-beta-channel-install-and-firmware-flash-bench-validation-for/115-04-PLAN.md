<objective>
Make the Python-package channel publicly reachable: publish `firestarter 3.0.0b11`
to PyPI so a fresh-machine `pip install --pre firestarter` lands the beta. This is
the ONBOARD-01 Step-0 gate — the PyPI half of "both channels public".

Two-workflow path (RESEARCH Q1): beta-release.yml bumps __init__.py b10->b11 and
creates a GitHub release on the app repo but does NOT publish to PyPI; the PyPI
upload is a separate MANUAL `gh workflow run publish.yml -f tag=3.0.0b11` (the
PAT-created release suppresses the auto `release.published` trigger). Both
dispatches are IRREVERSIBLE and outward-facing (PyPI versions can never be
reused), so they sit behind an operator-authorization checkpoint (D-03).

The version-mode trap (RESEARCH Pitfall 1) is load-bearing: dispatching from a
non-beta ref WITHOUT `beta_version` makes update_version.py produce a STABLE
3.0.1. Every dispatch passes the explicit beta input, and a post-publish
assertion confirms the artifact is `3.0.0b11`, not a stable.

Purpose: This is what finally moves the milestone from PINNED-at-b10 to a
community-installable beta. Output: an external PyPI + GitHub release; no repo
file written here (the bump is a CI-side auto-commit on the app v1.21 branch).
</objective>
