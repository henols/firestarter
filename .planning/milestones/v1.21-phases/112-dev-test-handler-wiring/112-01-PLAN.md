<objective>
Add the optional `sampler` callback to the Phase-108 test engine so a caller can
capture VPP/VPE rail voltage tightly bracketing the destructive write pulse
(D-04). This is the single engine-side change of Phase 112 — the deferred
Phase-111 SC2 wiring (sampler around the write step) finally gets a call site.

Purpose: Make measured before/after write-step voltage capturable without the
engine ever importing hardware.py — the handler (plan 02) passes a thunk over
`hardware.sample_vpp_mv`/`sample_vpe_mv`. Keeps the engine sampler-agnostic so
`sampler=None` leaves every existing run_plan test green and bench-free.
Output: `run_plan(..., sampler=None)` and a threaded sampler hook firing around
`OP_WRITE` in `_dispatch_multi_run`, plus tests proving both behaviors.
</objective>

    Add a keyword-only `sampler: Any = None` parameter to `run_plan` (after `runs`),
    to `_run_step`, to `_dispatch_step`, and to `_dispatch_multi_run`, threading it
    down the existing `*, runs=runs` call chain (run_plan calls _run_step at :566;
    _run_step calls _dispatch_step at :666; _dispatch_step calls _dispatch_multi_run
    at :709). Default `None` at every level so all existing callers/tests are
    unaffected (D-04 — this is the load-bearing backward-compat guarantee).

    In `_dispatch_multi_run` (the OP_WRITE loop at :819-828): when `sampler is not
    None` AND `op == OP_WRITE`, invoke the sampler immediately BEFORE and
    immediately AFTER the `operator.write_eprom(name, eprom_data, tmp_source_path)`
    call. Pass the sampler a phase discriminator so the caller can tell before from
    after — use the string literals "before" and "after" (i.e. `sampler("before")`
    then the write call then `sampler("after")`). Do NOT sample around OP_VERIFY or
    OP_ERASE, and do NOT sample around the whole run loop — bracket each individual
    OP_WRITE run's write call (the rejected coarse-sampling alternative in D-04
    cannot distinguish a write droop from a read droop).

    Wrap each `sampler(...)` call so a sampler exception NEVER aborts the write step
    (Pitfall 1 — the sampler is a best-effort diagnostic, not part of the write
    contract): catch a broad Exception around the sampler call and swallow it (the
    engine records nothing extra; the report simply shows NOT_MEASURED). The
    operator.write_eprom line itself stays byte-identical — the sampler calls are
    added strictly around it, adding no new dispatch and no new operator method.

    HARD CONSTRAINT: do NOT add `import hardware` / `from firestarter.hardware ...`
    to chip_test.py. The sampler is an opaque callable the handler supplies (D-04
    decoupling). Update the run_plan docstring to document the new `sampler` param
    and the before/after-around-OP_WRITE contract.
