<objective>
Close the single remaining Phase 112 gap: SC2 / SWEEP-05. `derive_plan(chip, db, destructive=False)` currently returns 4 steps — `[id, read, blank-check, verify]` — because the `OP_VERIFY` step append at `chip_test.py:387` is unconditional (it sits below, but is not gated by, the `if destructive:` block that governs `OP_WRITE`). On a non-destructive run there is no preceding write, so `_dispatch_multi_run`'s `OP_VERIFY` branch compares a freshly-generated address-derived pattern against whatever the chip currently holds → near-certain mismatch → BAD verdict → `exit 1` on the tool's safest, most casual invocation path. ROADMAP Phase 112 SC2, ROADMAP Phase 109 SC1 (SWEEP-05), `112-02-PLAN.md`'s own `must_haves.truths`, and the shipped `--help` text all promise the non-destructive plan is exactly id + read + blank-check (3 steps).

Fix direction (a) is DECIDED (not open for reconsideration — two already-shipped locked SCs mandate it): gate the `OP_VERIFY` append behind `destructive` in `derive_plan`, mirroring `OP_WRITE`/`OP_ERASE`. This makes the non-destructive plan genuinely 3 steps (verify structurally absent, recorded on `locked_destructive`) and leaves the destructive plan byte-for-byte unchanged (write, verify, erase all present in the same order). Add non-mocked regression tests that would have caught this, repair the three existing tests that currently codify the buggy 4-step composition, and fold in the operator-recommended RPT-04 documentation-debt fix so REQUIREMENTS.md no longer describes the deleted interactive-provenance model.

Purpose: Restore the tool's default, safest invocation to a trustworthy `exit 0` on a healthy chip, matching every locked success criterion and the shipped `--help`. Add CI coverage so this class of regression cannot recur without a bench.
Output: A gated `OP_VERIFY` in `derive_plan`; a non-mocked composition + behavioral regression test set; a truthful RPT-04.
</objective>
