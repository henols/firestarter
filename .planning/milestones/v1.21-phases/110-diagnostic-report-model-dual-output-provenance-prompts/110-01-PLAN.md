<objective>
Build the core of the new host-side `diagnostic_report.py` module: the module
constants (`SCHEMA_VERSION`, `NOT_MEASURED`), the `AutoCapture` and
`TransportHealth` sub-dataclasses, and the aggregate `DiagnosticReport`
dataclass with its single-source dual render (`to_dict()` canonical dict →
`to_json_block()` fenced JSON AND `render()` rich table, both reading the same
dict). This plan delivers RPT-01 (one source, two renders, `schema_version`),
RPT-02 (auto-capture identity/ids/protocol/error_code/fingerprint), and
XPORT-01 (transport-health `"not measured"` honest fallback).

Purpose: This is the single source object every `dev test` run produces. It
composes already-built, already-tested Phase-108/109 dataclasses
(`Plan`/`StepResult`/`Fingerprint`/`BannerCounts`) plus the new sub-objects;
Phase 112 renders it, Phase 113 parses its JSON via `schema_version`. Getting
the single-source-render contract right here is what makes the two renders
provably never drift.

Output: `firestarter_app/firestarter/diagnostic_report.py` (partial — the
`Provenance` and `DbDiff` sub-objects arrive in plans 02 and 03) and the
bench-free test file `firestarter_app/tests/test_diagnostic_report.py`.
</objective>
