<objective>
Add the read-only advisory DB-diff to `diagnostic_report.py`: the `DbDiff`
dataclass and `build_db_diff(name, db, results)` transform, composed into
`DiagnosticReport`. This plan delivers RPT-05 — the report shows the chip's
`support_status` at test time beside a plainly-labeled, advisory
proposed-disposition string derived purely from the sweep verdicts, so a
maintainer can triage on the diff alone. It is read-only triage text by
construction: it never writes any `support_status` and never implements the
Phase-113/114 taxonomy state-machine.

Purpose: The DB-diff is the report-model-side expression of the milestone's
founding no-auto-graduate constraint (grounded in this project's own false-PASS
history — Rev-0 shield Bug A, ST-vs-Winbond chip-id mixup, AM27C020 write#1 60/64
vs write#2 0/64). The diff INFORMS a human; it never IS the decision. Proving
read-only by construction (a write-method-less mock DB) is what keeps the
Phase-114 human gate honest.

Output: `DbDiff`, `build_db_diff` added to
`firestarter_app/firestarter/diagnostic_report.py`; the sub-object composed into
`DiagnosticReport`; read-only DB-diff tests added to
`firestarter_app/tests/test_diagnostic_report.py`.
</objective>

Verdict → advisory string mapping (planner discretion within D-07's advisory/read-only constraint):
- any `BAD` in verdicts → `"suggests: community-fail signal (advisory — human triage required)"`.
- verdicts are a subset of {OK, NA, SKIPPED} and contain at least one OK → `"suggests: candidate for community-reported (advisory)"`.
- `marginal` present, or any StepResult fingerprint classification == "indeterminate" → `"inconclusive — needs N>=2 agreement (advisory)"`.
- otherwise → `"no change suggested (advisory)"`.
