<objective>
Add `derive_plan()` to `chip_test.py` (SWEEP-01): given any chip name in the database —
including chips the maintainer has never physically touched and chips whose `support_status`
would cause `resolve_chip` to refuse them — derive the exact ordered list of operations that
chip's protocol supports, strictly from the frozen DB fields `protocol` / `electrical-type` /
`FLAG_CAN_ERASE`, never re-invoking build-time `classify()`. Derivation reads the DB via
`get_eprom` + `convert_to_programmer` (which structurally bypasses the `resolve_chip`
support-status guard) and produces step descriptors; the guard-honoring execution path is
Plan 108-04's `run_plan`.

Purpose: Turn a chip DB entry into a technology-aware op list without touching hardware and
without the support-status guard, so the sweep can be planned for coverage-expansion chips.
Output: `derive_plan(name, db, *, destructive=False)`, the step-descriptor record shape, the
protocol→ops derivation rules, and derivation unit tests (bench-free).
</objective>
