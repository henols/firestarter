<objective>
Harden the Phase-112 `dev test` handler (SAFE-04): make `dev test <chip>` hard-fail
immediately -- exit 1, bare `Error: <chip>: not found in database`, no "did you mean" --
when the chip name is absent from the database (`app.db.get_eprom(chip)` empty), short-circuiting
BEFORE any hardware is energized or any report is rendered. A present-but-unsupported chip
(in the DB but refused by `resolve_chip` on support_status -- case B) is left UNCHANGED and
still runs the full sweep.

Today the handler proceeds for an absent chip: it energizes the board to read the hardware
revision, runs an empty plan, and renders a full-but-hollow diagnostic report for a chip that
does not exist. This is a 2-line guard plus two regression tests.

Purpose: fail fast + safe on a typo'd/unknown chip name, without breaking the entire point
of the community-validation command (proving support on chips the maintainer's DB refuses).
Output: the guard in `cli_handlers.py:dev_test`, and two tests in `test_dev_test_cmd.py`.
</objective>
