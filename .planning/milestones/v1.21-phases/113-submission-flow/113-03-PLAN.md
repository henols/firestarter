<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| tester's machine → public GitHub issue | the previewed/sent body must be the sanitized one; the local report path must not leak into the public body |
| CLI invocation → an actual submission | a submission must be an explicit, TTY-confirmed act — never a side effect of a bare/off-TTY run |
| large report → browser URL | must degrade (drop JSON) or hard-stop, never silently truncate at the server cap |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-113-02 | Information Disclosure | submit_report body + oversize note | high | mitigate | Sends the sanitize_dict output only; the oversize note prints saved_json_path.name (filename) not the full path |
| T-113-03 | Tampering | oversize URL measurement | medium | mitigate | Escalation keys on len(url.encode('utf-8')) of the fully-encoded URL; JSON dropped past 7.5 KB, hard-stop past ~8 KB (no open) |
| T-113-04 | Repudiation | submit_report TTY gate | high | mitigate | D-04 explicit confirm_fn preview on a TTY; off-TTY prints + returns (no browser/gh); requires the explicit --submit flag (Plan 04) |
| T-113-01 | Tampering / EoP | tier dispatch to submit_via_gh | high | mitigate | gh dispatch reuses the Plan-02 list-argv shell-out; no shell string constructed here |
| T-113-SC | Tampering (supply chain) | pip installs | low | accept | Zero package installs — stdlib + existing rich |
