<objective>
Eliminate the T-93-CANERASE 12V-on-5V hardware hazard (the real core of FIX-01) via
defense-in-depth: a host flag-derivation fix (do NOT send FLAG_CAN_ERASE for protocol 0x05)
AND a firmware guard (flash4 never asserts the 12V erase rail when handle->protocol == 0x05).

Purpose: A 5V-only W29C040 (protocol 0x05) currently receives FLAG_CAN_ERASE on the wire,
which routes firmware flash4_write_init → flash4_erase_execute → asserts
CTRL_VPP_REGULATOR_ENABLE | CTRL_VPP_VPE_DROP_ENABLE | CTRL_VPE_ENABLE = 12V boost on a 5V part
(SAFE-01-PREFLIGHT Item 2, RED/HIGH). flash4 auto-erases per page during the page-write, so the
separate 12V bulk erase is never needed. This fix is the SAFE-01 precondition for any Phase 95
bench write that runs without --skip-erase.

Output: protocol-gated host flag derivation, a firmware protocol==0x05 erase-skip guard, a host
wire test, and a native no-VPP test on the flash4 erase/write path. Dual-repo lockstep (host +
firmware committed inside their submodules, meta gitlink bumped).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host DB → wire JSON | host derives `flags`; a wrong flag value can route the firmware to a 12V rail on a 5V chip |
| wire JSON → firmware handler | hand-crafted/stale JSON can carry a hazardous flag the host would not emit |
| firmware → RURP hardware | flash4_erase_execute asserts the 12V VPP boost regulator (CTRL_VPP_REGULATOR_ENABLE) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-93-CANERASE | Tampering / DoS (hardware destruction) | convert_to_programmer + flash4_write_init/erase | mitigate | Host: omit FLAG_CAN_ERASE for algorithm==5 (Task 1). Firmware: skip flash4_erase_execute when handle->protocol==0x05 (Task 2). Defense-in-depth — both sides. |
| T-94-HANDCRAFT | Tampering | wire JSON | mitigate | Firmware guard (Task 2) keyed on handle->protocol==0x05 ensures a hand-crafted JSON carrying FLAG_CAN_ERASE still cannot 12V the 5V chip. |
| T-94-VHEURISTIC | (design defect) | firmware erase guard | mitigate | Guard keys on handle->protocol, NEVER on vpp_mv (W29C040 vpp_mv=12000 is a chip-ID datum); D-06 boundary enforced (Pitfall 3). |
| T-94-NOBYPASS | Elevation | chip_resolver.resolve_chip | accept | SAFE-01: no --force, no resolve bypass introduced; W29C040 stays on the `supported` path. No code change needed in this plan. |
</threat_model>
