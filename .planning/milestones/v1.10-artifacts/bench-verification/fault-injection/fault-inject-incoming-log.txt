## KEY FINDING (XACT-02 partial)
The host decoder DETECTS the mutated fw->host frame instantly (CRC mismatch logged) and RECOVERS
(next transfer byte-exact) — the safety-critical resync property holds. HOWEVER the operation-level
error surfaces as a ~2 s "ERROR: Timeout", NOT the sub-second fast-fail XACT-02 specifies. After
discarding the bad frame the host waits for the next expected response and hits its read timeout.
So "detect + recover" is PROVEN; "sub-second clean error, no 2 s cascade" is NOT met as-is.
