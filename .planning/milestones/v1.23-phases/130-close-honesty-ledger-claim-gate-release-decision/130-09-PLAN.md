## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| a dated capture -> a future reader | The note's value is that it records what was believed on a specific day. An in-place edit destroys that value silently, because a dated file that has been edited still looks dated. |
| the SUPERSEDED section -> a future scoping pass | A correction section that restates a superseded claim without its correction becomes a new stale source in the same file. |
| a section heading -> the checker's block model | A heading that looks labeled but carries no recognised token exempts nothing, and the resulting green would come from the needle not matching rather than from the label working. |

| T-130-39 | Tampering | the note's dated body | high | mitigate | Append-only, proven by a first-134-lines SHA-256 comparison and a diff criterion requiring zero removed lines. |
| T-130-40 | Repudiation / false assurance | the SUPERSEDED section itself | high | mitigate | Every row pairs the superseded claim with its corrected value and its evidence, so the section cannot be read as asserting the old figure. |

Widening the checker's token set to fit a heading is prohibited. |
