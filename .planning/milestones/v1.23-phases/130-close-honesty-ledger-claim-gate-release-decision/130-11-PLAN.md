<objective>
Write the honesty ledger — the single source of the permitted wording both release bodies must match, and
the first of the four contracted closing artifacts to land.

D-09's shape is the substance, not a layout preference: this milestone's defining fact is that **all of it
is software-only**, so the honest statement is the **strength gradient**. A green CMake configure and a
published release asset are not comparable proof, and a ledger organised one-row-per-requirement-category
would make adjacent rows read equally strong. Grouping by evidence tier is what stops that.

Two traps this plan must not walk into:
- **The self-reference trap.** `check_permitted_claims.py`'s `scan_text` matches phrase shape on a raw line
  with no quotation, citation or code-fence awareness. A ledger that quotes a forbidden phrase in order to
  say it is **not** claimed trips its own gate — this bit all six `125-0N-SUMMARY.md` files. v1.22 solved it
  by citing the forbidden claim by `file:line` and reproducing only the permitted wording.
- **The negated-honesty trap.** An honest phrasing such as *"nothing about the PY32F071 is
  silicon-verified"* carries both a py32 token and a forbidden phrase in one proximity window and **will**
  fire. The sanctioned response, recorded in the scanner's own comment, is to use the canonical caveat
  sentence — never to narrow the pattern set.

Purpose: pair every permitted claim with its explicit non-claim, at the right strength, before any of it
reaches a stranger.
Output: `130-LEDGER.md`, and the first observation of the claim gate's arming going live in the real
directory.

**Requirement ticking:** this plan ticks NO requirement ids.
</objective>
