<objective>
Write `firestarter/scripts/check_size_baseline.py` — the BASE-01 comparator that reads
`scripts/baseline/size_baseline.json` and a build/test log (or rebuilds), and exits non-zero on any
divergence — plus its paired planted-fixture pytest, and delete the superseded `check_uno_ram.sh`.

Purpose: D-01 makes the baseline an exit code rather than a table a human reads. This is the mechanism
Phase 124's MERGE-05 (Leonardo flash must not grow, Uno-class ≤ 64 B) and MERGE-06 (both native envs at
the recorded case and suite counts) are discharged by. Without it, the JSON from 123-01 is a document.

Output: one checker, one pytest, three planted log fixtures, one deleted shell script.

**This plan does not measure anything.** Every number it compares against comes from 123-01's committed
JSON, and every log it parses is a committed fixture. No `pio` invocation happens inside pytest — that
would pay a cold-toolchain cost in CI and make the test non-hermetic.
</objective>

    **Module docstring.** Follow the house convention: what the gate asserts, an `Exit codes:` block, and
    the anti-hollow contract paragraph naming its paired pytest (`tests/test_check_size_baseline.py`), its
    committed fixtures (`tests/fixtures/planted_size_baseline_*`), and its env seam by name — the same
    shape `check_no_log_in_sdp_window.py` lines 45-55 carries. Include an explicit non-claim: a green run
    proves the recorded numbers still hold for the log it was given; it does not prove the log came from
    a clean build, and `--rebuild` is the only mode that guarantees that.

    **Repo-root resolution.** Resolve the repo root from `Path(__file__).resolve().parent.parent` so the
    gate behaves identically regardless of the caller's cwd — mirroring `check_mypy_watermark.py` line 23.

    **Env seam.** `FIRESTARTER_SIZE_BASELINE = os.environ.get("FIRESTARTER_SIZE_BASELINE", <default>)`,
    read at module scope, defaulting to `<repo root>/scripts/baseline/size_baseline.json`. This is the
    single-target form (a default IS appropriate here, unlike the list-valued seam in 123-10), matching
    `check_no_log_in_sdp_window.py`'s `FIRESTARTER_SDP_SRC` idiom.

    **Regexes** — name them `SIZE_RE`, `CASES_RE`, `SUITE_RE` and anchor them exactly as RESEARCH
    specifies. `SIZE_RE` matches both the `RAM:` and `Flash:` lines in one pattern, multiline-anchored, and
    captures `kind`, `used` and `total` from the `(used N bytes from M bytes)` tail. `CASES_RE` matches the
    `N test cases: N succeeded` summary line. `SUITE_RE` matches per-suite SUMMARY rows and captures both
    the `native/avr/<suite>` path and the status word. Do not include the percentage or the bar-graph
    column in any pattern — they vary and are not the datum.

    **Parsing.** `parse_sizes(text)` returns a mapping keyed by `RAM` and `Flash` to `(used, total)`; if the
    set of found kinds is not exactly both, raise `ParseError` naming what was found. `parse_native(text)`
    returns `cases`, `succeeded`, `suites` and `all_passed`; raise `ParseError` if either the summary line
    or the per-suite rows are absent. `ParseError` is a module-level exception class, caught in `main` and
    converted to **exit 2** — never exit 1 and never exit 0.

    **Comparison.** `compare_avr(env, parsed, baseline)` asserts `flash_used` and `ram_used` equal the
    recorded values and that `flash_total`/`ram_total` are unchanged (a changed total means the board or
    framework moved, which is a finding, not a pass). `compare_native(env, parsed, baseline)` asserts all
    three of A-4's facts: `cases` equals the recorded value, `suites` equals the recorded value, AND every
    suite status is `PASSED`. Assert all three explicitly — a run with 17 suites all ERRORED still has 17
    suites, and that is precisely A-4's recorded failure mode.

    **CLI.** Accept `--baseline PATH` (overriding the seam), repeated `--avr-log ENV=PATH` and
    `--native-log ENV=PATH` arguments naming which env a log belongs to, and a `--rebuild` flag that shells
    `pio run -t clean -e <env>` + `pio run -e <env>` for the three AVR envs and `pio test -e <env>` for the
    two native envs and feeds their output to the same parsers. `--rebuild` satisfies D-01's literal
    "rebuilds and exits non-zero on violation"; the log-supplying mode is what makes the paired pytest
    hermetic and fast. Every subprocess invocation passes a **list**, never a shell string.

    **Output.** On success print a single `PASS:` line naming every env compared and its figures — the
    anti-skip discipline, so a run that compared nothing cannot look like a run that compared everything.
    On violation print `FAIL:` naming the env, the baseline value and the observed value, using the
    bucketed printer shape with a 20-row cap. On a parse failure print `ERROR:` to stderr naming the log
    path and what could not be found, and exit 2.

    **Never-vacuous guard.** If zero envs were compared (no logs supplied and `--rebuild` absent), print a
    `FAIL:` naming the never-vacuous condition and exit 1. A comparator that compares nothing must not
    print `PASS:`. Place this guard BEFORE the per-env loop, not after.

    Entry point: `if __name__ == "__main__": sys.exit(main(sys.argv[1:]))`.
