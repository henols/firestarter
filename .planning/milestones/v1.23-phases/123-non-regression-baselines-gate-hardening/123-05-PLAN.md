    **Arming (D-07).** `ARMED` is whether `<root>/platform/py32f071` is a directory, with `<root>` from the

    **Definition scan.** `DEFINE_RE` matches a preprocessor define of a macro named `RURP_` followed by
    upper-case, digits and underscores and ending in `_PROVISIONAL`, tolerating whitespace between `#` and
    `define`. Collect every match as (macro name, file, 1-indexed line). Scan `SCAN_DIRS` =
    `include/`, `src/`, `platform/`, `test/`, restricted to `SCAN_SUFFIXES` = `.h`, `.hpp`, `.c`, `.cpp`.
    The scan is repo-wide by design: the `RURP_` prefix is what bounds it, and restricting to the platform
    directory would miss a provisional flag introduced in shared code, which is the more dangerous case.
    State that in a comment.

    **Consumer search.** For each defined macro, search the same directory set for any other occurrence of
    the identical identifier, excluding the defining line itself and excluding any `#undef` of it (an
    `#undef` is not a consumer). `UNDEF_RE` exists for that exclusion. A macro with zero consumers is a
    violation naming the macro, its defining file and line, and stating what a consumer would look like —
    a message that tells the reader how to fix it, not merely that it is wrong.

    **Never-vacuous.** If the gate is armed and found zero `_PROVISIONAL` definitions at all, that is a
    **failure**, not a pass: the arming key says a port is present, and a port carrying a provisional pin
    map with no provisional flag means either the flag was renamed out of the pattern or the scan
    directories are wrong. Exit 1 with a message saying which. This is the single most important design
    decision in this checker and the reason arming reading (a) was chosen — an always-armed gate could not
    take this position.

    **Encoding and binary safety.** Read files as UTF-8 with errors replaced, so one stray byte in a source
    file cannot crash the gate into a traceback that a caller might misread. A decode problem that prevents
    scanning a file is exit 2, not a silent skip of that file.

    **Output.** `UNARMED:` + exit 0 when the port is absent. `PASS:` naming each macro found and its
    consumer count, so a run that scanned nothing cannot look like a run that scanned everything.
    `FAIL:` bucketed with a 20-row cap. `ERROR:` to stderr + exit 2 for scan and configuration failures.

    **Docstring** carries the `Exit codes:` block, the anti-hollow contract naming
    `tests/test_check_orphan_provisional.py` and the two fixture trees, and the explicit non-claim: a green
    run proves every provisional flag is *referenced* somewhere; it does not prove the reference is a
    working guard. Also record the measured fact that on the py32 branch
    `RURP_PY32F071_PINMAP_PROVISIONAL` has exactly one repo-wide hit, so this gate has a known first firing
    at Phase 124 — and note separately that the sibling `RURP_PY32F071_PINMAP_CONFIGURED` is `#define`d 1
    and tested with `#if !…` in the same header, making its `#error` structurally dead; that half is
    MERGE-04's problem, not this gate's, and this gate must not be widened to try to catch it.

| Boundary | Description |
|----------|-------------|
| firmware source text → gate verdict | The gate reads C/C++ source as text; an over-broad consumer rule (counting comments or `#undef`) makes it pass on the exact defect it targets |
| arming key → gate applicability | An armed tree with no definitions must fail, or a rename out of the pattern silently disarms the gate |
| py32 worktree → committed test | A test that read the gitignored worktree would pass here and fail in a fresh clone |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-123-05-01 | Repudiation | a consumer rule loose enough to count an `#undef` or a comment | high | mitigate | `UNDEF_RE` exclusion plus two dedicated `tmp_path` tests that replace the consumer with an `#undef` and with a comment and pin the outcome |
