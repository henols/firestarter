<objective>
Write `firestarter/scripts/check_build_warnings.py` — the BASE-06 gate that parses build output, holds
macro-redefinition warnings at exactly zero on the three AVR environments, and holds each native
environment at its recorded 360-warning watermark — plus the compiled-fixture pytest that proves both
halves against real compiler output.

Purpose: BASE-06's stated purpose is that *the next real warning is not buried*. The literal zero rule
alone does not deliver that on the native envs, where 360 warnings already are the burial; the watermark
does. The operator has locked RESEARCH's Option A: exact zero scoped to the three AVR envs, plus a
recorded watermark of 360 per native env in the same baseline JSON.

Output: one checker, one pytest, four fixtures (two compiled sources, two derived logs).

**The 360 is characterised pre-existing debt, not damage.** It comes from each native suite's own
`avr/pgmspace.h` host shim being redefined by ArduinoFake's — 8 macros × 45 translation units.
Remediating it would edit 17 suite directories, which breaches this phase's "no firmware code moves"
boundary; RESEARCH's Option B was considered and rejected. Say so in the checker, not only in the JSON.
</objective>

    narrow if a future toolchain changed its column reporting. `WARNING_LINE_RE` counts every diagnostic
    line carrying a `warning:` token, for the total-warning watermark.

    **Rules.** `check_env(env, text, baseline)` looks the env up in the baseline's `warnings` block. For
    an env under `warnings.avr`, assert `macro_redefinition == 0` using exact equality — the AVR envs are
    measured genuinely clean, so equality is strictly stronger than an inequality and is what
    `policy.avr_rule` records. For an env under `warnings.native`, compare the total warning count against
    `total_watermark`: above it is a `FAIL:` naming the count and the watermark; below it is an `INFO:`
    line telling the reader to lower the watermark in `size_baseline.json` (mirroring
    `check_mypy_watermark.py`) and is NOT a failure; equal is an `OK:`. Also assert the native
    `macro_redefinition` count does not exceed its recorded value, so a new redefinition on native fails
    even if some other warning disappeared and kept the total flat.

    **Unknown env is exit 2, not exit 0.** If a log is supplied for an env name absent from the baseline,
    that is a configuration error, not a pass.

    **CLI.** Repeated `--log ENV=PATH` arguments; `--baseline PATH` overriding the seam; a `--rebuild`
    flag that shells `pio run -t clean -e <env>` + `pio run -e <env>` for the AVR envs and
    `pio test -e <env>` for the native envs, feeding output to the same parser. Every subprocess
    invocation passes a **list**. `--rebuild` is the mode a human or a later workflow uses; the log mode
    is what keeps the paired pytest hermetic and fast.

    **Never-vacuous guard, placed BEFORE the per-env loop.** Zero envs examined prints a `FAIL:` naming
    the never-vacuous condition and exits 1. A warning gate that examined nothing must never print `PASS:`.

    **Output.** `PASS:` names every env examined with its counts and the rule applied. `FAIL:` uses the
    bucketed printer with a 20-row cap, naming each offending env, its observed count and the rule it
    broke. `ERROR:` goes to stderr for parse and configuration failures, with exit 2.

    Entry point: `if __name__ == "__main__": sys.exit(main(sys.argv[1:]))`.
