    **Parsing.** `SET_BLOCK_RE` extracts `set(<NAME> <body>)` blocks by name. `PATH_RE` extracts
    source-file paths from a block body, accepting the quoted and unquoted forms and the `${VAR}` prefixes.
    Parse **only** the three `set()` source lists. Do NOT parse `target_include_directories` — it mixes all
    three path idioms and a non-existent include directory is a warning-class problem, not the rename-damage
    class BASE-04 targets. Say that in a comment, so a later reader does not "complete" the gate by adding it.

    **Scope by variable, not by shape.** `ENFORCED_LISTS` is exactly `FIRESTARTER_COMMON_SOURCES` and
    `PY32_PLATFORM_SOURCES`. `EXEMPT_LISTS` is exactly `PY32_SDK_SOURCES`. Resolve

    `PY32_EXCLUDED` entry, and not an oversight. Conflating the two would let a real omission hide behind
    the exemption.

    **Unknown list is exit 2.** If the manifest contains a `set()` source list whose name is in neither
    `ENFORCED_LISTS` nor `EXEMPT_LISTS`, that is a configuration change the gate has not been taught about:
    exit 2 naming the list. Silently ignoring it would be a fail-open of exactly this phase's class.

    **Forward check.** Every path in an enforced list must resolve to an existing file. Each that does not
    is a violation naming the list, the literal manifest text and the resolved absolute path.

    **Reverse check and the allow-list.** Enumerate firmware sources under `src/` that a port would be
    expected to compile and report those NOT named in `FIRESTARTER_COMMON_SOURCES` unless they carry a
    `PY32_EXCLUDED` comment line in the manifest. `EXCLUDED_RE` matches a comment line of the form
    `PY32_EXCLUDED:` followed by a path, a `--` separator and a reason. **The reason is mandatory**: an
    entry whose reason is empty or absent is itself a violation, because an allow-list without reasons
    degrades into a silencer. Report allow-listed omissions on the `PASS:` line by name, so a reader sees
    what was deliberately skipped rather than having to diff the manifest.

    RESEARCH measured the deliberate-omission set against `beta` as `src/boards/uno_rurp_shield.cpp`,

    **Never-vacuous guard.** If the gate is armed and resolved zero enforced paths, that is a failure, not
    a pass: a manifest with an empty or unparsed source list must not look like a clean one.

    **Output.** `UNARMED:` + exit 0 when the port is absent. `PASS:` naming the manifest, the count of
    enforced paths resolved, the exempt list skipped and every allow-listed omission. `FAIL:` bucketed with
    a 20-row cap, naming each unresolved path with its list and its resolved absolute path. `ERROR:` to
    stderr + exit 2 for parse and configuration failures.
