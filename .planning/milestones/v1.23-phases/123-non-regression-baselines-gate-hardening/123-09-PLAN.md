<objective>
Write BASE-03's skip census and D-09's recurrence lint: a test that fails the suite when any reported skip
claims the firmware checkout is absent while `../firestarter/.git` exists or gives a reason not on a
committed allow-list, and a checker that stops the bare file-existence absence idiom from coming back.

Purpose: 123-07 and 123-08 removed the fail-open proxy. Nothing yet stops it returning. Which firmware
file a 52-commit merge renames cannot be predicted, and without the lint the idiom reappears in the next
gate someone writes. The census is the runtime half: even a correctly-keyed suite can acquire a new,
undocumented skip, and an allow-list of reasons is stable where a count is not.

Output: one census test, one lint checker, one paired lint test, one committed planted Python fixture.

**No pinned skip count.** This suite already has environment-dependent behaviour — the
no-programmer-found tests flip with a live board attached — so a count would be flaky and would get
bumped reflexively until it meant nothing.
</objective>

  <action>
    **`tools/check_no_exists_proxy.py`** — a stdlib-only checker that scans host test sources for the
    absence-proxy idiom and exits non-zero when it finds one.

    **What it forbids, stated precisely.** A module-level assignment whose value is a boolean negation of a
    path-existence call — the shape that made a firmware **rename** look like a firmware **absence**. Use
    the `ast` module, not a regex: an AST walk over module-level assignments looking for a unary `not` whose
    operand is a call to an `exists` attribute is precise, whereas a regex over source text would both miss
    reformatted variants and fire inside comments and docstrings. Also catch the compound form — a `not`
    over a boolean combination of such calls — because `test_dispatch_mirror.py` used exactly that shape.

    **What it must NOT forbid.** A path-existence check inside a function body used for ordinary control
    flow is fine; only the module-level absence-constant shape is the defect. State the boundary in the
    docstring with an example of each, so a future reader does not widen the lint into an unusable one.
    Verify the boundary against the real suite: the lint must exit 0 over the post-rekey `tests/` tree.

    **Env seam, list-valued, no default.** `FIRESTARTER_PROXY_LINT_TARGETS` read at module scope with
    `os.environ.get(...)` and **no default**, so `None` (absent) and `""` (present-but-empty) stay
    distinguishable. Resolve targets with the three-level precedence: positional argv wins, then the seam
    checked with `is not None` rather than truthiness, then an explicit non-pattern default list of the host
    `tests/*.py` modules. The `is not None` check is load-bearing: a truthiness check would make an
    explicitly empty value fall back to the real defaults, which is the vacuous pass this whole family of
    guards forbids.

    **Two guards, never-vacuous first.** Put the zero-targets guard ABOVE the missing-target guard —
    RESEARCH recommends this hoist over v1.22's ordering, because the missing-target guard is vacuously
    satisfied by an empty list and an intervening edit could let the empty case pass silently. Observable
    behaviour is identical; the ordering is the hardening.

    **Output.** `PASS:` naming every file scanned (the anti-skip line). `FAIL:` bucketed with a 20-row cap,
    naming the file, the line number and the offending constant, and stating the fix — key on the repo
    marker via `tests/fw_presence.py` instead. Three-way exit taxonomy: 0 pass, 1 violation, 2 tool or
    configuration error including a syntax error in a scanned file.

    **Docstring** carries the `Exit codes:` block, the anti-hollow contract naming
    `tests/test_check_no_exists_proxy.py` and `tests/fixtures/planted_no_exists_proxy.py` and the seam, and
    the explicit non-claim: a green run proves this specific idiom is absent from the scanned files; it does
    not prove no other fail-open shape exists.

    both the simple and the compound absence-proxy shapes, plus at least one *legitimate* in-function

    3. Planted compound proxy fails, naming the constant.
    4. The legitimate in-function check in the same fixture is NOT among the reported violations.
    5. Never-vacuous: the seam set to the empty string exits non-zero with the never-vacuous message and no
       `PASS:`.
    6. Fail-closed: a nonexistent target path exits non-zero naming the missing path.
    7. Precedence pin: the seam points at the violating fixture while positional argv names a clean file,

    8. Syntax error in a scanned file exits **2**, not 1 and not 0.
