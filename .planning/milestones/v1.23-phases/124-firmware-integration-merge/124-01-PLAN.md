    `ScanError(Exception)` -> exit 2, caught only at the entry point.

    Logic:
    1. Resolve the range root; run every `git` call as `subprocess.run` with **list argv**, `cwd` set to
       the range root, `capture_output=True`, `text=True`. Never `shell=True`.
    2. `git rev-parse --verify <fork>^{commit}` — a fork ref that does not resolve is `ScanError` (exit 2).
    3. `git merge-base --is-ancestor <fork> HEAD` — a non-ancestor fork is `ScanError` (exit 2). This is
       the guard that stops the whole gate passing vacuously against a wrong or moved fork point.
    4. `git rev-list <fork>..HEAD` — the FULL set, not `--first-parent`. Record `len(commits)` as
       `scanned`.
    5. Never-vacuous guard: `scanned == 0` prints a `FAIL:` line naming the fork and HEAD and returns 1.
       Copy `check_orphan_provisional.py:335-345`'s message shape and its explanatory clause.
    6. Per commit: for each marker, `git cat-file -e <commit>:<marker>` (returncode 0 means present).
       If any marker is present, `git rev-parse -q --verify <commit>:{PY32_KEY}` — a non-zero return
       means the py32 stack is absent in that tree, which is a violation. Record the violation as
       `f"{commit} carries {marker} without {PY32_KEY}/"`.
    7. Also count `carrying` = number of commits in the range that carry at least one marker.
    8. Output: on violations, `FAIL: N violation(s) in <fork>..HEAD:` then up to 20 violation lines then
       the `... and M more` tail. On clean,
       `PASS: {scanned} commit(s) scanned in <fork>..HEAD, {carrying} carrying a portability marker, 0 violations`
       — the PASS line NAMES what it found so a run that scanned nothing cannot visually resemble a
       clean run.
    9. `main()` returns 0/1; `ScanError` -> print `ERROR: ...` to **stderr** and return 2. `if __name__
       == "__main__":` wraps `sys.exit(main())` in the same try/except, mirroring the analog.

    Do not implement a `--fix`, a `--first-parent` flag, or any bypass. There is no argv.
