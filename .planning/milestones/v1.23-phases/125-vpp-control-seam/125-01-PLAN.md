<objective>
Land the VPP control capability seam as an atomic change: two new hand-authored firmware files
plus the two lines in the ARM build manifest that declare them, with every existing gate and
both pinned native suites proven still green at their exact recorded counts.

Purpose: this is the phase's entire production-visible change. VPP-01 requires the two files be
hand-authored with nothing cherry-picked from PR #45; D-06/D-07 require the capability macro's
value to come from the compiler or the build system and never from the header that tests it;
D-12 requires the ARM manifest to name the new source. RESEARCH C-1 measured that adding an

141 cases / 141 succeeded to 17 suites / 0 succeeded — the operator resolved this as **Option A:
`include/rurp_shield.h` is not touched at all**. This plan therefore fires that tripwire in the
same task that authors the files, rather than deferring it.

`firestarter/platform/py32f071/CMakeLists.txt`, in one firmware commit; plus the recorded
