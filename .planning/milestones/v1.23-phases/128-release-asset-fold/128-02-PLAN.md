<objective>
Create the repo's first composite action, `.github/actions/build-py32f071/action.yml`,
holding the single definition of the PY32F071 toolchain install, cmake configure and cmake
build — and emitting the two values the release job will later assert on.

Purpose: D-06. Two workflows must run the identical ARM build, and one of the two copies is
`continue-on-error`, so any drift between duplicated steps would fail **silently** by
construction. A composite action makes the drift impossible instead of detectable. The
choice of *composite* over *reusable workflow* is REL-01's mechanism: a composite action's
steps run inside the calling job, so the ARM image is built in the same job (and therefore
after the same version bump) as the AVR images.

**Scope boundary — this plan does NOT close REL-01 or REL-04.** It supplies the mechanism
only. REL-01 additionally needs the ordered call site in `beta-build.yml` (128-05) and the
image-carries-the-version assertion (128-06), plus run A evidence (128-10). REL-04
additionally needs the CMake rename (128-03), the workflow assertions (128-06), and the
cross-repo binding (128-09). Do not tick REL-01 or REL-04 in REQUIREMENTS.md from this plan.

Output: one new directory and one new file, first of their kind in this repo.
</objective>
