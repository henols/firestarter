The operator's 2026-06-30/07-01 schematic study RESOLVED the CR-01 fork: a
DISTINCT PGM line exists on Rev 2 — it is the RW line, CTRL_READ_WRITE (physical
bit 0x40), which drives socket pin 31 on BOTH Rev 0/1 and Rev 2. RC-1's original
"pin 31 modeled as A18" was a misdiagnosis; pin 31 is the /PGM (=/WE) write
strobe. 98-01 correctly took pin 31 OFF the address bus but left it UNASSIGNED —
the residual gap. This plan assigns pin 31 to the RW line via rw-pin:[31],
mirroring the working DIP32_SST39SF040 flash entry, so the firmware's existing
rw_line mechanism drives pin 31 = /PGM at VIL for the whole write pulse. On Rev 2
CTRL_READ_WRITE (0x40) is in the passthrough mask of
rurp_map_ctrl_reg_for_hardware_revision — it survives the remap DISTINCT from
P1/VPP (0x08), so the fix is physically real on Rev 2 (unlike 98-02's inert
CTRL_ADDRESS_LINE_18 clear, reverted in the firmware plan 98-04).

Purpose: deliver the corrected host bus-config so the firmware (98-04) can rely
on the existing rw_line mechanism instead of the aliased-bit clear; harden the
diff_db classifier and build_db diagnostics; extract the shared size boundary.
Output: rw-pin:[31] on DIP32_27C020, regenerated DB, hardened diff_db/build_db,
named boundary constant, green host CI on py3.11.
