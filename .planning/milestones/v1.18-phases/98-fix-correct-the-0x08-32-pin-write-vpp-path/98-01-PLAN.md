the address bus (where `DIP32_STD` models it as A18 / bus line 22) so the firmware
bus-config no longer drives pin 31 from an address bit, while keeping VPP on pin 1.

HIGH, not the program-active VIL the AM27C020 needs, so the held-LOW PGM-assert is
Plan 02's firmware-belt responsibility. This plan's pin-31 job is precisely "take
it off the address bus." Assign the new pinout via `build_db.py` ONLY to the `0x08`
≤256K class (AM27C020) so the 512K AM27C040 (524288) and 1M AM27C080 (1048576) —
which legitimately use pin 31 = A18 — stay structurally excluded on `DIP32_STD`.
That structural exclusion is the host half of the D-04 alias-collision guard.
Regenerate the DB, re-baseline, and prove the change is scoped via `diff_db.py` +
`check_dispatch.py` on py3.11.

RESOLVED: existing protocol/pins/mem_size/bus_config fields suffice).
