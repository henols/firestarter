<objective>
Extend the ledger self-consistency gate (`check_ledger.py`) and its unit tests so a
v1.18-native `0x08` graduation can be recorded PASS, WITHOUT forcing the fabricated
`evidence.p90_writecycle_sha_matches_v115: true` flag that the current D-09 constraint
requires. AM27C020 has a v1.15 *read* baseline but NO v1.15 *write* baseline (its v1.15
write was the 0-bits failure) — its v1.18 write is a *first-ever successful write*, proven
by written-image-SHA == read-back-SHA on the Phase-98 fixed firmware, not by "matches v1.15".

This is the single required code task of Phase 99 (99-RESEARCH.md §Schema Tension /
Pitfall 2). It is branch-neutral: it makes the gate *capable* of passing a graduated `0x08`
row; whether that row is actually written PASS or stays a documented defect is decided by
the bench outcome in plan 99-04.

Purpose: Without this extension the graduated ledger row would either fail the gate or force
a dishonest v1.15-write-baseline claim. ROADMAP Success Criterion #3 requires the ledger to
be self-consistent at 0 contradictions after graduation.
Output: An extended, still-green gate + its extended test suite + an extended valid fixture.
</objective>
