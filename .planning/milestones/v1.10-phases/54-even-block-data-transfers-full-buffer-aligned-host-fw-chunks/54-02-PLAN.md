<objective>
Implement the host half of EVEN-01: parse the firmware-advertised 4th identity-string field
`<maxchunk>` into `SerialCommunicator.firmware_max_chunk` (V5 integer-only parse with an
`.isdigit()` guard, mirroring the existing `fw_fields[2]` pattern), and replace the body of
`_calculate_buffer_size()` so it returns `firmware_max_chunk` directly — eliminating the
`fw_buf - 2` arithmetic and any hardcoded per-board constant (D-03/D-04). Per D-05 (beta
lockstep, no mixed-version interop), raise `FirmwareOutdatedError` when the field is absent —
no graceful `buf-2` degrade. Add a new `test_even_block.py` suite and UPDATE the two existing
test classes that assert the old `-2` behavior (they will otherwise raise after the change).

Purpose: The host now sizes write/verify chunks to the full even buffer the firmware reports
(512/1024), so a 65536-byte image divides into whole blocks with no 256-byte remainder write
(EVEN-01 SC2). Covers both the write and verify legs (D-06 — both go through
`_main_phase_send_data` with `buf_size` from `_calculate_buffer_size()`).

Output: Host code that consumes `<maxchunk>` dynamically, a green host test suite, and a
pinned no-remainder regression.
</objective>
