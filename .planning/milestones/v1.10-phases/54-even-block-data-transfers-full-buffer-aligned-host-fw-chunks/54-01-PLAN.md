<objective>
Implement the Candidate A (data-path NUL-skip) mechanism in the firmware: parameterize the
COBS decoder's overflow cap so the MAIN/write-receive path can commit a full `DATA_BUFFER_SIZE`
payload (512 Uno / 1024 Leonardo) while the CMD_IDLE/JSON-command path keeps its
`DATA_BUFFER_SIZE - 1` NUL-slot reservation (CR-01). Extend the `FW_VERSION` identity string
with a 4th `<maxchunk>` field so the host can advertise-derive the chunk size with no
arithmetic (D-04). Update every Unity test suite that calls the decoder (the signature change
breaks compilation otherwise) and add the new MAIN-path / CMD_IDLE-overflow / no-remainder
test cases.

Purpose: Removes the last `-2` byte handicap on host→fw write/verify chunks at its firmware
source — the `DATA_BUFFER_SIZE - 1` cap — without any RAM growth (per D-01 RESEARCH lock:
Candidate A, zero-growth). This is the firmware half of EVEN-01; the host half (Plan 02)
consumes the advertised `<maxchunk>`.

Output: A firmware build where the MAIN-path decoder accepts a full even buffer block, the
identity string advertises `<maxchunk>`, and all four native suites are green.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host→fw serial (data path) | Untrusted serial bytes cross into the COBS decoder; the decoder writes into `data_buffer` |
| host→fw serial (command path) | JSON command bytes cross into the same decoder, then `data_buffer` is read as a C string by jsmn |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-54-01 | Tampering / DoS | `rurp_communication_read_data` PUSH overflow guard | mitigate | Guard still fires at `out >= cap` and returns -2 with `_drain_to_delimiter()`; `cap` is a compile-time constant (`DATA_BUFFER_SIZE` or `DATA_BUFFER_SIZE - 1`) at both call sites — no runtime user input controls the bound. The MAIN-path cap of `DATA_BUFFER_SIZE` fits `data_buffer[DATA_BUFFER_SIZE]` exactly (last committed index = cap - 1; CRC8 held in `last_byte` lookahead, never written). |
| T-54-02 | Elevation / memory-safety | CMD_IDLE path `data_buffer[n] = '\0'` | mitigate | CMD_IDLE cap stays `DATA_BUFFER_SIZE - 1`, so `n <= DATA_BUFFER_SIZE - 1` and `data_buffer[n]` is in-bounds — CR-01 reservation preserved. Pinned by the new `test_cmd_idle_overflow_at_full_block` Unity test (Pitfall 1 regression guard). |
| T-54-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed in this phase (pure source edits to existing files); no package-manager surface. |

No HIGH-severity threats: `cap` is compile-time, the overflow guard is unchanged in behavior, and no new attack surface is added (RESEARCH § Security Domain).
