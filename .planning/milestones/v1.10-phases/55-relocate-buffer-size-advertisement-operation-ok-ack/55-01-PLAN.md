<objective>
Make the catalog the source of truth for the relocated buffer-size advertisement, and
lay down the failing host tests that pin the CAP-01 safe-default contract before any
implementation lands.

This plan is the dual-repo linchpin (SC2/SC5): editing `messages.toml`, regenerating
`messages.h` (firmware) and `messages.py` (host) via the sync script, and asserting
byte-identity across all three copies. Both downstream repo plans (02 firmware, 03 host)
consume the regenerated catalog, so this plan runs first and alone in Wave 1.

The MSG_OK_READY param is declared `bytes` (NOT `u16`) — the enabling decision for the
"graceful 512 default" goal. `u16` sets `param_bytes=2`, which makes the host shape-check
REJECT acks from un-advertising (old) firmware, dropping the ack and timing out. `bytes`
sets `param_bytes=-1` (variable-length), skipping the shape check so old-firmware acks
pass through; the host extracts the u16 only when the param body is exactly 2 bytes.

Purpose: Establish the wire contract + RED gate so firmware and host can implement against
a single, regenerated, byte-identical catalog.
Output: Edited `messages.toml` (3 copies), regenerated `messages.h`/`messages.py`, and a
failing `TestCapSafeDefault` host test class plus a flipped existing test.
</objective>
