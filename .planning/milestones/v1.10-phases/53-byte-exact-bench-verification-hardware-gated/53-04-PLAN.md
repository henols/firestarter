<objective>
XACT-02 / SC2: Prove resync under fault injection in BOTH directions, on real hardware. Operator-witnessed.

The locked posture is bounded-desync + fail-fast (Phase 50 D-01): on a CRC8/COBS failure the receiver
discards bytes to the next 0x00 and surfaces a clean error IMMEDIATELY (no 2 s timeout cascade); the
FOLLOWING frame re-anchors. "Recovers within one packet" means the NEXT frame decodes clean — NOT that
the corrupted frame is salvaged. Because the len_u16 prefix was removed in Phase 50, the only corruptible
structural elements are the CRC8 byte and the 0x00 delimiter (D-02).

Two legs (D-01):
1. host->fw (primary, on the wire): the host deliberately corrupts an outgoing command frame, exercising
   the FIRMWARE decoder. Assert: (a) a clean error surfaces sub-second (NOT a 2 s cascade), and (b) the
   very next framed transfer on the SAME open connection completes byte-exact (D-03).
2. fw->host (secondary): the host receive-path hook (FaultInjectingSerialCommunicator) mutates a received
   frame once, exercising the HOST decoder resync. Same assertion.

Fault forms (D-02): corrupted CRC8 byte AND dropped 0x00 delimiter. A spurious extra mid-frame 0x00 is
optional. Recording the measured time-to-error number is optional but recommended as concrete evidence
the 2 s cascade is gone (D-03 discretion).

This phase adds NO transport behavior — it drives the 53-02 dev fault-inject harness against the merged
hardened firmware + host.
Output: both-direction fault-injection logs under .planning/v1.10/bench-verification/fault-injection/.
</objective>
