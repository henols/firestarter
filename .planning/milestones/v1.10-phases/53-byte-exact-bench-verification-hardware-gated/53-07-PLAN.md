<objective>
XACT-01 / SC1 (corpus extension): Prove the hardened COBS transport is byte-exact on a clean board
**against the ACTUALLY-SHIPPED post-54/55 contract** — operator-witnessed.

Plans 53-03..06 (authored 2026-06-02) prove SHA-256 byte-identity but predate Phase 54 (EVEN-01,
full even-block host->fw transfers, no buffer-2 remainder) and Phase 55 (CAP-01, ack-sourced buffer-size
advertisement on MSG_OK_READY; FW_VERSION reverted to pure `<version>:<board>`; safe-512 default when the
ack is absent — reversing Phase 54 D-05). The byte-exact corpus must witness the *shipped* contract so
serial is ruled out as a read-bug confounder on the real hardware that runs today, not on the Phase 49-52
contract the 53-CONTEXT scope-fence (written Jun 2, before 54/55) froze on.

This plan adds **NO transport behavior** — it only VERIFIES the already-shipped 54/55 contract on the
bench. It captures, as durable bench artifacts on the clean Rev 2.0-target boards:
  1. **Pure identity string** — raw wire shows `OK: FW: <version>:<board>` with NO `:<buf>:<maxchunk>`
     suffix (Phase 55 SC1; operator captures the raw line verbatim).
  2. **Ack-sourced chunk sizing** — the host sizes data chunks from the MSG_OK_READY u16 ack, NOT the
     identity string: Leonardo -> 1024-byte chunks (64 chunks for a 64KB chip), Uno -> 512-byte chunks
     (128 chunks). Capture the `DATA: <chunk: N bytes>` evidence + the chunk COUNT.
  3. **Even-block / no-remainder byte-identity** — a full 65536-byte chip READ (N=5 self-consistent) and
     a write->read-back cycle (N=5, read-back SHA == source SHA) complete with whole full-buffer blocks
     and no odd final remainder chunk (65536 % 1024 == 0, 65536 % 512 == 0), reusing the 53-02
     `dev consistency-check` / `dev write-cycle` harness exactly as 53-03 does.
  4. **Safe-512 graceful default** — recorded as ALREADY-COVERED-IN-SOFTWARE (Phase 55 TestCapSafeDefault
     3/3 + `_calculate_buffer_size` returns 512 when the ack is absent). NOT a new bench leg: re-flashing
     OLD un-advertising firmware to bench this path contradicts the chip-out/sideload + hardened-only
     constraints and risks the bench. No bench step requiring old firmware is invented.

Targets shield Rev 2.0 (D-07) — the operator MUST confirm the actual silkscreen rev at session time
because the EEPROM hw_revision byte cannot distinguish revs.

Purpose: extend the byte-exact corpus to the actually-shipped (post-54/55) transport contract so the
resumed v1.9 RCA inherits a corpus that matches the firmware/host on the bench.
Output: raw identity + chunk-count evidence + per-run/per-cycle binaries + SHA tables + software-covered
safe-512 note under .planning/v1.10/bench-verification/even-block-ack/.
</objective>
