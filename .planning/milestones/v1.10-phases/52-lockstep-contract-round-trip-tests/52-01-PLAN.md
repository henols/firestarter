<objective>
Author the canonical golden-vector catalog (`frame-vectors.toml`) and its deterministic
codegen (`codegen_vectors.py`), vendor both byte-identical into BOTH sub-repos, generate the
C++ PROGMEM header (firmware) and Python module (host), and wire a vector-catalog validity
check + codegen drift gate into each repo's CI.

This is the foundation Wave for Phase 52: the shared frozen golden vectors are the cross-repo
anchor (D-01). Both the firmware Unity suite (Plan 02) and the host pytest suite (Plan 03)
assert against the SAME frozen bytes produced here. The contract is FROZEN — every byte value
is a hardcoded literal in the catalog, never computed at codegen time (RESEARCH anti-pattern:
soft-coding vector bytes defeats the "frozen" requirement).

Purpose: Establish the single source of truth for the COBS frame contract (LOCK-01) and the
tool-enforced drift gate per repo (LOCK-02), mirroring the proven v1.2 message-catalog
mechanism (D-04).
Output: `frame-vectors.toml` + `codegen_vectors.py` (both repos, byte-identical) + generated
`frame_vectors.h` / `frame_vectors.py` + CI drift-gate steps in both workflows.
</objective>

catalog, its codegen, generated artifacts, and CI steps. The only real residual risk is
silent contract/catalog drift (Tampering), which the drift gates and paired-commit discipline
manage.
