## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host → firmware (serial line) | Untrusted bytes cross here. After Phase 51, the host actively emits delimiter bytes on the host→fw command channel; the firmware decodes a frame and (must) verify its integrity before parsing JSON. |
| decoded frame → JSON parser (firmware) | The decoded payload reaches `json_parser` inside the firmware. The current `{`-peek path performs NO integrity check before parsing. |

## STRIDE Threat Register

This is a documentation/analysis phase — no code is written, so no high-severity code-level
threat is introduced here. The threat surface is the *frame contract itself*: the contract must
record the mitigation Phase 51 inherits.

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-49-01 | Tampering / Spoofing | decoded frame → JSON parser (firmware) | mitigate | ADR frame contract MUST mandate: firmware verifies CRC8 BEFORE handing the decoded frame to the JSON parser (V5 Input Validation). A frame that passes the delimiter check but fails CRC8 is discarded before reaching the JSON parser. This is a Phase 51 design constraint the Phase 49 contract records (Task 3). |
| T-49-02 | Tampering | host→fw 0x00 delimiter timing (COBS path) | mitigate / accept | Resolved by the SAFE-01 static proof (Task 1): either prove the host cannot deliver a 0x00 frame-boundary byte during the programmer↔communication mode-transition window (mitigate, COBS eligible), or select SLIP 0xC0 per D-04 (accept the COBS risk by avoiding it entirely). |
| T-49-03 | Denial of Service | corrupted byte → 2 s timeout desync cascade | transfer | The framing layer's auto-resync (Phase 50, FRAME-02) bounds corruption to one frame; out of scope for Phase 49 but the contract's delimiter-based design is what enables it. Transferred to Phase 50. |

No package-manager installs occur in this phase (no npm/pip/cargo). The Package Legitimacy Gate
is not applicable.
</threat_model>
