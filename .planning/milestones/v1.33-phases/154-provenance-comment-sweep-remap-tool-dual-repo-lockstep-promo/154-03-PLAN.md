<objective>
Build the planted-violation controls SWEEP-07 requires, and prove them RED (and,
for the fail-open control, GREEN) **before** the sweep touches anything.

Purpose: source-scanning gates in this project fail OPEN, so a green run proves
nothing. Research demonstrated the sharp edge: with two comment lines inserted above
the real declaration spelling the initializer form with the *correct* bytes, and the
real `EEPROM_SDP_ENABLE` terminal byte corrupted from `0xA0` (SDP lock) to `0x10`
(**chip erase**), `test_sdp_table_parity.py` reported `5 passed` — all five legs,
including the one whose whole job is to prove the unlock terminal byte differs from
the erase terminal byte, were disarmed by comment text. The comment-blind mechanism
is reachable by exactly the operation D-01 prescribes.

Scope clarification, stated explicitly per Ruling A so this does not read as scope
creep: **SWEEP-07's new test code IS in scope.** CONTEXT.md `<domain>`'s "comment
text only" describes edits to **existing** source. SWEEP-07 is a settled requirement
that *mandates* these controls, and a control is test infrastructure, not a
behaviour change. Research recorded this as finding F6 — a wording gap, not a
conflict. The four fixtures and five legs land in the `firestarter_app` sub-repo
where the gates live, and fold into that repo's single D-11 commit.

Output: four committed fixtures, three new legs in `test_sdp_table_parity.py`, two
new legs in `test_dispatch_mirror.py`, and the recorded RED-before proof.
</objective>
