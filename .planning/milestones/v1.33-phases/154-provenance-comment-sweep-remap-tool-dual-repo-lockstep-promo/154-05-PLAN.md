<objective>
Build the citation-remap tool and prove its two named hazards — range shrinking and
idempotency — against synthetic diffs. **Build it; do not apply it.**

Purpose: per D-01 and D-10 the remap runs **exactly once**, in Phase 159, over the
composite pre-154 to post-158 diff. D-10 records why the roadmap's sweep-last
fallback was declined: 723 citations would otherwise be remapped twice, 41% of that
rework caused by four added `#include` lines, and composing four successive mappings
would create a range-shrinking hazard that one composite mapping avoids. So this
phase's job is a tool whose whole proof burden rests on its unit test, because
nothing else exercises it.

Output: `remap_citations.py`, `test_remap_citations.py`, and five committed synthetic
fixtures — including the chained-map pair that is the only fixture shape capable of
catching a non-idempotent implementation.
</objective>

  <action>
Create `.planning/v1.33/tools/remap_citations.py`.

Mechanism — `difflib.SequenceMatcher(None, old_lines, new_lines, autojunk=False).get_opcodes()`
over line lists. Stdlib only; no third-party dependency and no package manifest, consistent
with the `.planning/v1.16/ledger/tools/` precedent D-09 names. Two choices are load-bearing
and must be stated in the module docstring: `autojunk=False` is **required** (the default
heuristic treats any element occurring in more than 1% of a sequence of at least 200 items as
junk, so over a 900-line C++ file ubiquitous lines like a lone closing brace or a blank line
get auto-junked and silently excluded from `equal` runs — the single easiest way to get a
subtly wrong map); and `replace` is treated as non-surviving exactly like `delete`, because a
reflowed comment is a `replace` and its recorded `source_text` can no longer match at the
destination, so such a citation cannot round-trip and must be flagged `retarget=True` rather
than assigned a number the oracle will then reject. Mapping `replace` positionally would
manufacture false green.

Pre-sweep side — the "old" content must come from git (`git show <pre-sweep-sha>:<path>`),
not from the current working tree, because by the time the remap runs in Phase 159 the old
content exists nowhere on disk. Take the pre-sweep sha as an argument. Keep `git diff -U0` as
a **cross-check in the unit test only**, asserting the difflib map agrees with the unified-hunk
map on one real file; do not use it as the production mechanism.

Range handling — map the two endpoints **independently**. The shrink property is not a special
case needing its own branch: it falls out automatically, because the accumulated deletion
offset differs at the two endpoints. Handle `colon_list` elements as independent point
citations with forward clamping, not as a range — research measured 194 of them in the
swept-targeting corpus and the requirements do not mention the variant.

Idempotency — make the REMAP-02 oracle the write predicate, in the three-check order above.
This single design gives SWEEP-11's idempotency, REMAP-02's oracle and REMAP-05's
resumability at once: a partially-applied remap resumes correctly because already-correct
records are recognised as fixed points rather than re-shifted. Never key a rewrite off "is
this integer in the map's domain" — that is the naive form research measured drifting
`:15` to `:10` to `:8` to `:6` on successive runs.

Retarget records — a `retarget: true` record's new target is **hand-chosen**; the clamp is a
starting suggestion for the human, not the answer. The tool must never write a `retarget`
record's clamp as if it were a result; emit it for review and count it.

CLI — introduce the argparse shape rather than copying it; the named analog has no CLI at all
and is configured entirely by `os.environ.get` path constants derived from `__file__` with
four hard-coded `..` segments. Required positional `repo_root`; required `--manifest` (an
absent manifest is an error, exit 2, never a derived default); `--pre-sweep-sha`; `--apply`
(default dry-run). Assert `_HERE` is absent from the module. Any path the tool builds must be
checked against the `firestarter` name-collision trap that `firestarter_app/tests/scan_paths.py`
documents — one `..` from a `tools/` directory lands in the app's own Python package, two reach
the sibling firmware repo — which is exactly why the resolution rule excludes fixtures and why
this tool imports `citation_paths.py` instead of resolving paths itself.

Exit codes, house 0/1/2 contract in the module docstring: 0 = all records processed, oracle
holds; 1 = a real violation (an oracle assertion failed, or a record's `target_file_resolved`
does not exist); 2 = infrastructure (manifest unloadable, manifest parsed to zero records, an
empty input set). Exit 2 is the honest code for SWEEP-11's non-zero-on-empty-input. The PASS
line reports counts: records examined, records rewritten, records already at their fixed
point, records flagged `retarget`.

Path safety (ASVS V5/V12): resolved targets must stay inside the explicit `repo_root`; reject
`..` traversal and absolute paths; write atomically (temp plus rename); never follow a symlink
out of the tree.
