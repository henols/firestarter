<objective>
Close both measured DEDUP-03 blind spots before the refactor lands, so the new assertions are
regression evidence for plans 03 and 04 rather than a description of them.

Purpose: research planted four severity transpositions and measured exactly what catches each.
The VPP over-voltage `response_code` is caught only by `native_loop_v131`, which no CI workflow
runs. The chip-ID `response_code` is caught in CI. But the **under-voltage severity pairing is
caught by nothing** and the **chip-ID message id is caught by nothing** -- and since every
`LOG_{WARN,ERROR}_ID_BYTES` macro is the same alias of `LOG_ID_BYTES`, severity rides entirely
in the id, so a transposed chip-ID id ships an ERROR-severity frame on a `--force` run and a
WARNING frame on a refusal, invisible to all 172 CI cases. DEDUP-03 says a green golden trace
does not satisfy it. This plan is what does.

Output: an under-voltage severity-pairing case (or pair of cases) in `test_vpp_eprom_v131`,
and both chip-ID fork directions pinned by message id inside the existing
`test_case7_mismatching_chip_id_with_force_warns`, each proven RED against a planted
transposition and GREEN against the real tree.
</objective>
