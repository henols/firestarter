<objective>
Make the firmware heap-free, and close the unchecked-allocation dereference that the
allocation carried, in one atomic commit that also updates the two native suites the change
compiler-forces.

Purpose: `mem_util_blank_check` allocated four bytes -- a struct holding one 32-bit value --
to carry a saved address across two calls of one function, and it was the allocator's only
caller anywhere in the image. That single call site linked a 586 B allocator and five
allocator globals, and it wrote through the allocation result with no NULL test on a part
with under 473 B of shared heap-and-stack headroom. A file-scope static in the owning
translation unit has the identical lifetime -- the firmware runs strictly one command at a
time -- with none of that.

Output: the static, the removed struct member, and both native suites updated in ONE commit,
because removing the member without the test edits is a hard compile error that drops 45
cases and turns both native CI legs red.
</objective>
