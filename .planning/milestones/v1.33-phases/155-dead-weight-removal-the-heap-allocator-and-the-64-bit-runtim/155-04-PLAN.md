## The coverage ceiling, carried in the mandated terms

`src/boards/rurp_common.cpp` is compiled by NO native environment. All six native envs share
one `build_src_filter`, admitting `src/proms/`, `boards/rurp_serial_utils.cpp`,
`json_parser.c` and `operation_utils.cpp` and nothing else -- and widening it was measured
unavailable, because the translation unit is gated on the three `ARDUINO_AVR_*` board macros
and its body writes `ADMUX` and `ADCSRA`. In native builds `rurp_read_voltage_mv` is a stub
returning 0, with four suites overriding it, so every native VPP suite exercises the CONSUMER
against a mock.

Therefore, and in exactly these terms: `rurp_read_voltage_mv` is **proven by a committed
host-side numerical oracle over a stated input grid, bound to the shipped C by a
source-contract scan; no native and no bench coverage exists.** This phase creates neither.

The named residual risk, stated and NOT presented as covered: avr-gcc miscompiling the
32-bit multiply/divide. No artefact of this phase mitigates it. It is mitigated only by that
being AVR's most-exercised path and by this change REDUCING codegen complexity, since it
deletes the 64-bit path rather than adding one.

## The hollow-gate tension, answered rather than dodged

`tests/test_config_storage_dualslot.py`'s docstring explicitly rejects "an independent fake
reimplementation of the algorithm living only in this test", naming it as the hollow-gate
shape Phases 118 and 124 each had to unwind. DEAD-04's numerical oracle IS an independent
reimplementation, so a reviewer will raise this. Two answers, both required in this plan's
output:

1. **The source-contract scan is the answer, and it is not optional.** It converts "a copy
   behaves" into "the shipped text is the formula the copy models". The model's guard
   constants and scale factor live in ONE place and are asserted to appear verbatim in the
   comment-stripped shipped C, so a change to either side turns CI leg 3 red.
2. **`test_config_storage_dualslot.py`'s own option -- host-compile the real C -- is
   unavailable here.** That module compiles the shipped C by explicit path with `gcc`. It
   cannot work for this file: `src/boards/rurp_common.cpp` wraps its entire body in a
   preprocessor test of the three `ARDUINO_AVR_*` board macros with an unsupported-board
   `#error` fall-through, and the body calls `analogRead`, `analogReference` and
   `rurp_get_config` and writes AVR ADC registers. Forcing a board macro drags in AVR
   register headers and makes the register mocking the thing under test.

State both in the oracle's module docstring, citing `test_config_storage_dualslot.py` by
name. A reviewer must find the tension already answered, not absent.
