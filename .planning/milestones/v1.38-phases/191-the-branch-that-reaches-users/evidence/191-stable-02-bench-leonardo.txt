FINDING: the no-flag path could not complete a version handshake against the
board's actual firmware (3.0.0b22). This is the plan's own named contingency
("The stable host is 951 commits older than the firmware currently on the
board, so a version handshake against 3.0.0b22 may not succeed"), not a
retry-until-clean workaround -- the same result on two consecutive attempts
is recorded here rather than smoothed over. Because no current version could
be read at all, the predicted version-parse warning and downgrade prompt
(which only fire when BOTH a current and a latest version resolve) never had
an opportunity to appear; that is a consequence of the handshake failing
outright, not a defect introduced by this leg.
