<objective>
Build the instrument before the outward-facing act, and prove it can go red.

This plan writes `191-stable-install-fixture.sh` — a clean-room `pip install firestarter` into a
scratch venv, driven all the way through the installed package's own firmware API to a live GitHub
release asset — and then runs it against the stable that is published **today** (`2.0.7`, which still
carries the bare slug). That run must **fail** on the redirect assertion. That failure is the point:
it is machine proof that the assertion this phase's entire STABLE-02 claim rests on is capable of
detecting the pre-change state, taken before anything irreversible happens.

Purpose: per D-07, `redirects == 0` is the whole substance of the fixture. The two endpoints return
byte-identical bodies, so a green resolve, a version string and an asset URL are all compatible with
a stale install. Per D-08 the transcript must also prove *which artefact* was exercised, because an
editable install in a sibling tree can shadow the PyPI package and this project has hit that trap.
Output: the fixture script, and the fail-first baseline transcript that licenses trusting it.

**Tracer.** This is the phase's vertical slice: one path through every layer the phase touches —
venv creation, index resolution, package provenance, the installed constant, the GitHub Releases API,
the redirect contract, the asset download, and explicit-path cleanup — wired end to end and verified
before any expansion task prepares a branch or reaches an operator gate.
</objective>
