Captured by: `git clone`, `git checkout`, `git config`, `git submodule update`, `git -C firestarter
<cmd>`, all run inside a directory created by `mktemp -d`. Observables read with `/usr/bin/grep`
and shell builtins, never PATH `grep` (ugrep, honours .gitignore, silently under-scans).

This transcript demonstrates D-16's second case: a clone that already exists in a maintained,
post-rename state, then travels back to a pre-rename ref. `.git/config` records a `git config
submodule.firestarter.url` override for `firestarter_fw` -- the standing state of a maintained
clone, and what /workspaces itself carries -- and the question is whether that override survives
and is honoured after checking out `v1.35`, whose own `.gitmodules` still names the old slug.

is exactly why the divergence has to be forced by checking out an old ref.

DIVERGENCE: .gitmodules at this HEAD names the OLD slug (git@github.com:henols/firestarter.git).
.git/config's override still names the NEW one (git@github.com:henols/firestarter_fw.git). The
checkout changed .gitmodules underneath the override and left the override itself untouched. When
the two disagree, .git/config wins -- READING 1 already showed that when they agree, nothing
observable changes and a reader looking only at that reading cannot tell whether the override was in
force at all. This reading is the one that proves it was.
