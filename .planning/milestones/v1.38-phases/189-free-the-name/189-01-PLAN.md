<objective>
Halt at the one act in Phase 189 that an agent may not perform — the GitHub rename of
`henols/firestarter` to `henols/firestarter_fw` (D-11, milestone D-7) — and, on resume, prove the
rename landed in the only way that distinguishes a live redirect from a re-occupied slug: by
asserting on both `.id` and `.full_name` (D-12).

This plan carries no implementation. It is deliberately a gate plan: every later plan in the phase
depends on it, and none of them may assume the rename happened. The phase's leading production
task — the tracer — is Task 1 of plan `189-02`, which runs only after this gate clears.

Purpose: the rename is the milestone's single naming act and its redirect is what keeps 27
stargazers, 11 forks and every installed CLI working. It is also the one step whose undo cost rises
the moment the old slug is claimed, which D-1 defers out of v1.38 entirely.
Output: a committed identity transcript under the phase directory that a verifier can re-read, and a
phase that is unblocked for plans 02, 03 and 04.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator -> GitHub web UI | The rename is applied by a human in a browser; nothing in the repository constrains what else that page can change. |
| agent -> GitHub REST surface | Read-only identity queries cross an authenticated boundary using the machine's `gh` token. |
| old slug -> renamed repository | GitHub's rename redirect is an implicit, externally-owned indirection that every existing clone and installed CLI depends on. |
