<objective>
Land the same one-line `.gitmodules` change on the meta repository's `main` branch, through the only
route branch protection allows, and write down which branch of RENAME-02 is satisfied how.

Per D-07 this is its own pull request inside Phase 189. `main` is the meta repository's GitHub
default branch, so it is the copy of the submodule URL that the front door hands to anyone who clicks
Clone; leaving it stale would leave the milestone's own findability motive half-served. Keeping it
independent of Phase 191's `firestarter_app` `main` work preserves the roadmap's stated invariant
that every phase depends on 189 and on nothing else of each other.

Per D-08 the third branch, `beta`, is close-carried and is stated as such here, so a verifier reading
the milestone mid-flight does not record an incomplete requirement where there is a deliberate
routing decision.

Purpose: RENAME-02 names two branches and this phase can only reach one of them by pull request and
the other by the milestone close. Both facts belong in writing.
Output: a prepared local branch, an operator-merged pull request, and a branch-disposition record.
</objective>

Branch-protection facts this plan is built on, from `CLAUDE.md` and the v1.35 close-procedure note:

- `main` is protected in all three repositories: pull request required, no direct push, no
  force-push, no deletion, and `current_user_can_bypass` is `never` — so **no person** can bypass it,
  the operator included. A pull request is the only route.
- This project's close targets `beta`, not `main` (`git.base_branch` is `beta`).
- The pull-request route into a protected `main` is already demonstrated: `prom#54`,
  `firestarter#58` and `firestarter_app#57` all merged into a protected `main` on 2026-09-02, after
  the rulesets were created.
- `origin/main` of the meta repository carries the same byte-identical `.gitmodules` as `beta` — two
  sections, TAB-indented, absolute SSH URLs. Measured 2026-09-13; do not re-measure.

Why the change is prepared in a scratch worktree rather than by checking out `main` here: the primary
working tree is on `v1.38-repository-rename` with the `firestarter` submodule moved, and switching
that tree to a `main`-based branch would leave the submodule directory disagreeing with the index for
no benefit. A worktree touches nothing in the primary tree, and leaving submodules uninitialised
there is harmless because the only file edited is `.gitmodules` itself.

Keep the scratch worktree outside `/workspaces`, for the same reason the RENAME-03 fixture's clone
lives outside it: a later `git clean -Xdf` aimed at this tree must not be able to take it.

Follow the repository's standing commit-attribution convention for every commit this plan makes.
