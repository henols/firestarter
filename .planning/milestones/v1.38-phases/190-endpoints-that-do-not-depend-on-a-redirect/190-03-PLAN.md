<objective>
Stop `fw` from reporting success after checking nothing. When the release endpoint cannot be
resolved and a board has been identified, the command must say which endpoint it tried, for which
board, and exit 1.

Purpose: this is the update path's half of URL-04 and of ROADMAP criterion 3. Today the plain
version check — the most common invocation of all — reaches the end of `manage_firmware_update` and
returns `True` with no message at all, so an operator can ship a board on stale firmware believing it
current. It is also the second half of what makes a mistaken retarget visible: a slug that resolves
nowhere currently produces a clean exit 0.
Output: one guard, one small helper, and a test module covering the branch that was never covered.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `api.github.com` -> `manage_firmware_update` | The release metadata crossing here decides whether the operator is told their firmware is current. An absent answer is currently indistinguishable from a satisfactory one. |
| `manage_firmware_update` -> the process exit code | The method's boolean is the only signal an operator or a future script has about whether the check happened at all. |
| the channel selection -> the endpoint named in the message | If the message names an endpoint the invocation did not use, the diagnostic actively misleads. |
