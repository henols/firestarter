<environment_notes>
PATH `grep` in this devcontainer is ugrep and honours `.gitignore`, so it silently under-scans. Meta-repo
readings use the absolute `/usr/bin/grep`. Sub-repository readings use `git grep`, which is git's own
matcher over tracked files and is unaffected by both problems — that is the form phases 189 and 190 used
and the form this plan reuses verbatim.

Sub-repository commands run with `git -C /workspaces/firestarter` and `git -C /workspaces/firestarter_app`,
never with a bare `git` at the meta root, because each submodule is a separate repository.

`/usr/bin/grep -c` exits 1 when the count is 0, so a leg that legitimately expects 0 carries a trailing
`|| true` and is judged on its printed number, not its exit status.

`.planning/config.json` is dirty in the working tree before this plan starts, from a pre-existing
GSD-verb defect that pruned two `planning.sub_repos` entries. It is not this phase's work and must not
be staged or committed here.
</environment_notes>
