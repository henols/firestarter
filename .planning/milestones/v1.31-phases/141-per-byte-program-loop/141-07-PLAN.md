<objective>
Prove the loop's cadence, its skip rules and its energy cap natively, using plan 141-03's harness.

The oracles, and the reason each is chosen over the obvious alternative:

- **Per-byte pulse count comes from the read-back model's own counter, not from the strobe stream.**
  `loop_readback_reads(addr)` is a `uint16_t` and is **uncapped**, whereas both the strobe recorder and the
  timing recorder cap at **512** entries. A 100-pulse `0x0B` case emits well over 512 strobes, so any
  assertion built on `strobe_count()` would silently truncate. The mapping is fixed and must be stated in
  every case that uses it: the loop reads **first** (LOOP-06's skip check) and then pulses, so
  `converge_after = N` means the byte matches on read `N+1`, i.e. after exactly **N pulses**, and
  `loop_readback_reads(addr) == 1 + pulses`. A `0xFF`-skipped byte is never read at all, so its count is
  **0**. This read-count-to-pulse-count shift by one is the single easiest place for this suite to be
  silently off by one.
- **Fixed width comes from the timing stream's value set**, which is only usable on **small** blocks where
  neither recorder overflows. With `read_settling_us` and `read_strobe_us` both zero, the complete set of
  `TIMING_KIND_DELAY_US` values a block can emit is `{3, pulse_delay}` — 3 us for `memory_set_data`'s
  pre-pulse settle at `memory.cpp:327` and the verify read's default strobe, and `pulse_delay` for the
  pulse itself. Any third value is growth, which is exactly what LOOP-01 forbids. Choose a `pulse_delay`
  that is not 3 so the two are distinguishable.
- **Which limit tripped comes from the logged-id capture**, filtered by id, because
  `LOG_DEBUG_ID_SUB` frames share the array.

Case sizing is a hard constraint, not a style preference: cases that assert on the strobe or timing
stream use blocks of at most 4 bytes with at most 4 pulses each and assert `strobe_overflowed() == 0` and
`timing_overflowed() == 0` as a soundness precondition; the long energy-cap cases assert **only** on read
counts, `response_code` and the logged id, and must **not** assert either overflow flag is clear.

| read-back model index → per-byte identity | a mis-derived index would collapse several bytes onto one counter and make every pulse count wrong in the same direction |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-141-CAP | Repudiation | 512-entry recorder caps on 100-plus-pulse cases | mitigate | Long cases assert only on the uncapped `uint16_t` read counter, `response_code` and the logged id, and explicitly do not assert the overflow flags are clear; small cases assert both flags are 0 as a soundness precondition |
| T-141-OFFBY1 | Repudiation | read-count-to-pulse-count mapping | mitigate | Every case states the mapping (`reads == 1 + pulses`, `0xFF` bytes get 0 reads) and the 500 us case names 101 pulses as the off-by-one signature in its failure message |
