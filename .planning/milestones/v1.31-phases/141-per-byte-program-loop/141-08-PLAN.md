<objective>
Prove the four requirements whose oracles are specialist: the overprogram arithmetic (which no shipped row
can reach), the hard-fail exit (whose obvious test is vacuous), the delay ceiling (whose claim is global),
and the high-voltage discipline across an A16 boundary on a 32-pin part (the highest-risk seam in the new
suite).

Four traps this plan exists to avoid, each recorded:

1. **LOOP-03 is unreachable through the table.** All three shipped rows have `overprogram_factor = 0`
   (`eprom_params.cpp:46-48`), so per **D-08** the proof is a **pure function** —
   `eprom_overprogram_us` — tested directly at `factor = 3`, plus a separate assertion that the live rows
   emit zero extra pulses (already covered by plan 141-07's case 5). A test-only injection seam into the
   production table was explicitly rejected.
2. **The LOOP-05 disable assertion is vacuous if scoped wrongly.** `command_done()`
   (`firestarter.cpp:162-171`) writes `CONTROL_REGISTER = 0x00` on **every** command exit, so a test that
   drives the whole command and then asserts "no high-voltage route is active" passes even if
   `eprom_write_execute` disables nothing. The assertion must be scoped to the CONTROL strobes
   `eprom_write_execute` itself emits — which is exactly why `drive_loop_write` calls
   `firestarter_operation_main` directly.
3. **LOOP-08's premise as originally stated is false.** A verify read **does** write the control register:
   `memory_get_data` reaches `mem_util_set_address`, which calls
   `rurp_write_to_register(CONTROL_REGISTER, ...)` **unconditionally** on every byte
   (`memory.cpp:189`). VPE survives because `CTRL_VPE_ENABLE` is in the **unconditional** preserve mask
   (`memory.cpp:161`) and because `rurp_write_to_register` **elides** the write when the recomputed value
   equals the cached one (`rurp_register_utils.h:39-42`). Assert route-bit **presence in every emitted
   value**, never "no CONTROL strobe during a verify read" and never "exactly one CONTROL strobe per
   block".
4. **The DIP32 seam needs a block the existing fixture cannot express.** `LOOP_BUS_CONFIG_0x08` is the
   tree's only 32-pin config, and the trace fixture drives it at address 0 with a 4-byte block. D-09's test
   needs a block crossing `0x00FFFF` to `0x010000`, which is exactly why plan 141-03's read-back model
   keys on the **full 16-bit latched address** rather than the trace suite's `& 0x03` index.

Purpose: complete the phase's behavioural proof, including the two claims that are global rather than
per-case.
