<objective>
Replace `eprom_write_execute`'s block-level mismatch-mask retry loop with a per-byte pulse-to-verify
loop driven by Phase 140's PROGMEM table, add D-03's pre-flight refusal to `configure_eprom`, and route
the erase pulse through LOOP-07's helper so its global claim is true.

This is the **only** plan that touches `src/proms/eprom.cpp` — deliberately, because that file's blob
SHA is pinned by `tests/golden/protocol_branch_inventory.json`, so every commit moving it breaks three
of the D-13 gate's seven tests until the golden is re-derived (plan 141-05). One plan means the gate
goes RED once, for one reason.

Decisions implemented, by name: **D-01** (when the next full-width pulse would cross the energy cap,
emit that pulse then stop); **D-02** (`accumulated = N * pulse_delay`, pulse widths only — the 3 us
pre-pulse settle, the verify strobe and address setup are not counted); **D-03** (refuse an
over-cap pulse pre-flight, before any HV); **D-04** (the two budget limits emit the two distinct IDs
plan 141-01 authored); **D-05** (reuse `handle->firestarter_set_data` / `_get_data`, no EPROM-local
duplicate write path); **D-06** (the erase pulse is the second over-ceiling-capable site);
**D-07** (`org_delay` save-and-restore for the overprogram pulse, not a width parameter);
**D-08** (prove the overprogram duration through a pure function, since `overprogram_factor` is 0 on all
three shipped rows); **D-09** (the 32-pin drop-bit case is an explicit commented branch keyed on
`handle->pins >= 32`, never on `protocol`); **D-12** (no chunking, no progress emission, but the cursor
stays shaped so a chunk bound can later be substituted without touching the loop body).

**Two dispositions decided here rather than deferred:**

1. **`verify_mode` is CONSUMED.** It is a shipped column no D-NN covers: `0x07`/`0x08` ship
   `VERIFY_PER_PULSE_PLUS_FINAL`, `0x0B` ships `VERIFY_PER_PULSE`, and `firestarter/CLAUDE.md` already
   documents the resulting behaviour. After the byte loop finishes a block, when
   `verify_mode == VERIFY_PER_PULSE_PLUS_FINAL` the loop runs **one final full-block read-and-compare
   pass** mirroring `memory_verify_execute` (`memory.cpp:333-353`): same `MSG_ERR_VERIFY` id, same
   5-byte payload, same `response_code` plus early return. This preserves an existing property (the
   pre-change loop's last action was always a full verify pass) and avoids a second shipped column with
   no consumer.
2. **`overprogram_cap_us == 0` yields 0 us — no overprogram pulse.** `eprom_params.h:51` defines the
   column as the clamp in `min(3 x overprogram_factor x pulse, cap)`, and `min(product, 0)` is 0. It is
   also the fail-safe reading: "0 means no clamp" would emit a multi-second VPE pulse at
   `factor = 3, N = 25, pulse = 65535`.

Output: one rewritten write path, one pre-flight refusal, one pure arithmetic function, one shared
failure reporter, one rerouted erase pulse.
