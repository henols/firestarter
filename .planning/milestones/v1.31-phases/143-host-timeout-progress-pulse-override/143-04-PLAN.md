## The three things this plan must get right

**1. The budget is used verbatim (D-09).** The firmware already padded it — twice the pulse-only worst case
plus two seconds, with a one-second floor, because only the firmware knows `delay(500)`, the final verify
pass, the per-pulse settle and the serial time. The host applies **no multiplier of its own**. A budget
that is too tight causes a spurious timeout on a **working** write; that is a false failure on real silicon
and is strictly worse than a generous ceiling.

**2. Absent means safe default, never a refusal (D-10).** Recorded fallback: **120 s**, derived not picked.
`143-RESEARCH.md` sharpened the derivation: 120 s covers **every reachable `0x0B` width** (that protocol's
per-byte bound can never exceed 99 998 us, and `99998 x 1024 = 102.4 s`) and every shipped-database
`0x07`/`0x08` width (25 x 1000 us x 1024 B = 25.6 s). Precedent to cite in the code: `_calculate_buffer_size`
— Phase 54's `FirmwareOutdatedError` was **reversed** into a safe default, which is the standing argument
against refusing the write.

Record the residual non-claim, **corrected** from D-10's wording: D-10 names "a mid-milestone v1.31 build"
as the realistic absent-advertisement case, but BF-1 showed such a build **cannot connect at all**, so it
never reaches the fallback. The reachable cases are (a) a **released `beta`** firmware, which has CAP-02 but
not CAP-03 — the genuinely realistic one — and (b) a v1.31 build after plan 143-03's CAP-02 port but before
its CAP-03 append. On those, a `--pulse-us` above roughly `120 / (25 x 1024)` = **4687 us** on a Leonardo
(or **9375 us** on an Uno, 2x more forgiving because its buffer is 512 B) can still time out. Named, not
fixed.

`SerialCommunicator.get_response` and assert the `timeout` it receives. That tests exactly what HOST-01

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| firmware-advertised budget to the host's wait duration | an untrusted integer from the wire decides how long the host will block; too large wedges the CLI, too small produces a false failure on a working write |
| the caller's programmer dict to the wire | mutating it in place would silently change every later chip in a batch loop |
| the shared `_main_phase_send_data` to its two callers | a change that reaches `verify_eprom` would hand a multi-minute timeout to an operation that must still report a dead board in ten seconds |
| a test's fake transport to wall-clock time | a test that exercises a real timeout path takes as long as the timeout, so CI cost becomes the oracle's cost |
