Land CAP-03's **host half**: a third length-discriminated field on `MSG_OK_READY`'s existing

## Why this needs no catalog edit and no codegen run (D-08, verified)

`MSG_OK_READY`'s generated catalog entry is `params=(("bytes","hex"),)` with `param_bytes=-1`, and **both**
prior extensions were decoded purely by length in this same override: CAP-01's 2-byte buffer size, and
CAP-02's `[hw_rev u8][ver_len u8][ver bytes]` tail. Neither required a `messages.toml` change. CAP-03 is
therefore "firmware appends bytes, host reads further into `params_bytes`": **zero `messages.toml` diff,
zero codegen run, zero new message id, zero `constants.py` parity churn**. `firestarter/messages.py` is
**codegen-generated and must never be hand-edited** — a CI leg (codegen drift gate) enforces that, and this
plan does not need to.

## BF-1 reconciliation — what this plan can and cannot claim

`143-RESEARCH.md` §BF-1 established, with four independent oracles, that **CAP-02's firmware half is not in
the v1.31 firmware branch**: it emits a bare 2-byte `MSG_OK_READY`, the branch forked one commit before
firmware PR #49 landed CAP-02 on `origin/beta`, and this app branch's `_probe_port` raises
`FirmwareOutdatedError` when the ack carries no identity (asserted on purpose by
`tests/test_fwguard.py::test_absent_identity_refuses`). Consequences this plan must honour and must not
paper over:

- **D-08's stated seam is unimplementable at offset 2.** Offsets 2 and 3 belong to CAP-02's arm. Writing a
  budget at offset 2 would make the host read `budget_hi` as a hardware revision and `budget_lo` as a
  version length — a **misparse**, not graceful degradation. The CAP-03 arm therefore lives **nested inside**
  CAP-02's arm, past its `if ver_end <= len(params_bytes)` guard, and is unreachable when no identity tail
  is present. That is correct and intentional.
- **This plan does not fix BF-1 and must not claim to.** Porting CAP-02's firmware emit is plan **143-03**'s
  first obligation. Until it lands, a v1.31 firmware build still cannot connect to this app branch at all.
  State that plainly in the SUMMARY; do not imply this plan makes anything talk to anything.
- `FIRESTARTER_DEV_ALLOW_PRE_V12=1` does **not** work around BF-1 — it bypasses the **version** check, and
  the identity-absent raise happens before `_validate_firmware_version` is reached. Do not suggest it as a
  workaround anywhere.
