**D-09's owed test, and Open Question 7 decided: a SOURCE-CONTRACT leg, labelled as such.**
D-09 makes `command_done()` (`firestarter.cpp:162-171`) the operation-level disable — it zeroes
`CONTROL_REGISTER`, `LEAST_SIGNIFICANT_BYTE` and `MOST_SIGNIFICANT_BYTE` on **both** the success arm
(`if (finished) command_done(&handle);`) and the timeout-abort arm of `loop()`, and because the
top-address bits and the `vpp_line` bit all live in those three registers, that zeroing fully
de-energises. D-09 says that reading is "recorded explicitly here so it is a decision, not a fudge —
and the phase owes a test proving `command_done()` actually clears, since nothing tests it today."
Verified: `grep -rn command_done src/ test/` returns four declarations, definitions and calls, one prose
mention, and four *comments* in `test_loop_eprom_v131.cpp` explaining why that suite deliberately does
**not** drive it. **Zero assertions.**

environment's `build_src_filter` (`+<proms/> +<boards/rurp_serial_utils.cpp> +<json_parser.c>
+<operation_utils.cpp>`) — which is exactly why `host_stubs_common.inc` stubs `op_reset_timeout` at all —
and adding it collides with the suite's own `main()` and would need a **seventh** environment, which
D-14 forbids. So the leg is a source contract, and the plan, the module docstring and the phase record
must all **label it as a source-contract claim, not a behavioural one**. It proves the source says the
right thing; it does not prove the AVR executes it. The related non-claim stands: that `command_done()`
runs on the real AVR abort path is **not** provable here, because the timeout arm depends on `millis()`
and is outside every native suite's reach.
