<objective>
Prove, off hardware, what Phase 142 actually changed — and prove the parts that did **not** change.

This plan is the behavioural evidence for VPP-01, for VPP-03's non-divergence property, and for
VPP-02's error-exit guarantee. It runs after plan 142-04, so most of its legs are **green on arrival**
and each therefore carries a named planted violation (the standing D-15 discipline).

**VPP-01, three kinds of evidence.**
- A direct `(protocol, ctrl_flags)` to mask **truth table**, callable because plan 142-04's Open
  Question 4 decision exposed `eprom_hv_route_mask` in `include/eprom.h`. This is the clearest possible
  statement of D-05's "selection is driven by `vpp_path`, not by a `protocol ==` switch", and it reaches
  the fail-closed NULL-row arm that no drive can reach (`configure_eprom:86-90` refuses an unknown
  protocol first).
- **Route-strobe proofs** that the resolved mask reaches the wire: `0x0B` drives the direct-VPE path
  with no drop bit; `--vpe-as-vpp` forces that same path onto a `0x07` handle (D-06 — the flag overrides
  the table, and it is a live user-facing flag set by **no** database entry, so proving it still works is
  what keeps this a firmware-only phase).
- The **negative** that D-02's gate exists for: a 32-pin part on **`REVISION_1`** still has its drop bit
  stripped after the first `set_address`. Rev 1, not Rev 0, is the load-bearing case — Rev 0 is
  separately refused by `eprom_check_vpp`'s `MSG_WARN_REV0_VPP_UNSUPPORTED` return while Rev 1 has no
  such guard.

**VPP-03's honest headline (D-03).** After this phase `eprom_check_vpp()` and the write path apply the
**same** routing. Before it they did not: `check_vpp` measured `0x08` with the drop bit **on**
(`eprom.cpp:345`) while the write stripped it before the first pulse (`:218`), so the
measured-and-validated voltage was not the voltage applied. Task 2 proves the closure by comparing the
physical control byte `eprom_check_vpp` measures under against the physical control byte in effect at
the write path's **first genuine program pulse** — not at its first control write, because the two were
already equal there even before the phase; the divergence lived in what held by the time a pulse was
emitted.

**VPP-02's headline gap.** Research's exit map found four leaking exits, all in `eprom_write_execute`:
`:226` (`row == NULL`), `:268` (`MSG_ERR_MAX_PULSES`), `:275` (`MSG_ERR_ENERGY_CAP`) and `:311`
(`MSG_ERR_VERIFY`). The last **disabled nothing at all** before this phase, and it is the highest-value
new case here. `:268`'s widened drop-bit leg lives in `test_loop_eprom_v131` (plan 142-04, parts I-K of its
single task);
`:275` and `:311` are authored here; `:226` is **structurally unreachable** — `configure_eprom:86-90`
already refuses an unknown protocol — so it is named as covered-by-construction by the wrapper and **no
case is faked for it**.

**D-11's explicit non-claim, restated so it is not inferred away.** The guarantee covers
control-register routes only. `mem_util_remap_address_bus` (`memory.cpp:418-420`) sets
`1UL << config.vpp_line` **ignoring `read_write`**, so it is asserted on reads too; clearing it on
write-path exit would be a read-path behaviour change this milestone excluded. The address-latch
`vpp_line` bit is cleared by `command_done()` at operation end and by nothing else. No case in this plan
asserts anything about it.

**D-03's non-claims, which bound every leg here.** Nothing in this plan says anything about silicon; the
`0x08` route change is proven in the **emitted control-register stream only**. No native suite reads an
ADC, so "the drop resistor produces ~13 V" is a non-claim. `delay()` and `delayMicroseconds()` are
unstubbed ArduinoFake free functions and the timing recorder stores **arguments only**, so **no timing
claim of any kind** is available from this suite. And on Rev 2-class, logical `CTRL_ADDRESS_LINE_18` and
logical `CTRL_VPP_P1_ENABLE` collapse onto the same physical bit `0x08` (`rurp_pinout.h:127`,
correction C-4), so every guarantee here is **logical**, not physical — that aliasing is unreachable
from a 27C write today but the record must say so rather than have Phase 144 discover it.

**Requirement ownership: this plan may mark NO requirement Complete.** It supplies behavioural evidence
for VPP-01, VPP-02 and VPP-03. `requirements:` is deliberately empty and must not be repopulated — plan
**142-07** declares all four `VPP-*` IDs and flips them in one hand edit after every piece of evidence
exists (the 141-05 / 141-09 convention).

**Read-only in this plan:** everything under `src/` and `include/` (except transiently, for the named
planted violations, each of which must be reverted and proven reverted), plus
`test/native/avr/test_loop_eprom_v131/`, `tests/`, `platformio.ini` and
`scripts/baseline/size_baseline.json`.

**L-1 working rule:** commit before running the full pytest suite.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| resolved logical mask to emitted physical byte | a resolver that returns the right mask proves nothing if the mask never reaches the wire, or if the write that carries it is elided by the register cache |
| measured VPP rail to applied VPP rail | validating a voltage under one route and then programming under another means the validated voltage is not the applied voltage |
| write-path error exit to rail state | the final-pass verify exit disabled nothing before this phase |
| board revision to bit decidability | on Rev 0 and Rev 1 the drop bit and A16 are the same physical line, so a drop-bit claim there is undecidable unless A16 is provably never set |
