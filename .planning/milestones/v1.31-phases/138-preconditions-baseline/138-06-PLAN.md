<objective>
Capture the **firmware** half of PREP-03's pre-change baseline: cold per-target flash and RAM for all
three AVR targets, case and suite counts for all four native environments, the native warning watermark
measured cold, and both gates' verbatim verdicts — then freeze them into an immutable
`size_baseline_v131.json` beside BASE-01 (**D-05**), measured and verified per **D-06**'s discipline.

Purpose: Phase 144's TEST-08 measures a flash and RAM delta against *this* record. A figure taken warm,
or truncated by a default two-minute timeout, or guessed down from prose, silently poisons that
comparison — and this repo has a worked correction on file proving the trap is live, not historical.

Measurement happens **after** the instrumentation lands, deliberately. AVR builds exclude `test/`, so the
AVR figures must be unchanged from the fork base and the live gate must still be GREEN — which turns this
measurement into positive evidence that the new stub layer is AVR-invisible. And the two pinned native
envs re-reading 141 cases across 17 suites with the new guards undefined **is** the flag-off proof,
stated behaviourally rather than as a byte diff.

Output: `size_baseline_v131.json`, `138-06-FIRMWARE-MEASUREMENT.md`.

**Fence:** the live `scripts/baseline/size_baseline.json` is **never rewritten** (D-05), and
`check_size_baseline.py` is **never repaired** when it is RED (D-07) — the discrepancy is recorded as a
named finding with an owner. Repairing a load-bearing gate inside the phase that exists to define
"before" would corrupt the measurement.
</objective>
