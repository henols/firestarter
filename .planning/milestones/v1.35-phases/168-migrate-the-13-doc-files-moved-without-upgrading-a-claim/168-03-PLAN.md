<objective>
Fix the 9 rows of the shipped chip database that carry a repository documentation path inside an
operator-visible string — by editing the generator and regenerating, never by touching the JSON.

Purpose: `firestarter info` surfaces `unsupported_reason` to a user, and after this phase the path
it names stops existing. This is a **data migration**, not only a code edit: the existing rows carry
the string. The project rule is standing and unambiguous — `chip_database.json` is generated, so the
fix is to the decode/emit path. Regeneration was measured this session to be a byte-for-byte round
trip against the current tree, so the only diff after the emitter edit is the 9 reason strings.

This plan runs **before** the wiki pages are stamped, because the stamp carries a hash of this file
and regenerating it afterwards would ship a stamp that is stale on the day it is written.

Output: a regenerated database whose reason strings name a wiki page instead of a path.
</objective>
