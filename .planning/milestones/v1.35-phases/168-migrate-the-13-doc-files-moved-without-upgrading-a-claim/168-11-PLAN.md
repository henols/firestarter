<objective>
Build and run the one-shot proof that the migration upgraded no claim: extract a committed claim
vocabulary from each pre-deletion source document and from its published page, compare the two
multisets, and report three buckets separately — dropped, added, and vacuous.

Purpose: criterion 4 demands a check that comes back empty, and the unit of that check is decided by
D-01.
It is **not** a text diff: the migration necessarily rewrote titles, rewrote links for a flat page
namespace and stripped unopenable paths, so a text diff is guaranteed non-empty for innocent
reasons — and a check that is non-empty for innocent reasons gets ignored, which this repository has
already proved with a workflow that failed five times out of five without ever asserting its
property. The failure mode that actually matters is a hedge quietly becoming a promise, and a
claim-token multiset catches exactly that while ignoring a renamed heading.

Two things about this checker are unusual and both are deliberate. Per D-03 it is a **one-shot proof,
not a standing gate** — it runs, it is demonstrated failing, its output is committed, and then it retires;
the accepted cost is that once the source directories are gone the source side is frozen forever and
nothing thereafter stops a later wiki edit from softening a 2026-08-31 claim. And **half of what the
requirement names is not present in the corpus at all** — one status value and the whole ledger
family occur zero times — which per D-04 the checker must print as vacuous rather than pass silently. A
"0 of 0 checked, PASS" is precisely the false pass this milestone exists to prevent.

Output: a vocabulary file, a checker, one observed red, and one committed green.
</objective>

  <action>
    Write `tools/wiki/honest01_claims.py` in the D-07 standalone-checker shape — the same shape as
    `wiki.py`, so no pytest harness enters the meta repository: stdlib only, module constants, a
    check function returning failure strings, a wrapper turning them into 0 or 1, and `main()`
    returning 2 for any unmet precondition. Flags: `--table`, `--wiki-dir`, `--vocab` and
    `--repo-root` (the directory containing both sub-repo checkouts). Load the vocabulary at one
    parse point and exit 2 on a parse or read failure, following the sibling precedent.

    Algorithm, per source-file to published-page pair:

    1. Read the source side with `git -C <sub-repo> show <sha>:<source path>`, taking the SHA from
       the migration table row. Read the destination side from the wiki clone at the mapped page name.
    2. **Non-vacuity, before any counting.** The `git show` must produce non-empty text and the
       mapped page must exist and be non-empty. If either fails, append a failure naming the row and
       **skip the comparison for that row** — a page that failed to resolve must never compare as
       "zero dropped". This is the single most important line in the checker: without it, a typo in
       a page name produces a perfect green.
    3. Normalise both sides identically: strip fenced blocks and inline code spans with `wiki.py`'s
       existing helper rather than a fresh regex, collapse whitespace runs, and lowercase only for
       the case-insensitive families.
    4. Count occurrences per token per family into two counters.
    5. Compare, and report **three buckets separately, never as one verdict**:
       - **dropped** — the source carried more of a token than the page does. This is the failure the
         whole requirement exists to catch. Exit 1, naming the page, the token and both counts.
       - **added** — the page carries more than the source did. Report it; do **not** fail. Adding a
         hedge is not upgrading a claim.
       - **vacuous** — any token in `expected_zero` present zero times on both sides. Print each one
         explicitly on its own line as zero-of-zero and not checked. Never fold these into the
         success line.

    The success line carries the count of pages compared and the count of tokens compared, so a
    vacuous pass is visible on its face.

    Note in the module docstring that this checker is a one-shot proof rather than a standing gate,
    and that once the source directories are deleted its source side is frozen at the recorded
    commits permanently.
  </action>
