<objective>
Give `firestarter_prom` the issue templates POLICY-02 asks for: a bug report, a feature request, and
a `dev test` chip-validation report — plus the chooser configuration that keeps the host CLI's
browser submission tier working.

Purpose: prom carries a `needs:report` label and issue #21 is a chip-validation report wearing it,
so the cost of unstructured intake is real and recurring (D-05). Forms make the missing information
impossible to omit; the chip-validation template's job is different — it hands over a command rather
than collecting fields, because only the CLI can produce the fenced-JSON block triage parses (D-06).

Output: four files under `.github/ISSUE_TEMPLATE/` in the meta repository, schema-validated offline
before they are committed, plus two evidence files.

**These files do nothing until they reach `main`.** GitHub reads issue templates from the default
branch only, and prom's `main` is 733 commits behind `beta`. Plan 172-07 carries them there in a
`.github`-only pull request; plan 172-08 proves they are live. This plan authors and validates them
on the milestone branch.

`autonomous: false` is deliberate: Task 1 is a package-legitimacy gate that must not be
auto-approved.
