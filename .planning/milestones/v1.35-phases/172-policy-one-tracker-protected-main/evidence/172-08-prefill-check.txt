== The question ==
D-07 keeps `blank_issues_enabled: true` specifically so that
`https://github.com/henols/firestarter_prom/issues/new?title=...&body=...` still opens a PREFILLED
blank issue rather than the template chooser. That URL is the browser tier of `--submit`, the tier
that exists for testers who do not have `gh` installed. GitHub documents `config.yml` as
customising *the chooser*; no reachable page says whether `/issues/new` with query parameters
still bypasses the chooser once templates exist. Unauthenticated probes only ever return a login
redirect with the query intact — consistent with the prefill surviving, but not proof. Hence a
human observation.

== The URL that was opened ==
Not hand-approximated. Generated by calling the product's own constructor, so the probe is
provably the same shape a real `--submit` produces rather than a lookalike:

  python3 -c "from firestarter.submit import build_issue_url, SUBMIT_REPO; ..."
  SUBMIT_REPO = henols/firestarter_prom

  https://github.com/henols/firestarter_prom/issues/new?title=%5Bdev%20test%5D%20at28c256%20%E2%80%94%20PASS&body=Prefill%20probe%20for%20v1.35%20Phase%20172%20plan%2008%20Task%203.%0ANot%20a%20real%20report%20%E2%80%94%20do%20not%20submit.%0A%0A-%20chip%3A%20at28c256%0A-%20verdict%3A%20PASS

Both `title` and `body` present, percent-encoded through submit.py's own
`urlencode(..., quote_via=quote)`, and NO `labels` parameter — the deliberate omission
`build_issue_url`'s docstring explains (RESEARCH Pitfall 1: GitHub silently drops or 404s
`labels` for a community tester without write access, so triage relies on the `[dev test]` title
marker plus the fenced-JSON `schema_version` instead).

== Why `dev test --submit` was NOT run to produce it ==
The plan permits either route ("a hand-built URL of the same shape answers the question equally
well"), and the hand-built route was chosen deliberately on three grounds: a real run costs a
board, a chip and ~100 s+ of bench time to yield one URL; the run's terminal step FILES A REAL
ISSUE in the public tracker, which for a probe is a live misfire risk in `firestarter_prom`; and
the question under test is a property of the URL, not of the run that builds it. The body text
carries "do not submit" so that an abandoned tab leaves nothing behind. Nothing was submitted.
