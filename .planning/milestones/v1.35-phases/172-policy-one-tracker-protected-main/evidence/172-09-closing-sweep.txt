WHAT THIS PHASE DOES *NOT* CLAIM — recorded beside the marks so they absorb nothing
===============================================================================

NON-CLAIM 1 — There is no GitHub Actions bypass, and there never was one to prove.
  Evidence: evidence/172-05-actions-bypass-probe.txt
  This plan's Task 3 instruction asks for a row saying the Actions bypass is "configured and,
  unless the throwaway-repo probe was run, unproven". That describes a state that never came to
  exist, and recording it as written would be recording a fiction. What actually happened:
  the Integration:15368 bypass was REJECTED at creation with HTTP 422 — "Actor GitHub Actions
  integration must be part of the ruleset source or owner organization" — because all three
  repositories are owned by the personal User account `henols`, which has no owner organization.
  The planned probe was rendered moot: it was designed to test whether an established Integration
  bypass covers GITHUB_TOKEN at push time, and the actor cannot be established at all.
  D-09 was revised by the operator to DeployKey:null:always, which all three rulesets now carry.
  All three repositories measure ZERO deploy keys, so that bypass grants nothing to anyone today —
  making POLICY-03's "no direct push" literally true of every person AND every bot right now, a
  stronger honesty position than the original design would have reached even had it validated.
  RESIDUAL, named: actor_id: null means ANY deploy key, present or FUTURE — not a specific key.
  Adding a deploy key to any of the three repositories later silently confers bypass on whatever
  holds it, with no further ruleset change. Inert today only because the count is zero.

NON-CLAIM 2 — gh#6's required status checks and required review-thread resolution are knowingly
  not implemented, per D-11.
  Both are declined deliberately, not overlooked. Status checks are the trap: pinning a check name
  that never reports deadlocks that repository's `main` behind a check that can never go green, and
  prom has only one registered workflow to pin. Review-thread resolution is a one-field addition
  (`required_review_thread_resolution: true`) that changes nothing for a single maintainer but sits
  outside POLICY-03's four clauses. Both are carried in the phase's Deferred Ideas and belong to
  whoever revisits the ruleset next. Phase 173's ledger should state them as non-claims rather than
  let them read as quietly delivered.

NON-CLAIM 3 — the wiki guard is registered but has never run.
  `Wiki check` has ZERO runs; its first fire is the weekly cron or a manual workflow_dispatch. Its
  three legs were run green against fresh clones in plan 172-03 and again in
  evidence/172-09-full-suite-final.txt, so the confidence is real, but "registered" and "observed
  green in CI" are different facts and only the first is true today.

NON-CLAIM 4 — the prefill check came back PREFILLED, so the plan's conditional third row is not
  owed. No regression, no backlog item, and submit.py was not touched (blob 179af6ed identical
  across the whole phase, per evidence/172-08-prefill-check.txt).
