=== METHOD DEVIATION, and why the plan's own leg would have been wrong twice over ===

This plan's <verify> leg runs a bare `grep -rInE <pattern> meta firestarter firestarter_app
wiki-clone --exclude-dir=.git --exclude-dir=.planning` over symlinked directories. That command is
unsafe in this devcontainer in two independent ways, and both were measured rather than reasoned
about:

1. `grep` on PATH here is **ugrep 7.8.4**, not GNU grep, and ugrep honours .gitignore by default.
   Measured: over /workspaces with the same pattern and exclusions, ugrep reports **0** matches
   where GNU grep (/usr/bin/grep 3.11) reports **38**. The plan's leg would therefore have gone
   GREEN by silently declining to scan, which is the exact failure mode T-172-04 exists to catch —
   and the without-exclusion counter would not have caught it either, because ugrep under-scans
   that leg identically.

2. Conversely, a raw GNU-grep directory walk is a **false RED** here. All 38 of those matches are in
   untracked, gitignored scratch that no consumer and no CI run ever sees:
     untracked_scratch_matches=38
     .v1.34-arms/{control,v133}/     — v1.34 host-arm worktrees, README/PKG-INFO/METADATA + doc/
     firestarter_app_py32/           — a gitignored sibling worktree, README + doc/
     firestarter_py32_ci/            — a gitignored sibling worktree, README
     firestarter_app/.venv/          — installed dist-info METADATA of published 2.0.7/3.0.0b21 wheels
   Every one is either a stale checkout of a README this phase has since trimmed, or the metadata of
   an already-published wheel that cannot be retroactively edited. Failing the phase gate on those
   would be failing it on artifacts outside the repository's tracked surface.

**Resolution used above:** GNU grep (/usr/bin/grep), scoped to `git ls-files` per repository with
.planning/ excluded, plus a plain recursive GNU-grep walk of the fresh wiki clone (which has no
gitignored scratch to confuse it). That is precisely the set a fresh consumer clone contains, which
is what the requirement is about. The result is 0 on all four surfaces — green on the merits, not
green because the scanner declined to look.

The registered CI copy of this leg is unaffected by (1): GitHub runners carry GNU grep. It is
exposed to (2) only if a runner's workspace ever contains gitignored scratch, which a fresh
actions/checkout does not. No change to wiki-check.yml is made or needed here.
