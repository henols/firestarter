**The script.** Shebang `#!/usr/bin/env python3`, then a module docstring that names the file, states what it asserts, and states the exit-code contract verbatim in `dispatch_mirror.py`'s form: 0 = the asserted property holds, 1 = the asserted property is false, 2 = a precondition was not met. The docstring is the only place prose is allowed anywhere in this file. Then `from __future__ import annotations` and stdlib imports only — `argparse`, `re`, `sys`, and `Path` from `pathlib`. No third-party import. No dynamic evaluation and no shell interpolation of any parsed field, per RESEARCH.md's ASVS V5 note.

Module-level UPPER_CASE constants for every regex, delimiter and floor:
`TABLE_ROW_RE` anchored as `^\|(.+)\|\s*$` (copy `honest01_claims.py:47`); `NO_VALUE_MARKER` set to the em-dash the table uses; `NAV_EXCLUDED_PAGES` as a `frozenset` of `_Sidebar.md` and `_Footer.md` only — matching `wiki.py:38`, and deliberately NOT including `Home.md`, because `Home` carries a main-table row and must be accounted for by it; `MIN_FOOTER_ROWS` set to 6; `MAIN_TABLE_KEY` set to the header cell `Wiki page`; `RETIRED_TABLE_KEY` set to the header cell `Was published as`; `REMOVED_TABLE_KEY` set to the header cell `What it was`; `FOOTER_RULE` set to the three-hyphen horizontal rule; and `FOOTER_RE`, the single regex that both the generator and the checker are keyed on.

**RESEARCH.md Pitfall 3 applies to naming.** The artifact is an in-page trailing block, not GitHub's reserved global `_Footer.md` page. `parse_tables(table_path) -> dict[str, list[dict[str, str]]]` — the deliberate fix for the accident PATTERNS.md flags. Walk the file line by line. A line that does not match `TABLE_ROW_RE` ends the current table and clears the captured header. The first row of a table is its header; the separator row (cells composed only of hyphens and colons) arms the table; subsequent rows are data. Classify each table by header identity: a header containing `MAIN_TABLE_KEY` is the main table, one containing `RETIRED_TABLE_KEY` is the retired table, one containing `REMOVED_TABLE_KEY` is the removed table. Return the three lists under those three names. Never key a row from one table by another table's header names.

`footer_eligible_rows(main_rows)` — main-table rows whose `Source path` and whose `Pre-deletion SHA` are both something other than `NO_VALUE_MARKER`. This is RESEARCH.md Pitfall 7's filter, made explicit rather than inherited from a SHA-only test.

`footer_line(row) -> str` — the single source of the footer text, called by both the generator and the checker so the two cannot disagree. Two variants, chosen by the row's `Post-move edits` cell. When that cell is `NO_VALUE_MARKER`, the line reads: an asterisk, then `Relocated from ` and the source path in backticks, then ` in ` and the source repo in backticks, then ` at ` and the pre-deletion SHA in backticks, then `. Moved intact and not edited since; not re-verified against the code.` and a closing asterisk. When the cell has a value, the line reads the same up to the SHA, then a comma, then ` then ` and the cell's value verbatim and ` on the wiki; not re-verified against the code.` and a closing asterisk. The two variants exist because a blanket unchanged-content claim would be false on four of the six pages — see this plan's "Open questions this plan decides".

`FOOTER_RE` — anchored, capturing the source path, the source repo, the 40-hex pre-deletion SHA and the optional post-move-edit clause, so the checker reads back exactly the fields `footer_line` writes.

`load_pages(wiki_dir) -> dict[str, str]` — every `*.md` in `wiki_dir` sorted, excluding `NAV_EXCLUDED_PAGES`, read as UTF-8. Copy `honest02_truth.py:314-320`'s shape.

`check_footers(rows, wiki_dir) -> list[str]` — leg 1, table to page. For each footer-eligible row: resolve `wiki_dir / f"{row['Wiki page']}.md"` and confirm the resolved path is contained inside the resolved `wiki_dir`; a row that escapes reports `UNSAFE ROW: <page cell> resolves outside the wiki directory` and is not opened (ASVS V12, threat T-173-07). A page that does not exist reports `PAGE MISSING: <page> — the table names it but the wiki clone does not have it`. A page whose last non-empty line does not match `FOOTER_RE` reports `FOOTER MISSING: <page>`. A page whose footer parses but disagrees with the row on repo, path, SHA or post-move-edit clause reports `FOOTER DRIFTED: <page> — footer says X, table says Y`, naming both sides.

`check_page_accounting(main_rows, wiki_dir) -> list[str]` — leg 2, page to table, the direction RESEARCH.md C-2 found missing. Every main-table row's `Wiki page` must resolve to a live page (the same `PAGE MISSING` word), and every live non-navigation page must appear as some main-table row's `Wiki page`, or it reports `UNRECORDED PAGE: <page> has no row in the migration table`. The retired and removed tables are parsed deliberately and are used only to keep their `Source path` cells out of the main-row list; a retired page is not live, so it never reaches this leg.

`emit_footers(rows, wiki_dir) -> int` — the generator, reached only under `--emit`. For each footer-eligible row, read the page, strip any existing trailing block that matches `FOOTER_RE` together with the `FOOTER_RULE` line and surrounding blank lines above it, then append a blank line, `FOOTER_RULE`, a blank line, and `footer_line(row)` with a trailing newline. Idempotent by construction: a second run must leave the tree byte-identical. Return the number of pages written.

`_build_argparser()` — `prog="provenance_footers.py"`, `description=__doc__`,
`formatter_class=argparse.RawDescriptionHelpFormatter`; `--table` and `--wiki-dir` both
`type=Path, required=True`; `--emit` as `action="store_true"`.

`main() -> int` — preconditions first, each with its own `ERROR: --<arg> not found: <path>` line to stderr and `return 2`. Then parse. Then the vacuity floor: if the main table was not found by header identity, or fewer than `MIN_FOOTER_ROWS` footer-eligible rows parsed, print an `ERROR:` naming the count and the required minimum and `return 2`, never 0 — `dispatch_mirror.py:200-208`'s pattern, and the reason a checker cannot green on an emptied table.
