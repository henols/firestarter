Add the `publish` capability to `tools/wiki/wiki.py`.

New helper:
- `_git(*args, cwd=None, check=True)` — wraps `subprocess.run(["git", *args], cwd=cwd, check=check,
  capture_output=True, text=True)`. List form only, never `shell=True`, never a shell string with an
  interpolated filename. This is the only place a git process is created.

New function `cmd_publish(args) -> int`, in this exact order:

1. Run `cmd_check(args)`. If it returns non-zero, print
   `ERROR: offline legs failed; nothing was sent to the wiki.` to stderr and return 1. Validation runs
   unconditionally before publication, following `codegen.py`'s validate-before-emit ordering — an
   orphan or an illegal filename must not reach the wiki.
2. Probe the remote with `_git("ls-remote", args.wiki_remote, check=False)`. On non-zero: if
   `args.require_wiki` is set, print `ERROR: wiki remote not reachable: <remote>` to stderr and
   return 1; otherwise print to stderr, on separate lines,
   `ERROR: wiki remote does not exist: <remote>`, a line naming `WIKI-01` as the blocked requirement,
   and a line instructing the operator to save one page at
   `https://github.com/henols/firestarter_prom/wiki` because GitHub creates the wiki repository only
   on the first web-UI page save and there is no API for it — then return 2. Exit 2 is a distinct
   state from exit 1 precisely so that the operator gate never reads as mysterious drift.
3. Clone into a fresh worktree under `tempfile.mkdtemp()` with `_git("clone", args.wiki_remote, wt)`.
   Clone, never `init` — the branch must come from the remote.
4. Assert the branch: `_git("rev-parse", "--abbrev-ref", "HEAD", cwd=wt)` must equal `WIKI_BRANCH`.
   On mismatch print `ERROR: wiki worktree is on branch <got>, expected <WIKI_BRANCH>` to stderr and
   return 1. A push that lands on a branch a wiki does not serve reports success and changes nothing
   a reader can see; this assertion is the only thing that catches it.
5. Assert the wipe target before deleting anything: the worktree path must be absolute, must contain
   a `.git` entry, and `_git("remote", "get-url", "origin", cwd=wt)` must equal `args.wiki_remote`.
   On any mismatch print `ERROR: refusing to modify <path>: not the expected wiki worktree` to stderr
   and return 1. A path bug here runs a recursive delete in the wrong directory.
6. Wipe every top-level entry of the worktree except `.git`, then copy every file from
   `args.source_dir` into the worktree. Use `pathlib` and `shutil` — `shutil.rmtree` per entry and
   `shutil.copy2` per file — not a shell invocation. The wipe-and-relay is what makes WIKI-02's
   authority direction mechanical and what makes a source-side deletion propagate.
7. `_git("add", "-A", cwd=wt)`, then `_git("diff", "--cached", "--quiet", cwd=wt, check=False)`.
   A zero return means nothing is staged.
8. Branch on the result. Nothing staged: print `OK: wiki matches source (<n> pages); no change.` and
   return 0, in both the dry-run and the `--push` case. Something staged and `--push` not set: print
   `ERROR: wiki differs from in-repo source.` to stderr, print the output of
   `_git("diff", "--cached", cwd=wt)` to stdout, and return 1. Something staged and `--push` set:
   commit with `_git("-c", "user.name=...", "-c", "user.email=...", "commit", "-q", "-m", <message>, cwd=wt)`
   using per-invocation identity rather than mutating global config, then
   `_git("push", "-q", "origin", WIKI_BRANCH, cwd=wt)`, then print
   `OK: published <n> pages to <remote> on <WIKI_BRANCH>.` and return 0.
   Never `--allow-empty`, never `|| true`, never a force refspec.
9. Remove the temporary worktree in a `finally` block.

The comparison in step 7 exists exactly once and both entry points reach step 8 through it. That is
D-08: the dry-run IS the drift check, so the check cannot report agreement while the publish would do
something different. Do not add a second comparison anywhere, and do not add a `--check`-style flag to
`publish` — the absence of `--push` IS the check.

Never log the remote when it could carry a credential: do not print `args.wiki_remote` inside an

exit 2 into a hard exit-1 failure, for use once the wiki exists). Add `"publish": cmd_publish` to
