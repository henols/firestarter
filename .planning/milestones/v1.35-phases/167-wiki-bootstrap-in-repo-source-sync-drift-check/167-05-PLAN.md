<objective>
Wire the offline half of the pipeline into CI and make the repository's documents of record true
again.

`.github/workflows/wiki-check.yml` is the second workflow this repository will have. It follows
`catalog-sync-check.yml`'s shape (D-07) with two deliberate corrections: it is keyed to `beta` rather
than `main` (D-06), and it declares an explicit `permissions:` block, which the existing workflow
lacks. It runs **offline legs only** — `wiki.py check` and `selftest.sh`. The live wiki-comparison
leg's code already exists and is fixture-proven, but its CI trigger is plan 167-06's operator-gated
work, because a check that compares against a wiki which does not yet exist would be red from the day
it merges, and the reflexive fix of warning-and-exiting-0 would make the check unable to fail for the
one reason it exists.

`CLAUDE.md` and `.planning/codebase/STRUCTURE.md` both become factually false the moment `wiki/`,
`tools/wiki/` and a second workflow exist. Correcting them here is meta-repo accuracy, not
documentation migration, so it does not collide with the Phase 168 fence.

Purpose: a check nobody is prompted to run does not run, and this project already decided sync
assertions belong in CI.
Output: one new workflow, two corrected documents of record, and the WIKI-06 API read-back.
</objective>
