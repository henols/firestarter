<objective>
Re-record the firmware size baseline to the current cold-build figures by fixture severance, in one
commit, so `check_size_baseline.py`'s default byte-identity gate is green again without the frozen
`captured_build_v158_*` generation being touched.

Purpose: Phase 183 shrank AVR flash on all three targets and moved the native case count on both native
envs. `scripts/baseline/size_baseline.json` still describes the tree as it was before that, and it was
already stale by a further 16 B on every target before Phase 183 began. This is the phase's largest
instance of a record describing a tree that no longer exists — and the one with a live CI consequence,
because `build.yml` runs the firmware suite ungated on every branch but `beta`.

This is the phase's TRACER slice. It wires the whole path this phase's firmware half touches —
measurement (`pio`) → record (`size_baseline.json`) → evidence (the fixture family) → assertion (the
four legs) → gate (`check_size_baseline.py` in default mode) — end-to-end in one atomic unit, before
anything expands out from it. The atomicity is not a planning preference: D-11 requires the JSON and
the logs to come from the same cold rebuild, and RESEARCH §A.7 requires the baseline move and the
severance to land in the same commit or firmware CI goes red. A per-target or capture-then-transcribe
split would violate one or both.

Output: four new fixture files, two genuinely re-captured native summaries, a baseline JSON re-recorded
on both axes, four repointed/updated legs with their severance docstring paragraphs, and a
reconciliation of the predicted red-leg count against the observed one.
</objective>
