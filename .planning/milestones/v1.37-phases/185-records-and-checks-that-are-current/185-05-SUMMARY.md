# Phase 185 Plan 05: Repair the catalog sync script's two self-comparing diff checks Summary

**Replaced two `diff "$X" "$X"` tautologies in `tools/catalog/sync_to_subrepos.sh` with a generate-to-temp / install / diff-the-install shape, and proved the repair by watching it fail on a planted read-only divergence before restoring and re-observing green.**

## Performance

- **Duration:** 24 min
- **Started:** 2026-09-11T00:00:00Z (approx, single-session execution)
- **Completed:** 2026-09-11
- **Tasks:** 2
- **Files modified:** 1

## Accomplishments
- Both post-generation verifications (firmware `messages.h`, host `messages.py`) now compare a fresh `mktemp` file against the installed committed path — two traceably distinct operands — instead of diffing the committed path against itself.
- Each repaired verification gained an `else` branch that writes an `ERROR:` line to stderr and exits non-zero; previously the tautology sat inside an always-true `if` with no `else`, so `set -e` could never fire.
- The RED state was genuinely observed (not asserted): a hand-diverged, `chmod 0444`'d `firestarter/include/messages.h` made the plain `cp` install fail, which surfaced through to the `else` branch's `ERROR:` line and `exit 1` — resolving the previously-reasoned-but-unmeasured `cp` vs. `cp -f` assumption on the first attempt.
- The paired GREEN was observed after restoring by explicit path (`chmod 0644` + `git -C firestarter checkout -- include/messages.h`), confirming the repair is not permanently armed.
- The script's update purpose is preserved: `git status --porcelain` in both sub-repos showed zero tracked modifications before the repair, after the repair, and after the restore — the repair verifies the install landed, not that the artifact was already drift-free.
