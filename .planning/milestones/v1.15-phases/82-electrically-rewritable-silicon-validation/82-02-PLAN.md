<objective>
Bench-prove the `supported` claim on real silicon for the 6 lower-risk rewritable chips via the
explicit A→B two-image rewrite (D-05/D-06) on Leonardo + RURP Rev 2.0: the three 0x07 12V EEPROMs
(W27C512, W27E512, SST27SF512 — REWR-01), W27E040 (0x08 — REWR-02), SST39SF040 (0x06 — REWR-03),
and FM1608 (0x40 FRAM overwrite — REWR-05). For each, confirm the DB decode matches silicon (DB-01)
and append a non-vacuous EVIDENCE row (D-14).

Purpose: Proves auto-erase (0x07/0x06/0x08) and clean overwrite (FRAM) actually fire on hardware —
the milestone's core "prove it on real silicon" claim. The flash4 pair (W29C020/W29C040, REWR-04)
and its CR-01 risk are handled separately in Plan 03.

Output: 6 appended EVIDENCE.{md,json} rows, each PASS/FAIL/ANOMALY with seeds, SHAs, and a DB-01
decode-vs-silicon confirmation.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host CLI → Leonardo + Rev 2.0 | wrong board/shield makes every PASS untrustworthy (read oracle corrupt off Leonardo) |
| write VPP path → 12V EEPROM socket | a miscalibrated R1 (1000 vs 270000) misreads VPP → wrong voltage on the part |
| verify-read step → VPP regulator | Phase 81 boot-VPP-refusal gotcha can surface during the read leg of write→read→verify |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-82-04 | Spoofing | board/shield identity | mitigate | Task 1 SAFE-01 gate: operator-stated silkscreen Rev 2.0 + `controller:`=Leonardo + port re-verify after any USB event (D-10) |
| T-82-05 | Tampering | VPP calibration | mitigate | Live `r1 ≈ 270000` readback per session (Task 1); STOP-and-recalibrate if wrong — guards the 12V write path |
| T-82-06 | Repudiation | false-PASS oracle | mitigate | Non-vacuous bar (D-14): consistency-check --runs 3 byte-identical + wrong-file verify RC=1 per PASS |
