<objective>
Close the D-30 FM1608 / FRAM (0x40) blank-check "Empty input" tooling gap host-side. FM1608 routes
through the firmware `configure_sram()` no-op stub, which leaves a NULL `firestarter_operation_main`
for `CMD_BLANK_CHECK`, so the firmware emits `0xA4 MSG_ERR_EMPTY_INPUT` (Pitfall 4 — it is a firmware
message, not a host string). SRAM/FRAM have no meaningful "blank" concept. Detect SRAM/FRAM in the
host blank-check entry and short-circuit with a clear message BEFORE sending a command the firmware
cannot service.

Purpose: FIX-01 host half — tooling polish (FM1608 already PASSed its write via direct `write -b` in
Phase 82, so this is not a silicon fix). Bounded to the host; the wire protocol and firmware are NOT
changed (D-11 bounds firmware to the VPP-skip only).
Output: a host short-circuit in `eprom_operations.py` (+ `cli_handlers.py` if the entry point lives
there) and a pinning test, host suite green.
</objective>
