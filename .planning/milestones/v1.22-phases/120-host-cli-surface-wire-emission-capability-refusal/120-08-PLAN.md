| Element in `dev test` | Line | What `dev sdp` must do instead |
|---|---|---|

## Exit-code decisions, settled here explicitly

- Operation ran: `sys.exit(0 if ok else 1)` — matching every other command (D-11).
- **Explicit user decline** at the confirm: `click.echo` an aborted message and `sys.exit(0)`. A decline is not an error; the user got what they asked for. This follows `dev test`'s `:1842` precedent and must be tested.
- **Host-imposed refusal** (absent / capability / support-status / off-TTY-without-`-y`): non-zero. Exit `0` on a capability refusal would be wrong, so both branches are tested.
- A `MSG_WARN_SDP_TBLC_EXCEEDED` (`0x87`) frame prints at WARNING and does **not** change the code.

## Mechanically enforced, not merely a style choice

`get_response()` filters `NON_RESPONSE_PREFIXES` (`["INFO", "DEBUG"]`) out entirely at `serial_comm.py:424`, so the operation layer **cannot** see the firmware duration frame. D-10's "no duration on the host line" is therefore mechanically enforced rather than a discipline. Do not attempt to plumb one; a task phrased as "extract the microseconds from the frame" contradicts D-10 and is impossible above the transport without touching the ring-fenced read loop.
