<objective>
Make the `--skip-sdp-unlock` opt-out verifiable at runtime: require firmware's `MSG_WARN_SDP_UNLOCK_SKIPPED` (`0x86`) ack when the flag was set, and fail loudly when it is absent (HOST-06, D-15). Record D-16's landing-order fact with commit provenance and introduce no version floor. Closes HOST-06.

Purpose: the two halves of the wire surface have **different detectability**, and that asymmetry is the whole answer to HOST-06. An unknown **command** produces an error, so plan 120-08's D-14 mapping handles the command half. An unknown **flag bit** produces **silence** — `0x100` against `3.0.0b11` is silently ignored and the declined unlock runs anyway, which is precisely the harm HOST-06 names. But when the flag *is* honoured, firmware emits `0x86`. So the absence of `0x86` after setting the flag converts a silent failure into a loud one, using machinery that already ships.
Output: a bounded observed-id record, the `write_eprom` check, tests for both directions, and HOST-06 ticked.
</objective>

## Why this seam and not the other two

`WARN` is **not** in `NON_RESPONSE_PREFIXES`, so a `0x86` frame *is* returned by `get_response()`. In `_execute_phase`'s loop it is neither the phase terminator nor an `ERROR`, so it falls to `_handle_progress_response`, which does `logger.warning(f"Programmer warning: {response.message}")` and **keeps nothing**. Three candidate seams exist; two are rejected:

- `_read_and_parse_lines` — **ring-fenced by GATE-1.8d.** Forbidden.
- `_handle_progress_response` — correct but shared by every operation and every phase. Rejected as too wide for a single-purpose check.
- **`_decode_id_frame` — chosen.** It is already an override wrapper whose docstring states *"The GATE-1.8d ring-fenced `_read_and_parse_lines` body is not touched — only this override seam is used."* Phase 55 records `firmware_max_chunk` there from `MSG_OK_READY`, with a plausibility clamp on the extracted value. Recording an observed id into a bounded set is the identical move with an in-tree precedent.

## D-16: no version floor, and the fact recorded instead

D-14 and D-15 discharge HOST-06's substance at **runtime**. The sequencing invariant itself is recorded as a fact rather than enforced by a comparator: **the firmware half landed first, in Phase 119, final commit `0048b3d`** on branch `v1.22-at28c-software-data-protection-lifecycle`, with the tree clean; the host half lands in Phase 120. A numeric minor bump to make the existing capture regex sufficient was rejected because it would make HOST-06's correctness depend on a release-versioning decision that belongs to Phase 122's CLOSE-03, and would constrain that decision from inside Phase 120. `firestarter/include/version.h:11` still reads `3.0.0b11` and is **not** bumped by this phase.
