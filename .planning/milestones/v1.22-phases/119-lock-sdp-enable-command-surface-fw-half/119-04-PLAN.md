Its comment block must record five things, because this comment is one of the two records that discharge
ROADMAP criterion 5:
1. That the array is AT28C SDP-**enable**: three writes to the magic addresses, terminal byte `0xA0`, per
   Atmel doc0270 rev `0270L-PEEPR-2/09` section 19 note 2 — the citation of record, corroborated by
   Microchip DS20006432B section 6.18 note 2, whose sentence is that the Write Protect state activates at
   the end of the write **even if no other data is loaded**. That is why there is no payload.
2. That the `extern` line is **load-bearing**: in C++ a namespace-scope `const` array has internal linkage
   unless a prior declaration with external linkage is visible, and Plan 119-06's cross-guard must pin
   this production array rather than a transcribed test-local copy.
3. That the table is kept **`0x0D`-local** and deliberately does **not** drive the byte-identical

   stays untouched.
4. **The dual-purpose hazard, stated plainly (D-10).** `AA-55-A0` is byte-identical to
   `FLASH_ENABLE_WRITE`, the protected-**write** prefix, and to `FLASH_ENABLE_WRITE_PROTECTION`. The only
