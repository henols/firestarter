## 8. The one deviation: app CI failed on its first push, fixed, then succeeded

**What happened.** The firmware push (§5, run `30551682616`) succeeded cleanly on the first
attempt, exactly as the plan's sequencing intends. The app's first push (`0adfb4f`, run
`30552014590`) reached the `pytest tests/ -v` step and **failed with 2 failed / 1101 passed / 31
skipped**:

```
FAILED tests/test_check_is_memory_cmd_no_ifdef.py::test_checker_exits_zero_on_clean_source
  AssertionError: checker exited 1 on the real, clean source.
  stderr: ERROR: source file not found: .../tools/../../firestarter/include/firestarter.h
FAILED tests/test_check_no_log_in_sdp_window.py::test_checker_exits_zero_on_clean_source
  AssertionError: checker exited 1 on the real, clean source.
  stderr: ERROR: source file not found: .../tools/../../firestarter/src/proms/eeprom_28c.cpp
```

**Root cause.** `beta-release.yml` checks out only `firestarter_app` — there is no sibling
`firestarter` checkout in that CI job (this is the first real `push: beta` run to exercise these
two test files; they were added by this milestone, Phase 119 Plan 03 / Phase 116 Plan 04, and had
only ever run in this session's devcontainer, where the sibling firmware checkout exists). Both
tests' `test_checker_exits_zero_on_clean_source` case resolves the real firmware source file with
no override and hard-asserts the checker exits 0 — but eight-plus sibling gates in the same commit
set (`test_sdp_table_parity.py`, `test_revision_constants_parity.py`,
`test_gen_validation_header.py`) already carry a `_FW_ABSENT` / `pytest.mark.skipif` guard for
exactly this "firmware checkout absent" condition, and these two files never got that guard when
they were written.

**Disposition: Rule 1 (auto-fixed bug) / Rule 3 (blocking issue), not Rule 4.** This is a
test-only, mechanical fix that mirrors an already-established, already-reviewed pattern in the
same file set — no production code, no threat-model surface, no forbidden action. It squarely
blocked completing Task 2 (a green app cut), so it was fixed inline rather than halting the plan
with firmware already published and the app left uncut.

**The fix.** Added the identical `_FW_ABSENT = not <path>.exists()` /
`pytest.mark.skipif(_FW_ABSENT, reason="firestarter firmware checkout absent (...)")` guard,
applied only to each file's clean-source control test (every other case in both files already
drives a fixture or temp file via `FIRESTARTER_CMD_ADMISSION_SRC` / `FIRESTARTER_SDP_SRC` and needs
no firmware checkout). Verified locally (firmware checkout present, so the skip does not fire):
`python3 -m pytest tests/ -v` → **1134 passed** (zero regression from the `122-NONREGRESSION.md`
baseline), `ruff check` / `ruff format --check` clean on both files.

**Where the fix landed — `beta` only, not the milestone branch.** Committed as `81fa53c` directly
onto `firestarter_app`'s `beta` (message: `fix(122-07): skip firmware-checkout-dependent
clean-source tests in standalone CI`), then `beta` was pushed a second time, triggering the run
that actually cut b14 (§5, run `30554308461`). The fix was **also** cherry-picked onto
`v1.22-at28c-software-data-protection-lifecycle` (as `b5096a1`) to keep the branch consistent for
any future merge, then **that cherry-pick was reverted** (`git reset` back to `4001396` + `git
checkout --` on the two files) once it was clear that keeping it there would leave the milestone
branch's HEAD SHA different from plan 122-03's recorded merge SHA — an acceptance criterion this
plan explicitly checks (`git log --oneline -1` on the milestone branch unchanged from 122-03's
merge SHA, used as a proxy for "no tag created by hand"). The milestone branch is confirmed back at
exactly `4001396bbd42d5ba36ce24f40e0315ee6de32d60`, unchanged (§10). This means the fix is
**live only on `beta`** right now; it will need to be picked up again whenever the milestone branch
is next merged toward `main` (`/gsd-complete-milestone`'s job) so it is not silently lost. Recording
this explicitly so it is not forgotten.

**What this deviation is NOT.** Not a production-code change, not a workflow-trigger edit, not a
`--force` push, not a hand-set version, not an architectural change. `.github/` byte-identical to
`origin/beta` in both repos (see §11 — the app repo already showed empty at merge time; the
firmware repo's pre-existing `build.yml` divergence, unrelated to any beta trigger, is also
addressed there).
