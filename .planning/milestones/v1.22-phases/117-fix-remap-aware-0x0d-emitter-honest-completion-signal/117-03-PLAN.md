<objective>
Correct `eeprom28c_write_execute`'s per-page polling so a partial write cannot report success, and
prove it with a planted partial-write scenario that the deleted check is shown — executably, in CI,
forever — to have passed.

Purpose: **FIX-06 is a conflation bug, not a sampling-rate bug.** "1 byte in 64" undersells it —
polling the page's last byte IS the canonical AT28C completion protocol. The defect is that the
*same read* also serves as the data-landed proof, via an equality compare that passes whenever the
old byte already equalled the new one (blank `0xFF` regions, unchanged bytes). That is exactly
gh#11's shape. Aim the fix at the conflation, or it will be aimed at the wrong thing.

Output: two functions with one job each, a read-back that attributes a failure to a byte, and a
side-by-side old-versus-new contrast that cannot decay into prose.

**Validation ceiling (REQUIREMENTS.md §"Validation Ceiling"):** no AT28C part is on the bench. Every
claim's subject is the code. Permitted: "the fixed path reports ERROR for a planted partial write".
Forbidden: any claim about whether real silicon completed a page write.
</objective>

## Decisions made in this plan (delegated by 117-CONTEXT.md §"Claude's Discretion")

1. **FIX-06's test home is `test_val_eeprom28c`.** It is already in `[env:native]`'s `test_filter`, so
   the new cases are protected independently of plan 117-01's RED→GREEN flip, and it is the `0x0D`
   Tier-1 suite. Verified during discussion and re-verified here: it holds exactly **3** cases, all
   VPP-free configure-phase assertions, none of which drives `write_init` or `write_execute` — so no
   existing golden can break. Rejected: `test_sdp_harness`, whose ordered strobe recorder caps at 512
   entries (`host_stubs_common.inc:87`) and would overflow on a real multi-byte page write, mixing an
   unrelated concern into the always-green stream-equality suite.
2. **The read-back covers only the bytes of the current flush window**, not the whole physical page
   including bytes a prior chunk wrote. Firmware may only claim what it can substantiate from
   `handle->data_buffer`: bytes written by a prior chunk are no longer in that buffer, so re-reading
   them would either fabricate an expected value or require re-deriving data the handle does not hold.
   Each chunk's own flush already read-back-verified its own bytes, so coverage of *every byte this
   operation wrote* is complete without it.
3. **The mismatch path reports the failing address.** Today's poll bare-`return`s mid-buffer with the
   poll address in `MSG_ERR_EEPROM_TIMEOUT` but no per-byte attribution. FIX-06's purpose is to make a
   partial write attributable, so the read-back's error payload carries the failing address alongside
   expected and observed, reusing the existing `MSG_ERR_VERIFY` id and `memory_verify_execute`'s
   payload order (`memory.cpp:308-328`). **No new `MSG_*` id is added** — that would require the meta
   `messages.toml` codegen ritual plus the host's parallel `messages.py` copy, which is Phase 118/120
   scope and would break the firmware-before-host ordering invariant.
4. **The planted mock is address-keyed with a single stale address.** It returns the correct written
   byte for every address except one planted earlier address, which returns its pre-write value. This
   satisfies the DQ7-complement poll for the page's last byte (so the completion arm reports done) and
   fails only the read-back — isolating the conflation precisely. Dispatch is on ADDRESS, never on call
   order, per the in-tree rule recorded at `test_eeprom28c_sdp.cpp:129-132`.

All edits in `eeprom_28c.cpp`. Touch no other file in this task.

**(a) Two new named constants**, in the existing constants block beside `AT28C_TWC_MAX_MS`:
  - `AT28C_DQ7_MASK` = `0x80` — the data-polling bit. Comment: during an internal page-write cycle a
    read of the last byte written returns the **complement** of that byte's DQ7; when the cycle
    completes DQ7 reads true. This is the canonical AT28C completion protocol and it is the *only*
    job the poll now has.
  - `AT28C_PAGE_POLL_MAX_READS` = `2000` — the poll's iteration bound, preserving today's effective
    ceiling (2000 iterations of `delayMicroseconds(10)`). Comment: an iteration count, not a `millis()`
    deadline, for the same reason as `AT28C_TOGGLE_POLL_MAX_READS` (the native suites mock `millis()`
    to a constant).

**(b) `eeprom28c_wait_for_page_write` — completion only.** Add a file-static
`bool eeprom28c_wait_for_page_write(firestarter_handle_t* handle, uint32_t address, uint8_t expected)`,
forward-declared with the file's other statics. Body:
  - loop up to `AT28C_PAGE_POLL_MAX_READS` times: `delayMicroseconds(10)`, then read through
    `handle->firestarter_get_data(handle, address)`; treat the cycle as complete when
    `(observed & AT28C_DQ7_MASK) == (expected & AT28C_DQ7_MASK)` holds on **two consecutive** reads,
    following `flash_util_verify_operation`'s double-read idiom (`flash_utils.cpp:38-40`) so a single
    transient sample cannot end the poll. Return `true` on completion;
  - on exhaustion, emit `LOG_ERROR_ID_BYTES(MSG_ERR_EEPROM_TIMEOUT, …, 5)` with the same 5-byte
    payload shape the existing code uses (`{address>>16, address>>8, address, expected, observed}`),
    set `handle->response_code = RESPONSE_CODE_ERROR`, and return `false`.

This function compares **only the DQ7 bit**, never the whole byte. Put that in its comment, with the
reason: a whole-byte equality compare is the conflation FIX-06 removes — it passes spuriously whenever
the old byte already equalled the new one, which is precisely gh#11's shape. Every read goes through
`handle->firestarter_get_data`; no direct `rurp_*` read, no `fu_flash_data_poll`.

**(c) `eeprom28c_verify_page_readback` — data-landed proof only.** Add a file-static
`bool eeprom28c_verify_page_readback(firestarter_handle_t* handle, uint32_t first_index, uint32_t last_index)`.
Body: for each buffer index `k` from `first_index` through `last_index` inclusive, read through
`handle->firestarter_get_data(handle, handle->address + k)` and compare against
`(uint8_t)handle->data_buffer[k]`. On the first mismatch, emit
`LOG_ERROR_ID_BYTES(MSG_ERR_VERIFY, …, 5)` with `memory_verify_execute`'s payload order —
`{expected, observed, addr>>16, addr>>8, addr}` where `addr` is `handle->address + k`, the **failing**
address — set `handle->response_code = RESPONSE_CODE_ERROR`, and return `false`. Return `true` when
the whole window matched.

Comment it with D-08: the read-back is always on, with no opt-out. Firmware owns the truth about
whether its own page write landed, and reporting success it cannot substantiate is the defect. An
opt-out would need a `FLAG_*` value landing in lockstep across `firestarter.h` and the host's
`constants.py`, which is Phase 120's HOST-03 scope, and firmware-before-host forbids emitting it
early. Overloading `FLAG_SKIP_BLANK_CHECK` was rejected: it already carries two meanings, and a third
makes it actively misleading. Redundancy with the host's own verify pass is **accepted** and worth
stating — the host's pass proves the image landed, this one proves *this page's write cycle* landed,
and only the second can attribute a failure to a page.

**(d) Rewrite `eeprom28c_write_execute`.** Keep the per-byte loop, the `address` and `data`
derivation, the `handle->firestarter_set_data` call, and the `page_end || last_byte` flush trigger
exactly as they are. Add a `uint32_t` window-start index initialised to 0 before the loop. Inside the
flush branch, in order: call `eeprom28c_wait_for_page_write(handle, address, data)` and `return` on
false; then call `eeprom28c_verify_page_readback(handle, <window start>, i)` and `return` on false;
then advance the window start to `i + 1`.

The window bounds are `<window start> <= i < handle->data_size` by construction, so no index can
exceed `data_size` or `DATA_BUFFER_SIZE`. Comment that invariant at the window-start declaration
together with decision 2 above (why the window, not the whole physical page).

**(e) Delete `eeprom28c_wait_for_write` entirely** — both its definition (:135-155 of the pre-phase
file) and its forward declaration (:23). Plan 117-02 removed its write-init call site; this task
removes its last caller, so nothing references it. It must not survive as dead code: its whole-byte
equality compare is the conflation, and leaving it in the file invites a future editor to call it
again.
