Purpose: the shipped SDP-disable sequence goes out through `flash_util_byte_flipping` →
`fu_flash_fast_address`, which writes only `LEAST_SIGNIFICANT_BYTE` and `MOST_SIGNIFICANT_BYTE` and

compares against a command byte, which both datasheets say is never stored, so it can only pass when
the sequence was *not* recognised.

`0x0D` pinouts, proven by the Phase-116 oracle, with zero change to the shared code the bench-proven
`0x05`/`0x06`/`0x07` families depend on.

## Framing corrections that must survive into the code and the capture

- **FIX-03 is a by-product, not a separate change.** Routing the emitter through the full remap closes
  the A16-A18 upper-address staleness gap for the 18 chips at 64 KB and above automatically. Verify it
  as a by-product; do not add a separate remap change.
- **The completion signal's honesty is about what it does NOT claim.** The old check was
  anti-correlated with success because it read back a byte the datasheets say is never written. The
  replacement's virtue is that a non-responding part yields "settled DQ6" immediately and the code
  **draws no conclusion from it** (D-05) — the conclusion is deferred to the page write's own poll,
  which has a real written byte to compare against (FIX-06, plan 117-03).
- **CORRECTION 4: 66 of 84, never "all 84".** `DIP24_2816`'s 19 chips are inhibited on the `0x2AAA`
  loads, not the `0x5555` loads. `DIP32_28C512_EEPROM`'s 18 chips are inhibited 0-of-6 from a fresh
  boot and only hazardous under a stale upper-address bit. A sentence saying "the `0x5555` writes are
  inhibited" is wrong for 19 chips.

## Decisions made in this plan (delegated by 117-CONTEXT.md §"Claude's Discretion")

1. **D-06 poll shape — unconditional `delay(t_WC)` first, then a bounded toggle-bit poll.** Chosen
   against the datasheet wording and `.planning/research/SUMMARY.md`'s explicit preference order,
   whose first choice is a `t_WC` wall-clock wait ("the datasheets' own instruction, provably correct
   with no read at all") and whose second is toggle-bit I/O6 polling. The rejected alternative — using
   `t_WC` only as a deadline for the poll — provides **no timing floor at all**, because a
   non-responding part reports "settled DQ6" on the first read pair and the poll would return
   immediately; that is exactly D-04's rejected "delete the wait entirely" arm wearing a poll's
   clothing, and it lets the first page write land inside the SDP-disable internal write cycle.
2. **Poll read address — the terminal command address, behind a named constant.** AT28C256 §6.16/§6.17
   note 3 states any address location may be used but the address should not vary; a named constant
   makes the invariance structural. Reusing the sequence's own last address keeps the poll target
   self-documenting. This is *not* the deleted check: no read value is compared against a stored or
   expected byte anywhere in the completion path.
3. **The poll bound is an iteration count, never a `millis()` deadline.** Load-bearing, not
   stylistic: both SDP native suites mock `millis()` to `AlwaysReturn(0)`
   (`test_eeprom28c_sdp.cpp:88`, `test_sdp_harness.cpp:73`), so a wall-clock deadline loop cannot
   terminate under plan 117-01's deliberately non-settling case-8 mock. `flash_utils.cpp:34` uses a
   `millis()` deadline, which is why that path is never exercised by these suites.
4. **Emitter signature — an explicit three-argument function, no `sizeof`-capturing macro.**
   `flash_execute_command`'s macro form captures `handle` from the caller's scope; that implicit
   coupling is part of what this milestone is unwinding. An explicit
   `(handle, sequence, length)` function is reusable by Phase 118 (report lines wrapped around the
   call, `FLAG_SKIP_SDP_UNLOCK` gating it) and Phase 119 (a standalone `CMD_SDP_LOCK`/`CMD_SDP_UNLOCK`
   arm driving it with a different table and no payload) **without a second refactor**.
