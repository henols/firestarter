<objective>
Close FIX-05: a native test that pins each table's terminal byte, asserts SDP-disable and chip-erase
are not the same object, and cross-guards the `0x0D`-local table against the shared one it duplicates
— with a planted-violation counterpart proving the guard fails when it should.

Purpose: `FLASH_ERASE` is `AA-55-80-AA-55-10`; `EEPROM_SDP_DISABLE` is `AA-55-80-AA-55-20`. They
differ by **one nibble in one byte**, and one of them erases the chip. `test_sdp_harness` already
proves this at the *stream* level (`test_negativeA_unlock_mutated_diverges_and_matches_erase`: driving
a terminal-byte-mutated unlock table produces a stream element-wise identical to driving the real
`FLASH_ERASE` table). D-11 formalises the same hazard at the *constant* level and adds the clause that
case cannot express: that the `0x0D`-local table stays byte-identical to the shared table the harness
drives.

Output: a permanent constant-level guard on the production array, in the suite that is green by
construction across this phase's fix.

**Validation ceiling (REQUIREMENTS.md §"Validation Ceiling"):** no AT28C part is on the bench. Every
claim's subject is the code — these are assertions about two `byte_flip_t` arrays in the firmware
source, never about what a chip does when a sequence reaches it. The mitigating fact that AT28C
chip-erase requires `OE = V_H = 12 V`, a rail `0x0D` never routes, is worth stating in a comment but
must **not** be leaned on: the `0x0D` bucket spans 20+ manufacturers whose erase gating may differ
(research SUMMARY §"Critical Pitfalls" 3).
</objective>

source files do not overlap. This plan touches only `test_sdp_harness.cpp`, but it must still run after
117-03 has finished building and testing.

## Decisions made in this plan (delegated by 117-CONTEXT.md §"Claude's Discretion")

1. **FIX-05's guard lives in `test_sdp_harness`, not `test_eeprom28c_sdp`.** 117-CONTEXT.md calls this
   "the safer home" and it is: that suite is already in `[env:native]`'s `test_filter`, so the guard is
   protected independently of plan 117-01's RED→GREEN flip, and it is where the stream-level
   one-nibble negative (`test_negativeA_…`, :215-240) and the LOCK-05 table-identity case (:261-275)
   already live. The new guard is the constant-level sibling of both, next to them.
2. **The guard reads the production array, not a transcription.** A guard over a test-local copy of
   `EEPROM_SDP_DISABLE` would pin the copy and let production drift, which is the exact failure D-11
   exists to prevent. Plan 117-02 granted the array external linkage for this reason.
3. **The planted-violation counterpart reuses the table already in the file.**
   `TEST_UNLOCK_MUTATED_TERMINAL` (:206-213) is already precisely the terminal-byte mutation the guard
   must reject. Reuse it rather than adding a second copy — one planted table, two consumers (the
   existing stream negative and the new constant guard).
