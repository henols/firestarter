<objective>
Land GATE-02: correct every doc that describes behaviour which does not reach silicon, and make the always-writes reality unmissable to a community tester.

Purpose: Phase 122 is about to ask the community to run `dev test` and file reports. Under D-04 that command always writes — UV parts get at least 256 bytes, everything else gets the whole device, twice. The only thing standing between a tester and a wiped chip is what the command prints and what these docs say. Meanwhile three doc claims are now false: that firmware permanently disables SDP via a command sequence before writing (pre-fix wording), that the erase-capability derivation from electrical type is authoritative (D-12 makes it false for `0x0D`), and that the sweep is non-destructive by default.

D-16 ships `doc/lockable-proms.md` as-is with its wrong row corrected and no provenance header. That was put to the operator explicitly — it ships roughly 300 rows compiled from third-party datasheets, reading as an authoritative reference, in the milestone whose validation ceiling forbids claims about SDP behaviour on real silicon — and the operator chose this path. It is an owned trade-off, recorded here so no downstream agent re-opens it.

Output: eight corrected docs across both sub-repos, one of them newly tracked.

Repos: `/workspaces/firestarter` and `/workspaces/firestarter_app`, both on branch `v1.22-at28c-software-data-protection-lifecycle`. Commit inside each sub-repo.
</objective>
