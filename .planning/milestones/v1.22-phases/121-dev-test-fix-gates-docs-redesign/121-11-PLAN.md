<objective>
Land DEVTEST-05 and DEVTEST-06: dedup first, ask every run, comment on a duplicate, and assert the negative argv as a deny-set on both `gh` paths.

Purpose: plan `121-09` made `submit_report` unconditional, which reverses v1.21 SUB-01/SUB-02's "explicit + interactive-only; never on a bare run" contract. That reversal is only safe if the ask is preceded by a duplicate check the tester can act on, and if the `gh` argv stays permission-independent — community testers generally have neither a pre-existing label nor write access to the tracker, and `gh issue create --label` aborts before creating in that case.

Two measured facts shape the design. The dedup query's exit code is **0 for both** "found" and "not found", so keying on the exit code conflates a clean run with a missing duplicate; the parsed JSON payload is the signal. And `gh issue comment` has no label, assignee, milestone or project flag at all, so commenting is inherently permission-independent in argv terms — the meaningful negatives there are the mutating and hijacking flags.

Output: two new injected-seam `gh` functions, a restructured `submit_report`, and a deny-set negative-argv suite.

Repo: `/workspaces/firestarter_app` on branch `v1.22-at28c-software-data-protection-lifecycle`.
</objective>

Add two functions to `submit.py`, both following `submit_via_gh`'s seam discipline exactly.

**`find_prior_report(fingerprint, *, run_fn=subprocess.run)`** returning a two-element result: the matched issue's URL or `None`, plus a boolean saying whether the check actually ran. Argv, as a **list**: the `gh issue list` subcommand, the explicit repo argument set to `SUBMIT_REPO`, the author filter set to the authenticated-account token, the search term set to the fingerprint, the state filter set to all, a JSON field selection covering number, title and url, and a bounded result limit. Pass `capture_output=True, text=True, check=False` and never `shell=`.

Branch on the **parsed payload**, per the measured signal table:
- non-zero return code → the check could not run; return no-URL plus check-did-not-run. Cover `gh` absent, unauthenticated (the unauthenticated exit code is 4, not 1), and offline with the same branch.
- return code 0 with an empty parsed array → no duplicate; return no-URL plus check-ran.
- return code 0 with rows → duplicate; return the first row's URL plus check-ran.
Parse defensively: a malformed or empty stdout must degrade to the check-could-not-run branch rather than raising. Always request the JSON field selection rather than parsing `gh`'s default human table.

Its docstring must state the three-branch contract explicitly, must state that exit 0 covers both found and not-found so the exit code alone is not the signal, and must record the search-index limitation: GitHub's issue-search index is eventually consistent, so an issue filed seconds earlier may not appear — the dedup check is therefore a courtesy, never a guarantee, and duplicates that slip through land visibly grouped by fingerprint on arrival.

**`comment_via_gh(issue_url, body, *, run_fn=subprocess.run, console=None)`** returning the comment URL or `None`. Argv as a list: the `gh issue comment` subcommand, the target issue, the explicit repo argument set to `SUBMIT_REPO` (never cwd-inferred), and `--body-file -` with the body on stdin (no length cap). ## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local report → PUBLIC GitHub issue body | Anything that reaches a seam unscrubbed is published |
| host process → `gh` subprocess | An argv assembled from report data crosses into an external tool |
| community tester's account → tracker permissions | The design must work for a tester with no write access and no pre-existing label |
