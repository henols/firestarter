<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| canonical catalog → two generated artifacts in two repos | A hand-edited mirror silently diverges from the source of truth |
| firmware source → host source-scanning gates | A gate aimed at a moved or missing firmware path passes vacuously |
| message text → user's inference about chip state | A message that omits its limitation invites a false inference |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-121-49 | Spoofing | a host or user inferring a protection state from the unlock-done id alone | medium | mitigate | The format string states the limitation in the message text itself, symmetric with the lock-done message; the SDP path still never writes a response code |
| T-121-50 | Tampering | a hand-edited mirror diverging from the canonical catalog | high | mitigate | Only the meta catalog is edited; both mirrors come from the sync script; three-way `cmp` and both drift gates asserted; idempotence proven by a second run |
| T-121-51 | Spoofing | a host gate passing vacuously against a missing firmware path | medium | mitigate | Both firmware-scanning gates are run and their resolved target paths are confirmed to exist |
| T-121-52 | Repudiation | claiming firmware cleanliness with a vacuously-passing path-scoped diff | medium | mitigate | Cleanliness is proven with `git status --porcelain`, never with a path-scoped `git diff` |
</threat_model>
