<objective>
Harden the two `no_programmer_found` characterization tests so they cannot be defeated by an attached board or a saved config port.

Purpose: `.planning` memory `reference_characterization_no_programmer_tests_fail_with_live_board.md` records these two tests going RED with a live board attached. Today each does `monkeypatch.setattr("serial.tools.list_ports.comports", lambda: [])` — but `SerialCommunicator._list_potential_ports(preferred_port)` appends `preferred_port` **before** it ever calls `comports()`, and `find_and_connect` sources that from `config_manager.get_value("port")`. So a machine with a saved port in `~/.firestarter/config.json` still gets a non-empty candidate list and the test attempts a real connection. RESEARCH A5 records that both tests *passed* in the research session with three devices attached, so the flake is intermittent — D-19 must therefore not be validated by "it passes now".

Output: both tests patched at the real seam, each carrying a negative-call assertion that no port was opened.

Repo: `/workspaces/firestarter_app` on branch `v1.22-at28c-software-data-protection-lifecycle`. Test-only; no production source changes.
</objective>

Prove the defeat vector, then close it.

**Reproduce first.** Write a throwaway probe (do not commit it) that sets a `port` value in a temporary config and runs the existing `test_no_programmer_found_read` logic with only `comports` patched, showing `_list_potential_ports` returns a non-empty list. If the vector does not reproduce on this machine, say so plainly — the hardening is still correct, because a monkeypatch a real device or a saved config value can defeat is a weak monkeypatch, and RESEARCH A5 records the flake as intermittent.

**Patch the real seam.** In both tests, replace the `serial.tools.list_ports.comports` monkeypatch with a patch of `firestarter.serial_comm.SerialCommunicator._list_potential_ports` returning an empty list, applied via `monkeypatch.setattr` with `raising=True` so a future rename of that method fails the test loudly instead of silently doing nothing. Keep the `comports` patch as well — belt and suspenders, and it documents the original intent — but the load-bearing patch is the `_list_potential_ports` one.

**Add the negative-call assertion to each test.** Patch `serial.Serial` (as resolved inside `firestarter.serial_comm`) with a `MagicMock` and assert it was **never called** after the operation returns `False`. The load-bearing assertion is that no port was opened; the `result is False` assertion alone cannot distinguish "no programmer found" from "found a real board and it refused". This is the same discipline as `read_hardware_revision_value.assert_not_called()` in the absent-chip work.

**Record the reason in-source.** Update the section header comment above both tests to state: the monkeypatch target is `_list_potential_ports`, not `comports`, because `_list_potential_ports` prepends `preferred_port` (from `config_manager.get_value("port")`) before consulting `comports()`, so a saved config port on an operator bench defeats a `comports`-only patch; and that the load-bearing assertion is the never-opened-port negative, not the `False` return.

Keep `EpromDatabase(skip_local_override=True)` in both tests exactly as it is — that is a standing phase-36 rule and unrelated to this fix.

Commit: `test(121-04): patch the real port-enumeration seam in the no-programmer-found characterizations (D-19)`.
