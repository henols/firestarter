<objective>
Land D-13: warn and proceed when `--skip-erase` is passed on a chip whose family has no erase operation.

Purpose: clearing the erase-capability bit for `0x0D` (plan `121-08`) does not stop `--skip-erase` being accepted and silently inert on those parts. That is the residual half of Phase 120's deferred flag-surface honesty item. HOST-02's D-18 already established the exact response for a vacuous flag on this codebase — one spoken line naming the observed protocol, then a normal write, with the bit still emitted so batch scripts keep producing identical frames. This applies that template to the second vacuous flag.

RESEARCH C-8 splits CONTEXT D-13's stated scope: the runtime warning belongs on `--skip-erase` alone. The blank-check flag has skipped only the blank check since Phase 92, so a "no erase to skip" line on it would be factually wrong — and it is genuinely required on a non-blank AT28C precisely because no erase exists to make the part blank. That statement is a GATE-02 documentation obligation (plan `121-13`), not a runtime warning.

Output: one new conditional arm in `write`, one new test module.

Repo: `/workspaces/firestarter_app` on branch `v1.22-at28c-software-data-protection-lifecycle`.
</objective>
