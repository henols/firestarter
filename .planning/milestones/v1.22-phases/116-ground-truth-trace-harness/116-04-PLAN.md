  <action>
Write a host-side checker that fails when a logging call appears inside the `0x0D` SDP
command-sequence timing window.

**Scope definition — structural, never a bare grep.** Locate `eeprom28c_write_init` by its
declaration in the source text, brace-match its body, and within that body define the window as the
region beginning at the first line matching a **command-emit anchor** and ending at the first
subsequent line matching a **completion-wait anchor**. Hold both anchor sets as module-level
constants (a small tuple of regexes each) with a comment stating that Phase 117 replaces the emitter
and will need to add its anchor here. On today's tree the emit anchor matches the
`flash_execute_command(EEPROM_SDP_DISABLE)` call site and the wait anchor matches the
`eeprom28c_wait_for_write(` call that immediately follows.

**Fail closed** — this is the property that stops a later rename from silently hollowing the gate:
- source path missing or unreadable → non-zero exit with a named error
- `eeprom28c_write_init` not found → non-zero exit
- zero emit anchors matched, or zero wait anchors matched after the emit anchor → non-zero exit with
  a message telling the maintainer to add the new anchor rather than delete the gate

A bare substring grep is explicitly wrong here: `eeprom_28c.cpp` carries prose comments describing
the sequence and its timing, and the sibling checkers in this repo record (Phase-109 SAFE-02,
Phase-110) that substring scans false-positive on exactly that. `ast` does not apply because the
target is C++, so the extraction must be brace-matched text handling, and it must strip `//` and
`/* */` comment spans from the window before applying the deny list — a comment mentioning a logging
macro is not a call.

**Deny list:** the logging macro invocations actually used in this codebase (read `logging_id.h` for
the real names, do not guess a prefix). A match inside the window is a violation.

**Out-of-window control:** `eeprom28c_wait_for_write` genuinely contains a logging call and is
outside the window; the checker must not flag it. Prove this in the paired test.

Follow the analog's contract exactly: module docstring stating this is a genuinely-populated
structural scan and not a hollow declared-empty detector, naming the paired pytest as the
anti-hollow proof; documented exit codes `0` clean (PASS line printed) and `1` violations found
(per-violation summary printed with line numbers). Env-override seam named `FIRESTARTER_SDP_SRC`,
defaulting to the real `firestarter/src/proms/eeprom_28c.cpp` path derived relative to the tool's own
location, mirroring the analog's `FIRESTARTER_DEVTEST_SRC`.

Must pass `ruff check` and `ruff format --check` against the py3.9 CI target.
