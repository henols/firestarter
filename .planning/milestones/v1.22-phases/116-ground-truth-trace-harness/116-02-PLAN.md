<objective>
Generate the `bus_config_t` ground truth the Phase-116 trace suites assert against, from the host's
own derivation path (D-08), commit it as a `DO NOT EDIT` header in the firmware sub-repo (D-10), and
guard it with a regenerate-and-diff host pytest carrying the established `FW_ABSENT` skipif (D-11).

four milestones (Phase 94 `page_size`, Phase 98 `rw-pin`); a hand-typed literal would stale silently
and the oracle would agree with itself while diverging from the wire.

Output: a generator, a committed generated header, and a drift gate with a non-vacuity leg.

**Zero production-code risk fence:** nothing under `firestarter/src/`, `firestarter/include/`, or
`firestarter_app/firestarter/` is modified. This plan writes only `tools/`, `tests/`, and one file
under `firestarter/test/`.
</objective>

Write a generator that derives, validates and emits the `bus_config_t` ground truth for the five
representative `0x0D` chips selected under D-09.

**Representative set (D-09 — one per pinout, plus a second `DIP32_28C512_EEPROM` size band):**
`AT28C256` (DIP28_28C256, 32768 B), `AT28C64` (DIP28_28C64, 8192 B), `AT28C16` (DIP24_2816, 2048 B),
`AT28C010` (DIP32_28C512_EEPROM, 131072 B), `AT28C040` (DIP32_28C512_EEPROM, 524288 B). Hold this
list as an authored module constant with a comment naming D-09 and the reason for the second DIP32
band: that pinout alone spans 64 KB to 512 KB, `AT28C010` and `AT28C040` share an **identical**
`bus_config`, so the band is distinguished by `mem_size` and prior register state, not by
`bus_config`.

**Derivation (D-08):** import `EpromDatabase` from `firestarter.database`, call `get_eprom(name)`
then `convert_to_programmer(...)` for each chip, and translate the resulting programmer dict into
`bus_config_t` fields exactly the way `json_parser.c`'s `parse_bus_config` does:
`address_lines[j] = bus[j]`; `address_mask |= 1 << bus[j]`; `matching_lines` is the first index `j`
where `bus[j] != j`, falling back to `len(bus)` when every line matches; the sentinel
`address_lines[len(bus)] = 0xFF` when `len(bus) < ADDRESS_LINES_SIZE` (20); `rw_line` from the
pinout's `rw-pin`; `vpp_line = 0xFF`; `static_high_mask = 0`. Do **not** reimplement
`convert_to_programmer` — import and call it.

**Validate before emit** — the load-bearing ordering copied from the analog. Raise `ValueError` and
write nothing on any violation:
- every chip resolves and yields a non-empty `bus` list, and every bus line is below 20
- `rw-pin` is present for all five; no `vpp-pin` and no `static-high-pins` on any of the four
  pinouts (this is also SDP-F8's observable — record it in a comment, do not act on it)
- the derived values equal the independently measured values from RESEARCH §F5 / §Code Examples, in
  the fixed order AT28C256, AT28C64, AT28C16, AT28C010, AT28C040:
  `matching_lines` = 14, 13, 11, 16, 16; `rw_line` = 14, 14, 11, 20, 20;
  `address_mask` = 0xBFFF, 0x1FFF, 0x07FF, 0xFFFF, 0xFFFF. A mismatch means `pinouts.json` moved and
  the trace goldens are stale — fail loudly rather than emit fresh ground truth silently.
- the two DIP32 rows have byte-identical `bus_config` values (the D-09 premise)

**Emit** to `firestarter/test/native/avr/_shared/sdp_bus_config.h`, matching the in-tree convention:
banner first line `/* DO NOT EDIT -- generated by tools/gen_sdp_bus_config.py`, a second banner line
naming `firestarter_app/firestarter/data/pinouts.json` as the input to re-run after, blank line,
`#pragma once`, `#include <stdint.h>` and `#include "firestarter.h"` (needed for `bus_config_t`;
the header must **not** re-declare that struct), `#define SDP_BUS_CONFIG_COUNT 5`, a local
`sdp_bus_config_row_t` typedef carrying `const char* chip_name`, `const char* pinout_name`,
`uint32_t mem_size` and a `bus_config_t bus_config`, then
`static const sdp_bus_config_row_t SDP_BUS_CONFIGS[]` with one row per chip in the fixed order
above. Deterministic output: fixed chip order, no timestamps, LF endings via
`write_text(encoding="utf-8", newline="\n")`.

**Argparse:** `--target` (defaulting to the sibling-repo path; mandatory because the drift gate
points it at a temp file) and `--check` (derive, validate, render, compare against the existing
target, print a diff summary and return non-zero on mismatch without writing). Exit codes mirroring
the analog: `0` ok, `1` validation failed, `2` a required chip or pinout not found.

The generator must pass `ruff check` and `ruff format --check` against the py3.9 CI target. The
devcontainer runs Python 3.12; `pyproject.toml` pins `target-version = "py39"` and
`requires-python = ">=3.9"`, so avoid 3.10+ syntax.
