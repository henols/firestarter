<objective>
Pin two facts the rest of the milestone leans on, as executable host tests: (a) the `0x0D` identity
gate is dead across all 84 chips, and (b) the unlock command table used by the trace suites is the
same table the shipped handler uses.

Purpose: TRACE-05 turns "the chip-id check never fires on this family" from a read-and-believe claim
into a machine-checked one, and gives `CLOSE-01`'s "84-chip count unchanged" requirement a home six
phases early. The table-parity gate closes RESEARCH §F6's transcription gap: `EEPROM_SDP_DISABLE`
has internal linkage so no test can link it, which would otherwise leave the trace suites asserting
against an unguarded hand-copy.

Output: two independent host pytest modules, each with a non-vacuity leg.

**Zero production-code risk fence:** this plan writes only under `firestarter_app/tests/`. It reads
`chip_database.json` and `eeprom_28c.cpp`; it modifies neither. The chip database must stay
byte-identical.
</objective>

Write a host pytest module pinning the `0x0D` identity-gate facts as machine-checked invariants.

Read `firestarter_app/firestarter/data/chip_database.json` directly (not through `EpromDatabase`, so
the test measures the shipped data rather than the loader's interpretation). The structure is
`{manufacturer: [chip, ...]}` and the fields live in a nested `programming` object — iterate
manufacturers, then chips, and select on `chip["programming"]["algorithm"] == 13`. A top-level scan
finds nothing and would pass vacuously.

Assert **both** halves — RESEARCH §F9 is explicit that either alone is hollow in one direction:
- **count:** the selected list has exactly **84** entries, with an assertion message naming TRACE-05
  and explaining that a count change means a chip was added to or removed from the `0x0D` bucket and
  the trace-coverage assumptions need re-checking. This is also `CLOSE-01`'s "84-chip count
  unchanged" fact, landed early.
- **per element:** every selected entry has `programming.chip_id_check` exactly `False` (identity
  comparison against `False`, not merely falsy), with a failure message listing the offending chip
  names.

Add a third assertion pinning the companion fact that makes the gate provably dead rather than
merely disabled: every selected entry's `programming.chip_id_value` is the zero sentinel
(`"0x00000000"`). Firmware skips the identity branch when `handle->chip_id` is 0
(`eeprom_28c.cpp:95`), so this is the field that actually determines the behaviour.

Add a **non-vacuity** test in the same module: build a synthetic in-memory DB dict containing one
`algorithm == 13` chip with `chip_id_check: True`, run the same selection-and-assertion helper over
it, and prove the helper raises. Factor the selection and the per-element check into a small module
helper both tests call, so the non-vacuity leg exercises the same code the real test does — not a
parallel reimplementation.

**This module must NOT carry the `FW_ABSENT` skipif** (RESEARCH §F9). It needs no firmware checkout;
adding the skipif would make the DB invariant silently skip in host-only CI. Keep it in its own file
so the skipif used by the sibling drift gate cannot leak into it.

Open the module docstring with the coverage-map convention used by the analog, enumerating what each
test proves including the non-vacuity leg.

Close RESEARCH §F6's transcription gap by pinning the shipped `0x0D` unlock table to a second
in-tree source, rather than to a hand-typed test copy.

The key structural fact discovered while planning: `flash_utils.h` declares
`FLASH_DISABLE_WRITE_PROTECTION` as the same six `{address, byte}` pairs as `eeprom_28c.cpp`'s
`EEPROM_SDP_DISABLE`, and because it lives in a **header** the firmware trace suites can include and
drive it directly — no transcription at all. This test guards the remaining risk: that the two
in-tree copies drift apart.

Write a host pytest module that:

1. Parses the six `{address, byte}` initialiser pairs out of `EEPROM_SDP_DISABLE` in
   `firestarter/src/proms/eeprom_28c.cpp` using a brace-scoped extraction (locate the named
   declaration, then read pairs until the closing brace) rather than a bare file-wide regex — this
   file's own comments describe the sequence in prose and a loose pattern false-positives on them
   (the Phase-109 SAFE-02 / Phase-110 lessons recorded in STATE.md).
2. Parses the same way out of `FLASH_DISABLE_WRITE_PROTECTION` in `firestarter/include/flash_utils.h`.
3. Asserts the two ordered pair lists are equal, with a failure message stating that the firmware
   trace suites drive the `flash_utils.h` table on the assumption it equals the shipped `0x0D`
   table, and that a divergence invalidates every Phase-116 trace claim.
4. Asserts a second, distinct fact that guards the one-nibble chip-erase hazard the milestone cares
   about (FIX-04's precursor): the parsed unlock table's terminal byte differs from `FLASH_ERASE`'s
   terminal byte while the first five pairs are identical. The failure message must name the hazard
   explicitly.
5. **Non-vacuity leg:** point the parser at a temp copy of `eeprom_28c.cpp` with one pair's byte
   altered and prove the parity assertion fails. Use an env-override seam named `FIRESTARTER_SDP_SRC`
   with a default of the real path, mirroring `check_dispatch.py`'s `FIRESTARTER_DB_FILE` idiom. The
   seam must **fail closed** — a missing or unreadable path is an error, never a silent pass.

Carry the `FW_ABSENT`-shaped skipif keyed on the presence of `eeprom_28c.cpp`, so the module skips
cleanly in standalone `firestarter_app` CI. This is the one place in the phase where the skipif is
correct; the DB invariant in Task 1 must not have it.

Must pass `ruff check` and `ruff format --check` against the py3.9 CI target.
