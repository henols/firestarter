## 1. SAFE-01 Static Proof — Host `0x00`-Silence in the Mode-Transition Window

### 1.1 Scope of the Proof

SAFE-01 is scoped to the **Phase 51 command-channel case**. Under Phase 50 (data-path framing
only), the firmware is in `com_mode=true` throughout any data-block transfer —
`rurp_set_programmer_mode()` is called only when an operation begins, and at that point the
command has already been received and `com_mode` transitions back to `true` before data blocks
are exchanged. Therefore the SAFE-01 `0x00` bus-aliasing concern is moot for Phase 50.

It becomes load-bearing when the host actively emits a `0x00` COBS frame-boundary byte on
the host→fw command direction — which is exactly what Phase 51 introduces. This proof is
written for that case.

### 1.2 Firmware Half — `com_mode` Gate

The firmware gate is defined in `uno_rurp_shield.cpp` lines 85-97. The `rurp_log_id` strong
override reads:

    if (com_mode) { _firestarter_emit_frame(...); }

The same gate covers `rurp_log_id_wide` at lines 92-97. While `com_mode = false`, the
firmware emits NO bytes on the serial line. `rurp_set_programmer_mode()` (lines 70-74 of
`uno_rurp_shield.cpp`) sets `com_mode = false` first, then calls `rurp_serial_end()` which
disables the UART and introduces a 5 ms delay. With the UART disabled, the Uno physically
cannot receive bytes into the RX ring buffer while `com_mode = false`.

`rurp_set_communication_mode()` (lines 44-67 of `uno_rurp_shield.cpp`) restores the state:
it sets PD0 high (pull-up, not a false UART start bit), then calls `rurp_serial_begin()`
to re-enable the UART, and finally drains any bytes that leaked into the RX ring buffer
via `while (SERIAL_PORT.available()) SERIAL_PORT.read()` before setting `com_mode = true`.

Firmware-half conclusion: while `com_mode = false` the firmware cannot receive a byte that
it would interpret as a COBS frame delimiter. This is architecturally guaranteed.

### 1.3 Host Half — Three Sub-Claims

The host-half proof requires three sub-claims, all of which are confirmed by static analysis
(cf. v1.9-COBS-DECISION §5 Q2 — "explicit handling proof" requested):

**Sub-claim A — pyserial `flush()` guarantees physical TX before return.**

`send_bytes()` in `serial_comm.py` at line 141 calls `self.connection.write(data_bytes)`
followed by `self.connection.flush()` at line 141. The pyserial `flush()` method maps to the
underlying OS serial port's drain/flush operation (POSIX `tcdrain()` on Linux, which blocks
until all output bytes have been physically transmitted to the device). At 250000 baud a
200-byte COBS-framed command takes approximately 8 ms; `flush()` blocks for that window.
After `flush()` returns, all bytes including the trailing `0x00` delimiter have been
physically transmitted. The host then enters the response-reading loop (`_read_and_parse_lines`
via `expect_ack` or `get_response`) and does NOT transmit again until a response arrives.
This sub-claim is confirmed.

**Sub-claim B — the COBS `0x00` delimiter is written in the same `send_bytes` call as the
frame body.**

Under the current protocol `send_json_command()` (lines 155-159 of `serial_comm.py`) calls
`json.dumps()` and passes the result to `send_string()`, which calls `send_bytes()`. Phase 51
will extend `send_json_command()` to wrap the payload in a COBS frame before sending.
This ADR mandates as a contract constraint that the entire framed command — payload,
CRC8 byte, COBS-encoded body, and trailing `0x00` delimiter — MUST be assembled into a
single `bytes` object and passed to `send_bytes()` as one call. A split where the delimiter
is emitted in a subsequent `write()` call is prohibited. This is the atomic-write mandate
(see Section 3 Frozen Frame Contract). With this mandate in place, the `flush()` at the end
of `send_bytes()` covers all bytes including the delimiter, leaving no split-write window.
Sub-claim B is confirmed by design contract.

**Sub-claim C — the firmware consumes the command payload (including the COBS `0x00`
delimiter) from the RX buffer before `rurp_set_programmer_mode()` is called.**

Under Phase 51's framing design, the firmware's command-channel decoder (which will replace
the `{`-peek path at `firestarter.cpp` lines 162-172) will read bytes from the serial RX
buffer byte-by-byte until it encounters the `0x00` frame delimiter. The frame decoder must
consume the entire frame, including the terminating `0x00`, before handing the decoded
payload to the JSON parser. `rurp_set_programmer_mode()` is called inside `_execute_operation()`
at `operation_utils.cpp` line 291, which is reached via `op_execute_function(configure_memory,
handle)` called from `parse_json()` (line 86 of `firestarter.cpp`), which is called after the
frame is decoded. Therefore the `0x00` byte is removed from the RX buffer by the frame
decoder before `rurp_set_programmer_mode()` is called. This ADR mandates as a Phase 51
design constraint that the firmware frame decoder MUST fully consume the frame including its
delimiter before calling the JSON parser. Sub-claim C is confirmed by design contract.

Residual case: if the host's `0x00` byte somehow arrived in the RX buffer during the
`rurp_set_communication_mode()` drain window (after UART re-enable but before parsing
resumes), it would be drained by `while (SERIAL_PORT.available()) SERIAL_PORT.read()` and
treated as a stale byte. This is safe because the drain loop runs before `com_mode = true`,
so the command parser cannot see those bytes.

### 1.4 SAFE-01 Proof Outcome

All three sub-claims are confirmed. The host cannot deliver a `0x00` COBS frame-boundary byte
that the firmware would interpret as a frame delimiter while `com_mode = false` or during
the mode-transition window. COBS `0x00` is NOT disqualified on bus-aliasing safety grounds.

**Outcome: COBS is eligible — the proof is conclusive. SLIP is not required under D-04.**

This closes v1.9-COBS-DECISION §5 Q2 ("if this proof is unavailable, SLIP is the safer
choice" — the proof is available) and feeds the safety criterion in the evidence matrix below.

## 2. Scored Evidence Matrix

All four criteria are scored on a 3-point scale: 3 = strong advantage, 2 = acceptable /
near-parity, 1 = disadvantage. Neutral posture per D-01; no criterion is pre-weighted per D-02.

| Criterion | COBS `0x00` | Score | SLIP `0xC0` | Score |
|-----------|-------------|-------|-------------|-------|
| **Safety / bus-aliasing risk class** | Risk proven low by SAFE-01 static proof (Section 1). The `0x00` delimiter can only appear while `com_mode=true`; the firmware-half gate is architectural; the host-half proof is confirmed via pyserial `flush()` guarantee, atomic-write mandate, and Phase 51 frame-decoder consumption contract. | 3 | No risk — `0xC0` never appears as an unescaped bus-driven byte on the data bus (PD0–PD7). Sidesteps the `0x00` concern entirely. | 3 |
| **Provable byte-exactness** (ease of round-trip + fault-injection proof) | By construction, no `0x00` byte can appear in the COBS-encoded body; the frame boundary is unambiguous. A COBS-encoded payload is self-describing via run-length blocks — the decoder can verify the round-trip by re-encoding. Fault injection: corrupting a run-length code byte is detectable (the CRC8 covers the raw payload, not the COBS overhead). Slight advantage: `0x00`-free-body invariant eliminates one class of false-positive delimiter. | 3 | Round-trip is unambiguous when implemented correctly. Two special bytes (`0xC0`, `0xDB`) must be escaped; any byte in the payload can be represented. Fault injection: a single-bit corruption of an escape byte (`0xDB`) can produce a mis-decoded payload byte and the correct next frame boundary — CRC8 catches this. Marginally more transformation steps in the decoder (unescape pass after delimiter detection). | 2 |
| **Implementation simplicity** (smallest auditable dual-repo diff) | ~40 firmware + ~30 host lines. Encoder must track run-start position and run length; emits a 1-byte run-length header before each non-zero run. 3 local variables on stack (~6 B). Decoder must accumulate a run count and replay. Slightly more state than SLIP. | 2 | ~20 firmware + ~20 host lines. Pure two-byte escape table: replace `0xC0`→`0xDB 0xDC` and `0xDB`→`0xDB 0xDD` on encode; reverse on decode. No run-length state. Decoder: scan for `0xC0` (delimiter), unescape `0xDB` sequences. Simpler loop structure, fewer edge cases to audit. | 3 |
| **Overhead** | At most +1 byte per 254-byte run. For a 512 B Uno frame: maximum +3 overhead bytes (3 run-length headers). For a blank EPROM payload (all `0x00`): maximum +4 bytes (each byte becomes a `0x01` run-length + the final delimiter). Deterministic, bounded. | 3 | Worst case 2× expansion on an all-`0xC0` payload. Typical EPROM binary payloads have roughly equal `0x00` and `0xC0` byte frequencies (Assumption A3) — in practice overhead is near zero. Near-tie for real payloads; COBS's bound is tighter in the worst case. | 2 |
| **Aggregate** | | **11 / 12** | | **10 / 12** |

**Matrix summary:** COBS scores 11/12 vs SLIP 10/12. The safety criterion is a tie (both score 3
after the SAFE-01 proof). COBS edges ahead on byte-exactness (unambiguous `0x00`-free invariant)
and overhead (deterministic bounded expansion). SLIP edges ahead on implementation simplicity.
The aggregate ranking favors COBS. This result, combined with the SAFE-01 proof outcome
(Section 1), produces the decision in Section 3.

This closes v1.9-COBS-DECISION §5 Q3 (SLIP vs COBS selection).

## 3. Decision Statement

**Selected mechanism: COBS `0x00` (streaming hand-rolled, per v1.9-COBS-DECISION §4.3).**

The scored matrix ranks COBS highest in aggregate (11/12 vs SLIP 10/12) across all four
criteria (safety, byte-exactness, simplicity, overhead). The SAFE-01 static proof (Section 1)
confirms that the `0x00` bus-aliasing risk is mitigated — COBS is not disqualified on safety
grounds. The proof is conclusive, so D-04 (inconclusive → SLIP wins) does not apply. COBS is
selected because the scored matrix ranks it highest on byte-exactness and overhead, with safety
at parity after the proof, and simplicity as the only criterion favoring SLIP.

## 4. Frozen Frame Contract (D-06)

### 4.1 Delimiter and Encoding Scheme

**Delimiter byte:** `0x00`

**Encoding scheme:** Streaming COBS (Consistent Overhead Byte Stuffing) run-length encoding.
The payload bytes are scanned for `0x00` bytes; each run of non-zero bytes (up to 254 bytes)
is preceded by a 1-byte run-length code (run_len + 1). A `0x00` payload byte terminates the
run and is implicit; it emits a run-length code of 1 and no data bytes for that `0x00`. The
encoded frame body contains no `0x00` bytes by construction. The frame is terminated by the
delimiter byte `0x00`. RAM cost: 3 local variables (~6 bytes stack). Reference algorithm:
v1.9-COBS-DECISION §3 streaming reference snippet.

The COBS scheme applies to the raw payload (including the appended CRC8 byte — see Section 4.3).
The encoded body is transmitted byte-stream to `SERIAL_PORT`; the full frame including the
trailing `0x00` delimiter MUST be assembled as a single `bytes` object on the host and passed
to `send_bytes()` in one call (atomic-write mandate from SAFE-01 sub-claim B). Splitting the
delimiter into a second write call is forbidden.

### 4.2 Scope of Framing

The new framing applies to:
- Framing 2 (host→fw data block): Phase 50
- Framing 3 (fw→host data block): Phase 50
- Framing 1 (host→fw JSON command): Phase 51

Framing 4 (fw→host log/telemetry: `[0xAA55AA55][len_u16][id][params][crc8][0x0A]`) is
**UNCHANGED in v1.10**. It already self-delimits via the magic preamble, length field, and
`0x0A` re-sync anchor. The `_firestarter_emit_frame` path in `rurp_serial_utils.cpp` and
the `[0xAA55AA55]` log/telemetry format are not modified.

### 4.3 Data-Block Frame Layout (Phases 50+)

Replaces the current `[len_u16 big-endian][xor_checksum][payload]` layout documented in
`rurp_serial_utils.cpp` lines 44-93.

| Field | Position | Width | Encoding | Value / Notes |
|-------|----------|-------|----------|---------------|
| COBS-encoded body | First byte of frame through delimiter-preceding byte | Variable | COBS run-length encoding | The concatenation of `[raw payload bytes]` and `[CRC8 byte]` encoded as COBS; contains no `0x00` bytes by construction |
| CRC8-CCITT byte | Last byte of raw pre-encoded payload (before COBS encoding) | 1 byte | CRC8-CCITT poly 0x07 seed 0x00 no reflection no final XOR | Computed over the raw payload bytes only; appended after payload, before COBS encoding; the CRC byte itself is subject to COBS encoding |
| Frame delimiter | After the last COBS-encoded byte | 1 byte | Literal `0x00` | Frame boundary marker; emitted as a single byte in the same `send_bytes` call as the frame body (atomic-write mandate) |

**Length prefix: REMOVED.** The 2-byte `len_u16` big-endian length prefix present in the
current framing is removed. The COBS delimiter provides unambiguous frame boundaries without
a length count. Retaining `len_u16` alongside the delimiter would undermine the resync goal —
corruption of `len_u16` is the exact failure mode the new framing eliminates. The decoder
accumulates bytes until `0x00` is received, then decodes the COBS body, checks CRC8, and
hands the payload to the consumer. No length field is needed.

**CRC8 replaces XOR:** The current data-block path (`rurp_serial_utils.cpp` lines 44-93)
uses an XOR checksum. Per D-05 (v1.9-COBS-DECISION), CRC8-CCITT poly 0x07 is retained
as the integrity layer. Phase 50 migrates the data-block path from XOR to CRC8. The
log/telemetry path already uses CRC8 and is unchanged.

### 4.4 CRC8-Before-Parse Security Mandate (V5 — Phase 51 Design Constraint)

The firmware MUST verify CRC8 BEFORE handing the decoded frame payload to the JSON parser
(V5 Input Validation — T-49-01 from the Phase 49 threat register). A frame that passes the
COBS delimiter check but fails CRC8 verification is discarded; its bytes do NOT reach
`json_parser.c`. The current `{`-peek command path (`firestarter.cpp` lines 162-172) has no
such integrity check — it passes bytes directly to the JSON parser. Phase 51 must replace
this with a framed-command decoder that enforces CRC8-before-parse.

This is a mandatory Phase 51 design constraint inherited from this frame contract.

### 4.5 Streaming-Encodable / Uno RAM Confirmation

Both the COBS encoder and decoder operate streaming with no second ~512 B encode buffer.
The encoder reads from `data_buffer[512]` (already on-stack during EPROM operations) and
emits COBS bytes directly to `SERIAL_PORT.write()` without materializing the encoded form.
RAM overhead is ~6 bytes stack (3 local variables: `i`, `run_start`, `run_len`). This fits
the ~545 B free-RAM Uno ceiling (measured 2026-06-01 at 1503/2048 B used). No second buffer;
no re-chunking; Uno constraint satisfied per D-04.

The CRC8-CCITT poly 0x07 table is retained unchanged in both repos (D-05): PROGMEM table
at `rurp_serial_utils.cpp` lines 109-131 (firmware); `_build_crc8_table()` at `frame_parser.py`
lines 28-44 (host).

All four files in the lockstep dual-repo mandate must be modified for Phase 50 and Phase 51.

| File | Sub-repo | Phase | Change Required |
