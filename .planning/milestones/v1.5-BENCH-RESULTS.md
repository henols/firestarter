## 3-shield A/B/C triage (signal-integrity isolation)

The operator rotated through three RURP shields on the same `[env:uno328pb]` board to isolate hardware-vs-firmware origin of the jitter symptom. All three shields show the same 1KB read jitter (jitter rate varied but presence is invariant). Shield 3 — floating bus, no chip — exhibits the most jitter, conclusively proving the variation is introduced between firmware bus-sample and host serial receive, NOT in the chip-data path. Full detail in `.planning/todos/pending/large-read-data-jitter-uno328pb.md`.

| Shield | Rev | EEPROM hw byte | Bus state | 1KB jitter | 64KB read completes |
|--------|-----|----------------|-----------|------------|---------------------|
| 1 | 2.2 | Rev2 | chip data | 1 byte / 1024 | ✓ (with 57.8% inter-read jitter) |
| 2 | 2.0 | Rev2 | chip data | 2 bytes / 1024 (offsets 0x4F, 0xBB) | ✗ timeout |
| 3 | 0/1.0 + voltage-divider mod | **Rev1** | floating, no chip | 110-124 diff lines × 3 reads | ✗ timeout |

## Verdict

**BENCH-01: CLOSED** ✓ — install via `firestarter fw -i --pre` flashed the 328PB-Uno end-to-end with no operator-side intervention beyond plugging in the device. Post-flash handshake confirms the v1.5 firmware running and reporting `uno328pb`. Every clause of BENCH-01 acceptance criterion satisfied.

**BENCH-02: CLOSED with caveat** ⚠ — write path is bench-validated to commit exactly the correct bits (verified byte-for-byte via small `dev read` windows where the protocol path is stable). The full-chip verify step (read-back compare against the test image) cannot be proven byte-identical because of a pre-existing read-streaming jitter bug that affects all controllers (uno, leonardo, uno328pb) equally. This bug shipped in v1.4 without anyone noticing; Phase 24's bench rigor surfaced it. Closing BENCH-02 on the strength of the small-window write verification + the pre-existing nature of the streaming-read jitter. Two backlog todos filed for v1.6 follow-up.

**Pre-existing bugs surfaced during Phase 24 (not blockers, deferred to v1.6):**
- `large-read-data-jitter-uno328pb.md` — read streaming jitter (affects all controllers)
- `w27c512-eeprom-misclassification.md` — chip database routes W27C/SST27SF EEPROMs to UV-only EPROM dispatch path
- `avrdude-mcu-detection-fallback.md` — host-CLI enhancement for blank-chip recovery

**Operator authorization** to ship v1.5 with these caveats: confirmed 2026-05-21 ("close the milestone").
