<objective>
Resolve the headline VAL-06 SRAM no-op question with a DEFINITIVE bench verdict using the FM1608
two-pattern method — classifying `configure_sram` as a table-stakes-PASS or as a FIX-01
correctness defect. This is the Phase-73 HARD GATE (D-09): VAL-06 must reach a definitive verdict,
never SKIP-deferred; an inconclusive result keeps the phase open.

FM1608 is FRAM (non-volatile), so the volatility confound disappears (D-05) — a plain
write then read-back is electrically clean. The known FM1608 byte-0 write bug is the only
confounder, and it is separated out by per-byte analysis (D-08), NOT fixed (it is a parked,
out-of-v1.13-scope debug item). The standard `dev validate-family sram` runner is AVOIDED because
write_cycle_eprom calls erase_eprom first and FRAM has no erase step (RESEARCH Pitfall 3 / sram.cpp
no-op); this plan uses `firestarter write FM1608 <file> -b` + `firestarter read FM1608` to perform
the two-pattern sequence manually, then records the verdict into the matrix artifact.

Purpose: Hand Phase 74 FIX-01 a definitive verdict (defect routes to implement real SRAM
read/write; PASS closes FIX-01 not-needed with evidence). Output: a definitive VAL-06 verdict with
per-byte evidence plus a recorded sram Tier-3 cell.
</objective>
