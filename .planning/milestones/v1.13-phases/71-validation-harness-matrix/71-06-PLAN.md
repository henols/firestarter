<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| runner → cycle methods → hardware | The runner orchestrates real write/read on a seated chip (bench, Phase 73); a wrong oracle masks a real divergence |
| board identity → write-cell attempt | uno328pb must never attempt a program/write (999.2 brownout); a wrong verify board corrupts the PASS oracle |
| emitted artifact | Results are EMITTED by the runner, never accepted as input |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-71-VACUOUS | Spoofing | a PASS cell from a verify that cannot fail | mitigate | Mandatory negative control classifies a deliberate mismatch as FAIL (test_negative_control); a green cell is provably non-vacuous (D-08) |
| T-71-WRONGBOARD | Tampering | a non-Leonardo verify read producing a false PASS | mitigate | Leonardo-only authoritative PASS; other boards record advisory not PASS (v1.9 read-bug oracle corruption avoided) |
| T-71-UNO328 | Damage | uno328pb attempting a program/write (brownout 999.2) | mitigate | Hard-coded N/A for uno328pb write/program cells; cycle method never invoked (test_uno328pb_na) |
| T-71-STALECAL | Tampering | stale R1 calibration (999.1) yielding a wrong-VPP write | mitigate | r1 ≈ 270000 ±25% precondition aborts the write path before any cycle (test_r1_precondition_aborts) |
| T-71-FORGE | Tampering | a forged validation-matrix.json claiming PASS for an untested cell | mitigate | Artifact is emitted by the runner only; never read back as input; codegen reads only the authored spec (RESEARCH §Security Domain) |
| T-71-SC | Tampering | npm/pip/cargo installs | accept | No package installs; reuses Click + existing ops methods (D-10). No legitimacy checkpoint needed. |
</threat_model>
