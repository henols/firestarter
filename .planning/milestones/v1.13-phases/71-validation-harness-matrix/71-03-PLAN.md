<objective>
Extend `check_dispatch.py` (D-09 / HARN-04) with per-family VPP dispatch invariants AND populate
the currently-hollow `non_supported_dispatchable` inverse detector, so the CI gate FAILS when a
non-VPP family handler would enable VPP it must not — or a non-supported chip routes to a real
handler with a VPP mismatch. This closes the v1.12 accepted tech debt (CR-01 hollow-GATE-03).

Purpose: This is the security spine of Phase 71. The recurring project hazard is VPP mis-enable
on a non-VPP family / a non-supported chip reaching a real write handler (Phase 66 SC#3, v1.12
CR-01). The gate must be able to FAIL on that condition, not merely exist hollow.
Output: extended gate + a test proving it stays green on the clean DB and goes red on a synthetic
violating fixture.
</objective>
