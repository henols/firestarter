# Phase 71 Plan 02: Authored Validation Matrix + Codegen Summary

**One-liner:** Authored JSON matrix spec (D-01) + deterministic codegen script emit
a committed C++ header for native suites; schema validation and drift gate are in place.

## What Was Built

### Task 1: validation_matrix_spec.json + gen_validation_header.py + test_matrix_schema.py

**firestarter_app/tools/validation_matrix_spec.json** — The D-01 authored input.
Single hand-maintained JSON file enumerating all 6 algorithm families:

| Family ID    | Handler                | Protocols (decimal)  | Rep Chip   |
|--------------|------------------------|----------------------|------------|
| eprom        | configure_eprom        | 7, 8, 11             | W27C512    |
| eeprom28c    | configure_eeprom28c    | 13                   | AT28C256   |
| flash3       | configure_flash3       | 6                    | AM29F040   |
| flash4       | configure_flash4       | 5, 53, 57            | SST39SF040 |
| flash_intel  | configure_flash_intel  | 16                   | AM28F010   |
| sram         | configure_sram         | 14, 39, 40, 41       | 6116       |

Protocol union: {5,6,7,8,11,13,14,16,39,40,41,53,57} = 13 protocols as required.

**firestarter_app/tools/gen_validation_header.py** — Codegen script mirroring
`tools/catalog/codegen.py` shape:
- `validate_spec(spec)` raises ValueError on schema violations BEFORE emission
  (T-71-INPUT mitigation: schema_version must be int, families non-empty, each
  family must have id/handler/protocols, protocols must be list of ints)
- `emit_cpp_header(spec)` emits deterministic C++ header: sorted protocols per
  family, no timestamps, LF endings via `write_text(encoding="utf-8", newline="\n")`
- `main()` returns 0/1/2 (ok/schema-fail/spec-not-found)
- ruff-clean; py3.11+ compatible

**firestarter_app/tests/test_matrix_schema.py** — 17 tests:
- Positive: valid full spec + 6-family spec both pass validate_spec()
- Negative: 9 cases for ValueError (missing schema_version, wrong type,
  missing families, empty families, missing handler, missing id, missing
  protocols, protocols not list, protocols with string element)
- Shipped spec: 6 families, all 6 handlers, integer protocols, union = 13 IDs

TDD: RED committed (import error, spec/script missing), GREEN committed (all 17 pass).

### Task 2: validation_matrix.h (committed) + test_gen_validation_header.py (drift gate)

**firestarter/test/native/avr/_shared/validation_matrix.h** — Generated C++ header
committed to the firmware submodule (same posture as messages.h):

```c
/* DO NOT EDIT -- generated by tools/gen_validation_header.py
 * Re-run after editing tools/validation_matrix_spec.json */

#pragma once

#include <stdint.h>

#define VAL_FAMILY_COUNT 13

typedef struct {
    uint32_t protocol;
    const char* family_id;
    const char* handler_name;
} val_family_entry_t;

static const val_family_entry_t VAL_FAMILIES[] = {
    { 0x07, "eprom", "configure_eprom" },
    ...  // 13 rows total
};
```

**firestarter_app/tests/test_gen_validation_header.py** — 12 tests (drift gate):
- Header exists in firestarter submodule
- Has DO NOT EDIT banner
- Has VAL_FAMILIES + VAL_FAMILY_COUNT
- Has exactly 13 rows
- Re-running codegen → byte-identical to committed header (T-71-DRIFT gate)
- Malformed spec → exit 1, no output written (validate-before-emit)
- Parametrized × 6: all configure_* handler names present in committed header
