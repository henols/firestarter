<objective>
Build the gate that actually prevents the hardware 12 V-on-OE path from reaching a `0x0D` chip, and
prove it can fail.

Purpose: ERASE-04. The roadmap's criterion 3 says `tools/check_dispatch.py` is not to be weakened,
and implies it is what stops the wrong erase path. `D-153-03` records that it is not: that checker
operates at the database and dispatch-table layer and cannot see a control-register write inside a
handler body — while the hardware path already exists in this tree, in the sibling file an executor
also edits this phase. So the real control has to be built, not merely left intact.

Output: one checker, one paired test module with a committed planted-violation fixture, and the
evidence that `check_dispatch.py` itself is untouched.
