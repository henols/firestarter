<objective>
Move the generator to one honest representation per value: voltages as millivolt integers, timing
as microsecond integers, and no unit-suffixed string paired with its own numeric twin.

The seed's schema is **locked** (**D-07**) — `vcc: "5V"` -> `vcc_mv: 5000`; `vdd` -> `vdd_mv`;
`vpp` + `vpp_mv` -> `vpp_mv` only; `pulse_duration` -> `pulse_duration_us`. `chip_id_value` stays a
hex string, and `type` / `support_status` / `pinout` / `part_number` stay categorical. Clean break,
**no tolerant reader**.

`vdd` survives as `vdd_mv` (**D-05**) — it is load-bearing generator input consumed by the shipped
SRAM normalization, by `diff_db.py`'s classification, and (from Plan 06) by the margin-rail rule.
It is not surfaced anywhere and that stays true.

**Two emission paths exist, not one** (RESEARCH F-1). `tools/extra_chips.json` is merged
post-decode and byte-faithful at `build_db.py:829-859`, so its two records would otherwise ship the
old schema after the migration and D-10's direct indexing would raise `KeyError` on both. Migrating
it is a **deliberate hand edit to an authored supplement** — it is emphatically *not* a hand edit to
generated JSON.

**Expected transient:** after this plan the suite is RED on `firestarter/database.py` and
`tools/audit_coverage_matrix.py` consumers. Plan 04 and Plan 05 restore it. This plan's verify is
scoped to what it can honestly prove.

Purpose: end the half-done numericalization.
Output: a regenerated 746-chip database on the numeric schema, with `diff_db.py` still reporting
the identical bucket distribution — the proof that the migration changed no *value*.
</objective>

<planner_decisions>
- **P-04 (D-08 failure mechanism — settled here, not deferred).** `interpret_timing` **raises
  `ValueError`**; it does not call `sys.exit`. The message names both the protocol
  (`{protocol_id:#04x}`) and the unparseable value (`{raw_hex!r}`), which is exactly what D-08's
  discretion clause requires. Rationale: `interpret_timing` is a leaf decode function, and this
  repo's two `SystemExit` precedents — `diff_db._load_db` and
  `check_mypy_watermark.classify_mypy_result` — are both top-level gate/orchestration functions.
  **Measured load-bearing property:** nothing between the call site (`build_db.py:759`) and
  `main()`'s frame catches `ValueError` — `:441` and `:465` are `except Exception` but both are
  lexically *before* `chip_entry` construction and scoped to the network fetch and the
  package-details filter respectively — so an uncaught `ValueError` aborts `main()` **before** the
  JSON write, and no partial or wrong database is emitted.
- **`VPP_VOLTAGES` is deleted, not left dead.** Its only consumer is the `"vpp"` string emit this
  plan removes (verified: `grep` finds `VPP_VOLTAGES` at `:90` definition and `:740` use, nowhere
  else). A cited-but-dead string table is the "bypassed, not gone" shape DATA-03's discipline
  rejects. The `[VERIFIED: minipro/src/database.c + tl866a.c + tl866ii_vpp_voltages[] table]`
  preamble and its 0xF0-mask rationale **move** to sit above the surviving `VPP_MV` table so the
  citation is never orphaned.
- **`VCC_VOLTAGES` itself is not semantically edited** (**D-01**). Index `0x02` is a *faithful*
  decode of `infoic.xml`'s VCC nibble `2` and is `[VERIFIED: minipro database.c#L130-L135 @
  a8efaedc]`. Only its **values** become millivolt integers, per D-07. The margin-rail correction
  is a separate post-construction rule and belongs to Plan 06.
