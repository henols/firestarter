<objective>
Replace `cli_handlers.py`'s hardcoded null firmware identity with a real, prerelease-preserving one
harvested off the connection the hardware-revision read already opens, and carry the rename through
its entire mock surface.

Purpose: this is the finding that opens milestone v1.32 — every `dev test` report ever filed carries
`fw_board_identity: null`, so gh#21 and gh#32 (host `3.0.0b15`, unknown firmware) cannot be
distinguished from a board lacking the whole Phase-117–120 `0x0D` fix stack. The mechanism already
exists on the wire: the CAP-02 `MSG_OK_READY` ack puts the raw `"<version>:<board>"` string on
`comm.firmware_identity` **before** the dispatch switch runs (`serial_comm.py:412`), and
`HardwareManager` already holds that communicator.

Output: a populated, suffix-preserving `fw_board_identity` in every new report, captured with zero
additional serial connections.

**Evidence Ceiling (binding, PROJECT.md §Current Milestone: v1.32).** No AT28C part exists in
operator inventory. Nothing in this plan may require real silicon, assert the `0x0D` write path is
proven, graduate `0x0D` out of `UNVERIFIED`, change any `support_status`, or be phrased as closing
gh#21/#32/#11/#12. This plan makes future reports *attributable*; it proves nothing about the write
path.

**No firmware change.** `firestarter/` is read-only reference. Phase 149 owns the only
firmware-touching workstream.
</objective>

    would mangle `"3.0.0b19:leonardo"` into `"3.0.0b19_leonardo"`. Policy, exactly:
      - `raw is None` returns `None`.
      - `raw == ""` returns `None`.
      - Otherwise every character in the printable-ASCII range `0x20`–`0x7E` inclusive is kept
        verbatim (so `:`, `.`, digits and letters all survive) and every other character — U+FFFD from
        `serial_comm.py`'s `errors="replace"` decode, `\n`, `\r`, any control byte — is replaced by a
        single `"?"`.

        32 (`firestarter.cpp`), so 64 is slack, not a functional limit.
      - If the result is empty, return `None`.

    place of the bad bytes and therefore stays visibly faulty (D-07: a mangled identity is evidence of
    a transport fault, never silently converted to unknown), while an identity with **no** printable
    content collapses to `None` because there is no evidence to preserve and PROV-05 forbids a blank
    rendering. That collapse resolves RESEARCH Open Question 3 explicitly, in favour of collapsing —
    it is a planner decision, not an accident of an `or`.
