<objective>
Build the unit-level oracles for the capture seam's failure and edge paths, and prove at handler level
that an absent identity renders the explicit marker while the saved JSON stays typed `null`.

Purpose: RESEARCH measured that `tests/test_hardware.py` has **13 tests and none of them touch the
value-returning hardware read at all** — the method plan 147-02 widened had zero unit coverage. That
makes PROV-02's "no extraneous connection" claim and D-04's "the two values fail independently" claim
unproven at the level where they are actually decidable. And D-13's unknown leg is a defensive path
(`_probe_port` refuses firmware that reports no identity), so it must be proven at two levels that
genuinely run rather than left as a pre-authored RED.

Output: the W-1 unit legs and the D-13(b) handler leg, all reachable and seen to pass inside this plan.

**Evidence Ceiling (binding, PROJECT.md §Current Milestone: v1.32).** Every leg here runs against
fakes and mocks. Nothing may require real silicon, assert the `0x0D` write path is proven, graduate
`0x0D` out of `UNVERIFIED`, change any `support_status`, or be phrased as closing gh#21/#32/#11/#12.

**No firmware change.** `firestarter/` is read-only reference; Phase 149 owns the only
firmware-touching workstream.
