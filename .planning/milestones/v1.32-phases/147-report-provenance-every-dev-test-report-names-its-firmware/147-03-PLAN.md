<objective>
Bump the report schema to 1.4 with a documented rationale, and make an absent firmware identity render
as an explicit unknown in the human console surface — while the fenced JSON keeps typed `null`.

Purpose: `str(None)` renders as the four characters `None` in the `rich` table, which reads to a
triager like a captured value rather than an absent one. That is the whole of the PROV-05 defect, and
`hw_revision` carries it identically one row below — shipping a marker above a bare `None` would
invite a reader to treat the difference as meaningful.

Output: `SCHEMA_VERSION = "1.4"`, one new marker constant, one render-boundary helper, two fixed rows,
and a non-vacuous render oracle.

**Evidence Ceiling (binding, PROJECT.md §Current Milestone: v1.32).** No criterion here may require
real silicon, assert the `0x0D` write path is proven, graduate `0x0D` out of `UNVERIFIED`, change any
`support_status`, or be phrased as closing gh#21/#32/#11/#12.

**No firmware change.** `firestarter/` is read-only reference; Phase 149 owns the only
firmware-touching workstream.

**Requirement flips: none — `requirements:` is deliberately empty.** That array is not an "addresses"
label: `execute-plan.md`'s `update_requirements` step feeds it verbatim to
`gsd-tools query requirements.mark-complete`, which ticks each listed ID's checkbox in REQUIREMENTS.md
the moment this plan finishes. This plan *completes* neither requirement it touches, so it names
neither.

What this plan *advances*, for the verifier's benefit:

  a report written by an earlier version still parses. That proof is the frozen null-identity fixture
  and `test_legacy_null_identity_body_still_parses_and_groups` in plan `147-05`. **PROV-04's flip is
  owned by `147-05`.**

  in `diagnostic_report.py`). PROV-05 also requires the issue-parser surfaces, whose marker literals are

| Boundary | Description |
|----------|-------------|
| report model → public GitHub issue | `to_dict()` is serialised into a fenced JSON block in a community-visible issue body via `submit.py` |
| report model → terminal | `render()` writes a `rich` table a maintainer reads and acts on |
