<objective>
Turn a comment nobody checks into an enforced claim.

`firestarter_app/firestarter/constants.py:144` has carried a "Firmware sync: `json_parser.c`
(`key_page_size`)" note that was **measured false** — no such key existed in the firmware until plan
04 created it. PGSZ-03 requires the two repos to hold the same constants inside one milestone branch,
verified by a cross-repo check. The fail-closed scan infrastructure this needs already exists
(`tests/fw_presence.py` plus the committed inventory in `tests/scan_paths.py`), so this phase adds one
inventory entry and one test module, not a mechanism.

Two properties make this gate worth more than a string comparison. First, the assertion must prove the
key is **dispatched**, not merely declared — a PROGMEM string that never appears in `key_parsers[]`
exists and never matches anything, which is the hole a naive presence check misses. Second, the
planted-violation legs must carry **no** `requires_fw` decorator: they read committed fixtures, so they
stay live in app CI where the sibling firmware checkout is absent. Without that split the gate would
be entirely unexercised in the only environment that runs on every push.

Purpose: make criterion 3's cross-repo parity a machine-checked fact for all three `JSON_KEY_*`
constants, not just the new one.
Output: the parity module, two planted fixtures, one inventory entry, and the skip-leg transcript. The
change under test is **software-proven and unvalidated on silicon**.
</objective>

- **The assertion compares the hyphen form.** The internal database key is `page_size` with an
  underscore; the **wire** key is `page-size` with a hyphen. `constants.py`'s `JSON_KEY_PAGE_SIZE` is
