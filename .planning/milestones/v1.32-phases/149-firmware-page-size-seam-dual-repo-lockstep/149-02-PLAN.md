<objective>
Arm the honesty gate **before** the artifacts it protects are written, and resolve the one measured
defect that would otherwise make it unsatisfiable by its own required phrase.

Every prior claim gate in this project carries `("proven-unqualified", re.compile(r"\bproven\b",
re.IGNORECASE))`. `\b` fires after a hyphen, so PGSZ-05's mandated phrase — the words
**software-proven and unvalidated on silicon** — is itself a `proven-unqualified` violation. Copied
verbatim, D-19's gate would simultaneously require and forbid the same sentence. The repo already
documents this property at `146-check-claims.py:63-65`; Phase 146 could write *around* the word, and
Phase 149 cannot. This plan narrows the pattern with a negative lookbehind and proves, with a
committed negative control, that a bare "proven" still fails.

Purpose: make PGSZ-05 machine-checkable while the artifacts are being authored, which is when
overclaims get written — not three phases later when nothing can be retracted.
Output: `149-check-claims.py`, its paired suite, its fixtures, and both RED and GREEN transcripts.
The subject the gate guards is a change that is **software-proven and unvalidated on silicon**.
</objective>

  `_DEFAULT_TARGETS`, and NOT in any SUMMARY.** The RED transcript necessarily contains forbidden
  phrases. Plan 08 extends the target list to every `149-*-SUMMARY.md`; a SUMMARY quoting a planted
  overclaim would make the closing gate RED. A dedicated non-target file is the only shape that keeps
  both the transcript and the gate honest. A test leg asserts the transcript file is absent from
  `_DEFAULT_TARGETS`.
- **`_DEFAULT_TARGETS` at this plan's authoring time is exactly one entry: `149-PAGE-SIZE.md`.**
  The gate has no exit-0-on-nothing-scanned branch (deliberately not ported from Phase 137's
  checker), and it fails closed on a target missing from disk. So it cannot name a SUMMARY that does
  not exist yet. Plan 08 extends the list once every SUMMARY exists and re-runs RED→GREEN. Two
  transcripts, both real — this is `149-RESEARCH.md` §R9e's recommended option 1.
- **The `firestarter_app/README.md` changelog line is scanned via `argv`, not `_DEFAULT_TARGETS`.**
  It lives outside `_HERE`, so `_assert_default_targets_are_local()` would reject it. `resolve_targets`
  supports positional argv precedence for exactly this, and the self-check only validates
  `_DEFAULT_TARGETS`. Plan 08 runs that argv form.
- **Prefer unwindowed forbidden patterns.** Each windowed (`{0,3}` / `{0,4}`) form is measurably
  weaker than an unwindowed one, so each windowed pattern gets its own committed plant.
- **Worktree isolation MUST be OFF for this plan: set `USE_WORKTREES_FOR_PLAN=false`.** This is an
  instruction, not a footnote. `git worktree add` on this superproject leaves **both** submodules with
  **0 entries**, and GSD's per-plan worktree gate intersects only `files_modified` against
  `.gitmodules` paths — a **lower bound** that cannot see a plan which merely *reads* a submodule. So
  read `commits_land_in` **plus the task bodies**, not `files_modified`. This plan's `commits_land_in` is
  `[meta, firestarter, firestarter_app]`, where **both submodules are read-only** — every commit lands

  **not a git repository at all**, so each `rev-parse` exits non-zero and the `&&` chain fails —
  closed. That, not tree-cleanliness, is the mechanism that makes the flag load-bearing here.
  Cleanliness is gated only where it is actually invariant: `git -C /workspaces/firestarter status

  stderr and leaves `test -z` inspecting empty stdout, i.e. it would fail **open**.
