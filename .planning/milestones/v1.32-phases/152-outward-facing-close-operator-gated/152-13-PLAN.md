Write `152-check-not-auto.py`, a small stdlib-only guard whose whole job is to exit non-zero when the
project configuration says an auto or chained run is active. It answers RESEARCH Open Question 5 with
a mechanism instead of a restatement.

Behaviour:
- Accept an optional `--config PATH` argument, defaulting to the repository's own configuration file,
  so the guard is testable against fixtures rather than only against live state.
- Read the configuration's workflow block and the key that records auto/chain activity — use the exact
  key name confirmed from the live file, not an assumed one.

  it was read from, and the reason: every outward requirement in this phase is operator-reviewed before
  posting, and auto/chain modes auto-approve human-verify checkpoints.

  state is not a safe state. Say so in the message. This is the same fail-closed discipline the claim
  gate uses and it is the whole value of the guard.

workflow block and the one key are enough — and note in a comment that they are fixtures, not
configuration.

names the key in its output; and the guard exits 0 against the falsy fixture. Add a third leg asserting
it exits non-zero when pointed at a path that does not exist.
