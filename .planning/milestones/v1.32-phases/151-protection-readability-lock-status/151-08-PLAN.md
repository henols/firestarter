<objective>
Land both read sequences in firmware: a shared single-byte read in vendor-ID mode, two
family-specific status-read operations, their dispatch arms, the `loop()` arm and the operation
entry point.

Purpose: LOCK-02, D-02. The `0x06` half covers 190 database rows through
`configure_flash_nor_unlock`; the `0x05` half covers 27 rows through `configure_flash_5v_page`
and is the half funded to make the v1.17 W29C040 locked-boot-block question answerable from the
read side. `0x10` is deliberately unimplemented and ships as `not_implemented`.

What exists to build on, measured: `flash_util_get_chip_id` already issues `FLASH_ENABLE_ID`,
reads `0x0000` and `0x0001`, then issues `FLASH_DISABLE_ID` — so the AMD/JEDEC mode entry and
exit are already in the tree and already exercised by both target handlers. A protect-verify
read is that function with a different read address. What does **not** exist, at all: any read
at a computed status address, any protected/unprotected byte decode, any Product-ID-mode entry
distinct from `FLASH_ENABLE_ID`, and any sector map. Those come from `151-SEQUENCES.md`.

Output: `flash_util_read_in_id_mode`, up to two new pinned `byte_flip_t` tables, two
`*_read_protection_execute` operations, two dispatch arms, `eprom_lock_status`, and the `loop()`
arm — plus native legs in the two existing family suites.

**Leonardo growth budget, and it is not the MERGE-05 band.** Every byte this plan adds lands on
all three AVR targets, and leonardo carries **two** distinct flash ceilings with two failure
modes. The **MERGE-05 band is 0 B** and fails **loudly** — `check_size_baseline.py --policy
merge05` goes red, and plan `151-10` funds it with a named exemption. The **Caterina cliff is
28672 B** and fails **silently**: quick task `260820-a7w` raised the reported `flash_total` to the
ATmega32U4's real 32768 B by forfeiting Caterina's 4096 B, and
`firestarter/platformio.ini:87-94` states the accepted trade — *"the linker no longer protects the
top 4096 B, so firmware that grows past 28672 B will be linked into and flashed over Caterina,
bricking USB bootloader entry on this board. There is deliberately no compensating guard
(T-a7w-01)."* With live `flash_used` 27212 the safe budget is **28672 − 27212 = 1460 B** — much
larger than the 0 B band, but **unguarded and unrecoverable-by-CI**: no checker in this repository
tests it, and an exemption would satisfy the MERGE-05 gate while still bricking the board. Treat
1460 B as a hard budget to stay inside; if this plan's bytes would cross it, that is a
**STOP-and-report** for `151-10`, not something to absorb. Do **not** add a bootloader-safe guard —
the operator declined one twice, at a7w (T-a7w-01) and again in CONTEXT.md §"Deferred Ideas". Same
discipline as the native warning watermark's zero headroom, different axis.

**Requirement flips owned by this plan: none.** It advances LOCK-02.
</objective>

| Boundary | Description |
|----------|-------------|
| host command frame → chip bus | `CMD_LOCK_STATUS` drives real address and data cycles onto a socketed part. |
| decode constants → emitted status byte | A coerced decode turns an unrecognised silicon value into a confident claim. |
| operation path → VPP/VPE rails | A stray control-register write on a 5 V part is a hardware-damage risk. |
