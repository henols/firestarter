<objective>
Open the firmware's memory-command admission path to one new command, `CMD_LOCK_STATUS 16`,
and move every site that mirrors the admitted set — in both repos — in the same change.

Purpose: LOCK-02 and OD-3. The gate at `firestarter/src/firestarter.cpp:74` is the ordinal
test `if (handle->cmd < CMD_READ_VPP)`, and `CMD_READ_VPP` is 11. Slots 0-10 are exhausted —
`firestarter/include/firestarter.h:73-75` records that "Slots 9 and 10 were the only two free
command values" — so a command at 16 falls into neither arm today and receives no
`json_parse()` and no `configure_memory()`: `handle->protocol` stays 0 and the bus config,
pin map and mem size are never populated. Option (b), re-ordering the enum, breaks wire
compatibility with every shipped firmware and every host constant. Option (c) is structurally
impossible because `firestarter_get_data` is a protocol-handler function pointer set by
`configure_memory`. OD-3 therefore takes option (a): widen the gate to
`is_memory_cmd(handle->cmd) || handle->cmd < CMD_READ_VPP`.

That is a change to a safety-adjacent ordinal test. `is_memory_cmd()`'s own preamble records
that it is "an ACCESS-CONTROL GATE, not hygiene ... configure_eprom() (reached only through
this gate) enables the 12V VPP boost regulator — a hazard on a 5V part." So this plan states
in its own artifacts that the admission set grew from eight commands to nine, and re-proves
the exhaustive truth table in both DEV_TOOLS states.

Output: the enum entry, the ninth `is_memory_cmd` arm, the widened parse gate, all four
mirror sites, the host constant pair, and a new non-vacuous source-scan test for the gate
expression itself.

**Leonardo growth budget, and it is not the MERGE-05 band.** Every byte this plan adds lands on
all three AVR targets, and leonardo carries **two** distinct flash ceilings with two failure
modes. The **MERGE-05 band is 0 B** and fails **loudly** — `check_size_baseline.py --policy
merge05` goes red, and plan `151-10` funds it with a named exemption. The **Caterina cliff is
28672 B** and fails **silently**: quick task `260820-a7w` raised the reported `flash_total` to the
ATmega32U4's real 32768 B by forfeiting Caterina's 4096 B, and
`firestarter/platformio.ini:87-94` states the accepted trade — *"the linker no longer protects the
top 4096 B, so firmware that grows past 28672 B will be linked into and flashed over Caterina,
bricking USB bootloader entry on this board. There is deliberately no compensating guard
(T-a7w-01)."* With live `flash_used` 27212 the safe budget is **28672 − 27212 = 1460 B** — much
larger than the 0 B band, but **unguarded and unrecoverable-by-CI**: no checker in this repository
tests it, and an exemption would satisfy the MERGE-05 gate while still bricking the board. Treat
1460 B as a hard budget to stay inside; if this plan's bytes would cross it, that is a
**STOP-and-report** for `151-10`, not something to absorb. Do **not** add a bootloader-safe guard —
the operator declined one twice, at a7w (T-a7w-01) and again in CONTEXT.md §"Deferred Ideas". Same
discipline as the native warning watermark's zero headroom, different axis.

**Requirement flips owned by this plan: none.** It advances LOCK-02; the flip belongs to
`151-13`.
</objective>
