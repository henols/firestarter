<objective>
Run the three bench legs that exist, record every raw result either way, and write down in one
artifact exactly what each leg earned and what it did not.

Purpose: D-03, and the honest accounting of it. D-03 frames the W29C040 run as an exploratory
**probe**, never validation, and its correction is load-bearing: `lockable-proms.md` §1 documents
**W29C040 / W29C040P** as *"Variant-dependent — Boot blocks or SDP — Must check the exact suffix
and revision"*. It is **not** in the documented-readable set. The part that is documented readable
is **W29C020 / W29C020C**. v1.17's finding that the operator's W29C040 carries a permanently
locked first-16K boot block is **empirical** — write→verify failed across the range — not a
documented readable-status claim.

Research added a genuinely new finding that changes what this session can earn. The `0x05`
sequence **decomposes**, and its mode-entry half is verifiable on silicon with **zero new code**:
`firestarter id W29C020` already drives `CMD_CHECK_CHIP_ID` → `flash_5v_page.cpp:54-57` →
`flash_utils.cpp:82-87`, which issues `FLASH_ENABLE_ID`, reads `0x0000`/`0x0001` and issues
`FLASH_DISABLE_ID`, and it must return **`0xDA45`**. That is a real positive control on the
`AA/55/90` → read → `AA/55/F0` transition, on this exact part and socket, and it is gated by none
of D-03, D-06 or D-07 because it is an existing shipped command exercising existing shipped code.

Output: `.planning/phases/151-protection-readability-lock-status/151-BENCH.md`.

**Requirement flips owned by this plan: none.** LOCK-02 and LOCK-03 were flipped by `151-13` on
software evidence. Nothing here may flip a requirement, and nothing here may upgrade a claim.

**⚠ This plan must NOT be run under `--auto` or `--chain`.** Those auto-approve human-verify and
human-action gates, and every gate below is the only thing standing between an unattended run and
a chip in a socket. `autonomous: false` alone does not protect this plan.
</objective>

    independent oracle is write→verify, which is destructive **and** is the *indirect* method

    plausibility judgement, not a verification.

    needs one, and the only oracle a write would supply is the one the definition of "readable"
    excludes.
