# devtest skills: close superseded failures, label by cause, report fix versions

## Operator ruling (2026-08-31)

Triaging the open `dev test` backlog surfaced a rule the skill did not have:

> "all issues that are reporting FAIL and has a later are reported PASS must be
> directly defered since they are fixed and cant be considered as valid"

`devtest-triage` held the **opposite** position — "a `PASS` in a group folds as
EVIDENCE, never closes the canonical" — so a failure a later report showed passing
stayed open forever, burying live work under noise.

Two follow-on rulings shaped the rest:

- PASS issues carry a label saying what they are and **no reference to the
  validated-EPROM ledger** — an internal repo path the reporter cannot open brings
  them nothing.
- Neither skill may "describe things that was and no longer applies, it give no
  useful information to the LLM".

## Scope

`.claude/skills/devtest-triage/` and `.claude/skills/devtest-rootcause/` in the meta
repo. No product source touched; no chip database regenerated.

## Tasks

1. Add a supersede test to `devtest_issues.py` and rework `cmd_fold` around it.
2. Add a shared label taxonomy with a `labels` subcommand.
3. Teach `devtest-rootcause` to report the artefact versions carrying a fix, and to
   label `fix:committed` / `fix:released`.
4. Sweep both skills of text describing what the code used to be.
5. Resolve `/workspaces` hardcoding so the skills work in any checkout.
6. Triage the live backlog under the new rules.

## Constraint

Closing an issue is outward-facing. The three-leg test makes the *decision*
mechanical, but `fold --apply` stays operator-gated — the dry run is shown first.
