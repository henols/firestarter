> **Outward-facing. Do not execute this plan with `--auto` or `--chain`.** Those flags auto-approve
> human-verify gates in this project, and `autonomous: false` alone does **not** protect a gate. This
> plan publishes an **immutable** artefact to PyPI that every default `pip install firestarter` will
> resolve. Both checkpoints below are `blocking-human` and must be reached with a person present.

<objective>
Turn the merged commit into something a stranger's `pip install` will actually get, and then prove it
by installing it — not by reading the diff.

The operator cuts the tag and the release by hand, because `release.yml` cannot push to a protected
`main`, and dispatches `publish.yml` by hand, because its `release: published` trigger has never
fired in the eight runs this repository has ever had. The agent then reads PyPI live and re-runs
191-01's fixture, unmodified, against whatever the index now serves.

Purpose: STABLE-01 is the publish and STABLE-02 is the proof. The proof only means something because
the identical script already went red against the pre-cut stable in 191-01 — that pair of transcripts
is the entire argument, and neither half is worth anything alone.
Output: a published stable, a live PyPI reading, and the green half of the fixture pair.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator → PyPI | An immutable public artefact is created; nothing downstream can withdraw it, only yank it. |
| PyPI index → every future `pip install` | The published distribution becomes the default artefact for every user of this project. |
| GitHub Actions → PyPI | `publish.yml` builds and uploads using the repository's `PYPI_API_TOKEN` secret. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-191-04-01 | Tampering | publishing an artefact built from the wrong commit | high | mitigate | The tag is created on the merge commit read back from the contents API in 191-03, and `publish.yml` checks out that tag by name via its `tag` input. The fixture then reads the endpoint out of the *installed* package, so a build from the wrong ref would surface as a redirect reading, not pass silently. |
| T-191-04-02 | Repudiation | treating the publish run's green tick as verification | high | mitigate | The verification is a live `pypi.org/pypi/firestarter/json` read plus a clean-room install of whatever the index serves. The run's conclusion is recorded as context and explicitly labelled as not the verification. |
| T-191-04-03 | Elevation of privilege | `PYPI_API_TOKEN` held by the publish workflow | medium | accept | The token is a repository secret used only by `publish.yml`; nothing in this plan reads, prints or handles it, and no upload happens from this container. Unchanged by this phase. |
| T-191-04-04 | Spoofing | a green fixture run produced by a modified fixture or a shadowing install | high | mitigate | The script is asserted byte-identical to the committed one before it runs, and the transcript's `installed_file:` line is asserted to resolve inside the scratch venv. `--no-cache-dir` closes the stale-wheel path. |
| T-191-04-05 | Denial of service | a wrong version number spent permanently | medium | mitigate | The version is confirmed at an explicit `checkpoint:decision` before the act, with the immutability consequence stated in words and the observation — not the prediction — as its basis. |
