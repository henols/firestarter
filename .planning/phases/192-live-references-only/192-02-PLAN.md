<environment_notes>
PATH `grep` in this devcontainer is ugrep and honours `.gitignore`, so it silently under-scans. Every
command whose evidence depends on seeing every file uses the absolute `/usr/bin/grep`, and every file
set is enumerated with `git ls-files`, never with a shell glob.

`/usr/bin/grep -c` exits 1 when the count is 0, so a leg that legitimately expects 0 carries a trailing
`|| true` and is judged on its printed number, not its exit status.

There is no nested subagent dispatch available to a GSD executor in this devcontainer, so
`map-codebase.md`'s `detect_runtime_capabilities` step routes to `sequential_mapping`. That is the same
workflow at the same scope, performed in-context — not a substitute for it.

`.planning/config.json` is dirty in the working tree before this plan starts, from a pre-existing
GSD-verb defect that pruned two `planning.sub_repos` entries. It is not this phase's work and must not
be staged or committed here.
