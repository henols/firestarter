<objective>
Give `write` an opt-in `--verify` that reads the written region back through Phase 202's comparison
engine, reports one combined verdict line that never says "successful", and carries Phase 202's
0/1/2 exit contract for that invocation only. `--full` rides along with the meaning it already has on
`verify` and `blank`.

Purpose: WRITE-04 and WRITE-05, and roadmap criterion 4. This is also the phase's one-way door — the
exit-code contract is a published CLI surface that Phase 207's REL-04 will document in the wiki — so
it opens with a decision checkpoint.

Output: `--verify` and `--full` on `write`, four verdict-line constants, `suppress_verdict_line` on
both operator methods, and `tests/test_write_verify.py`.
</objective>

  <name>Task 1: Confirm the `--verify` exit-code contract before it is published</name>
  <decision>
`firestarter write --verify` will opt that invocation into Phase 202's three-code contract —
**0** verified, **1** the write failed or the comparison mismatched, **2** a transport or hardware
failure anywhere in the invocation including the guard read — while plain `firestarter write` keeps
its existing **0 / 1** contract unchanged. One command will therefore carry two exit contracts,
selected by a flag, and the `--verify` help text will say so.
  </decision>
  <context>
This is the phase's only one-way door. Exit codes are a published CLI contract: scripts and CI jobs
branch on them, Phase 207's REL-04 will document them in the wiki, and changing them afterwards
breaks callers rather than requiring a refactor. CONTEXT rates D-13 `one-way` for exactly that
reason, and D-13 was decided by Claude after the operator answered "you decide" — so unlike the other
sixteen decisions, this specific option was never chosen by a human.

What the alternatives cost:
- **Confirm as decided (recommended).** WRITE-05 covers the `--verify` path and nothing covers plain
  `write`, so this is the narrowest widening that the requirements actually motivate. Cost: one
  command with two contracts, accepted and documented in `--help` rather than left as folklore.
- **Give plain `write` the 0/1/2 contract too.** More consistent, but it changes the meaning of exit
  1 for every existing caller of `firestarter write` with no requirement asking for it, and the wider
  CLI-consistency question is already on the backlog from Phase 202's deferred list.
- **Keep `--verify` on 0/1 as well.** Simplest, but it makes a transport failure indistinguishable
  from a genuine mismatch on the one path where the difference matters most — which is the exact
  property Phase 202's CMP-07 was written to secure for `verify` and `blank`.

Undo cost if this turns out wrong: every script branching on `write --verify`'s exit code, plus a
wiki correction, plus a version note. There is no code migration — the cost is entirely borne by
callers outside this repository.
  </context>
