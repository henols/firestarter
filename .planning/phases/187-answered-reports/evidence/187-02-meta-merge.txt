--- Post-merge git cherry (D-05 equivalence proof) ---

  $ git cherry origin/beta gsd/v1.37-operator-safety-answered-reports-claim-hygiene-activated-202
  ^+ count (new commits, ahead of beta)        : 0
  ^- count (already-equivalent commits on beta): 0

  Both counts are 0, which is the correct and strongest form of post-merge equivalence for a TRUE
  merge (not a squash): once `beta`'s tip is a real two-parent merge commit whose second parent is
  this branch's tip, every commit formerly unique to this branch is now a literal ancestor of
  `origin/beta`, so `git rev-list origin/beta..branch` is empty and `git cherry` has nothing left
  to compare — not merely "180 commits found patch-equivalent" (which is what a squash-merge
  would have produced), but "180 commits no longer unique at all." This preserves the per-commit
  correspondence `git cherry` relies on for the rest of the phase, as required by this task's
  action (a squash would have destroyed it).
