## Tests

### 1. Disposition of WR-01 (negative start address passes the host alignment guard)

expected: An explicit (a) file-as-debt or (b) fix-now decision.

**What is true, live-reproduced against the current tree:**
`firestarter write W29C020 <file> -a -256` passes the host alignment guard and exits 0.
`parse_address` does not reject negatives, and Python's `%` returns a non-negative
result for a negative dividend, so `-256 % 256 == 0` reads as "aligned".

**What the verifier and the code review could not determine, and the orchestrator has
since resolved:** what the firmware does with a negative address on the wire.
`simple_strtoul` in `firestarter_fw/src/json_parser.c:30` consumes only `[0-9]`;
a leading `-` is not a digit, so the loop body never runs and the function returns 0.
Confirmed by compiling the function verbatim and running it: `-256` -> 0, `-1` -> 0.

**Therefore the actual consequence is narrower than the review could establish.** A write
requested at a negative address silently lands at **address 0** — which is page-aligned,
for a length already proven to be a whole number of pages. So it erases nothing outside
the range it writes, and it does not violate WRITE-01 or WRITE-02. It is a
**wrong-destination** defect (a silent clamp to 0 where a refusal belongs), not a
partial-page-destruction defect, and it is out of scope for this phase's four success
criteria, all of which concern alignment and length rather than address sign.
