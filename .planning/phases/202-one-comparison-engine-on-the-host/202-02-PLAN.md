<objective>
Prove the property the whole milestone rests on: the host comparison is bounded independently of
device size, in memory and in output volume, and is not slower than the firmware path it replaces.

CMP-03 is a memory requirement and RESEARCH.md measured a 5300-fold separation between the streaming
and materialised shapes, so the memory assertion is easy and unflakeable. The hazard is the one
nobody flagged: a literal reading of D-02 produces a per-byte, per-bit inner loop that costs 19.8
seconds over 512 KiB and still passes every memory assertion. This plan pins both.

It also completes CMP-05's engine half: coalescing, ordering, adjacency, the `MAX_RETAINED_RANGES`
boundary and the exactness of the D-16 tail counters.

Purpose: make the two properties that are invisible in a functional test into failing tests.
Output: a bounded-memory, bounded-runtime, honestly-counted accumulator with the bounds asserted.
</objective>

D-02 forbids a device-sized materialised offset list. It does not forbid a chunk-sized one, and the
distinction is worth roughly eleven times in runtime. An executor reading D-02 literally writes the
21-second version and passes every memory assertion in task 1. This task makes that outcome a red
test instead of a shipped regression.

Add two runtime tests over a 512 KiB simulated device in 1024-byte chunks, each timing only the
feed-and-finalise cycle with `time.perf_counter`, never wall-clock time including fixture setup.

The first drives the all-matching pattern and asserts the elapsed time is under 1.0 second. RESEARCH
measured 0.002 seconds for the equality fast path and 19.8 seconds for the naive per-byte loop, so
the gate sits five hundred times above the good shape and twenty times below the bad one.

The second drives the every-byte-differs pattern and asserts under 8.0 seconds. RESEARCH measured
1.9 seconds for the per-chunk offset list with a hoisted per-bit sum and 21.4 seconds for the nested
per-offset per-bit loop. Both gates discriminate the shape, neither can flake on a loaded runner.

Give both tests a docstring naming what a failure means: not "the machine was slow" but "the inner
loop descended to per-byte work on a chunk that compared equal, or the per-bit sum was nested inside
the per-offset loop". Cite the three measured figures in that docstring so the next reader does not
have to re-derive the budget.

Add a structural companion test that does not depend on timing at all: parse
`CompareAccumulator.feed`'s source with `ast` and assert the function body contains a comparison of
the expected chunk against the actual chunk whose true branch returns before any per-offset
iteration. A timing test tells you the shape regressed; this one tells you where.

Put a comment at the fast path in `compare.py` recording why it is there, in the repo's convention of
naming the rejected alternative: the counter-only shape that avoids lists entirely was measured at
21.4 seconds against 1.9, for roughly 79 KB less peak.

  <action>
Complete CMP-05's engine half and close the adjacency, ordering, empty, boundary and precision edges
for CMP-03 and CMP-05.

Coalescing and adjacency. Assert that a run of differing bytes spanning a chunk boundary yields one
`MismatchRange` covering the whole run, not one per chunk — the open range must survive across
`feed` calls and only close when a matching byte or `finalise` closes it. Assert that two differing
spans separated by exactly one matching byte stay two ranges, and that two spans which touch end to
start become one. Assert that no two entries in `CompareResult.ranges` touch or overlap.

Ordering. Assert `ranges` is sorted ascending by `start` and that feeding the identical synthetic
input twice produces equal range lists, so the output order is specified and stable rather than
incidental.

Empty and single-element. Assert that an accumulator finalised with no `feed` call at all returns a
result with `total` 0, `compared` 0, `bad` 0, an empty `ranges` list, `extra_ranges` 0, `extra_bytes`
0, and `compared_end` equal to `compared_start` minus one — and that it raises nothing. Assert the
same for a single one-byte chunk, matching and differing. Add a comment at that test naming the trap
it guards: a zero-length read-back compares as perfect equality, and only a length gate distinguishes
it from a genuine clean pass, so the engine must report it honestly rather than defensively.

The `MAX_RETAINED_RANGES` boundary, and one step either side. Construct inputs producing exactly
`MAX_RETAINED_RANGES` minus one, exactly `MAX_RETAINED_RANGES`, and exactly `MAX_RETAINED_RANGES`
plus one coalesced ranges. Assert nothing is dropped and `extra_ranges` is 0 in the first two, and
that the third retains exactly `MAX_RETAINED_RANGES` entries with `extra_ranges` equal to 1 and
`extra_bytes` equal to that range's byte count.

Precision. Drive the alternating pattern over a 512 KiB simulated device — the case D-16 names, which
produces roughly 262144 coalesced ranges — and assert three things: `len(result.ranges)` equals
`MAX_RETAINED_RANGES`; `extra_ranges` plus `MAX_RETAINED_RANGES` equals the true total range count;
and `extra_bytes` plus the byte counts of the retained ranges equals `result.bad` exactly. Every
printed count must be an exact integer from a counter, never a list length and never derived from a
float. Assert that `result.bad` and every `MismatchRange.count` are `int` instances.

Assert `render_compare_lines` emits nothing at all for a clean result, and that for a capped result
its final line carries both the extra range count and the extra byte count taken from those counters.

Add a comment at the cap in `compare.py` recording that the cap bounds what is shown and never what
is counted — that is the standing prohibition this plan carries, and it is the difference between a
bounded report and a quiet under-count.
  </action>

    - Two differing spans separated by one matching byte produce exactly two ranges; two touching spans produce exactly one.

    - `ranges` is sorted by ascending `start`, and two identical feeds produce equal range lists.

    - For the alternating 512 KiB case, `extra_ranges` plus `MAX_RETAINED_RANGES` equals the true range count, and `extra_bytes` plus the retained ranges' counts equals `bad`.
    - `render_compare_lines` returns an empty list for a result with zero bad bytes.
    - `result.bad` and every `MismatchRange.count` are `int`, not `float`.
  </acceptance_criteria>
