## Notes

- This file is generated by `.claude/skills/devtest-triage/scripts/eprom_ledger.py`.
  A hand edit to any table is discarded on the next write. Notes are preserved.
- A family is named after the firmware protocol constant that programs it, in
  `firestarter_fw/include/proto_constants.h`. The name follows from the family key, so
  adding a chip never renames a family that was already present. Where one protocol
  covers several pinouts or rails, the name carries the pinout, and the rail too if the
  pinout does not separate them.
- A validated chip is evidence for its untested family siblings, never proof. The family
  key fixes the programming path, the socket wiring and the programming rail. It does not
  fix the values that path reads — see the Family variation table for how much varies.
- `PROTO_EPROM_28PIN` and `PROTO_SRAM_28PIN` carry no size variation, so every member is
  the capacity that was validated. `PROTO_FLASH_5V_PAGE`, `PROTO_FLASH_NOR_UNLOCK` and
  `PROTO_EPROM_32PIN` do vary: a larger sibling drives address lines the validated part
  never drove, which on 32-pin parts is where the JP4 and JP5 straps decide whether the
  socket is wired correctly at all.
- `PROTO_FLASH_5V_PAGE` also varies in page size, and that protocol reads the part's real
  page size when it writes. A sibling with a page size other than 128 or 256 runs a
  different write than anything recorded here.
- Chip ID is per-part. No family shares identity bytes, so a sibling whose recorded ID is
  wrong fails at the `id` step however well its family is validated.
- AE29F2008 (ASD) and W29C020 (Winbond) are separate database entries whose fields are
  identical on every value, including the chip ID `0xDA45`. They are the same silicon
  sold under two names. Both rows are kept because two distinct physical parts were tested.
- `Firmware` reads `not reported` where the report carried no firmware identity. The host
  cannot read a firmware prerelease suffix, so it is never inferred from the host version.
- `Chip ID` reads `none` where the part reports no identity. The `id` step is then `NA`,
  which is not a failure.
