# Documentation Reorganization — Shaping Notes

## Scope

Reorganize and correct all user and developer documentation in the wiki and in the three repos.

- The wiki is the user manual: install, read chips, program chips, a short part on the beta
  channel, and the relevant technical reference.
- The meta `README.md` is the hub. It points to the wiki and to the two sub-repo READMEs. The meta
  repo holds the only change log (`CHANGELOG.md`) and `VALIDATED-EPROMS.md`.
- The `firestarter_app` and `firestarter_fw` READMEs point to the meta README and to their own
  technical documents. Those documents are short and relevant. They do not repeat what the wiki
  already explains.
- Every document has the logo. The logo files are only in the meta repo. No document links to a
  datasheet. The Ko-fi ("buy me a coffee") link is on every entry page.

## Decisions

- D-1. One change log: `CHANGELOG.md` in the meta repo, for CLI and firmware. The app
  `CHANGELOG.md` and the wiki `Breaking-Changes` page are removed.
- D-2. Delivery: a `docs/reorganize` branch and a PR to `main` in each repo. No merge by Claude.
  The wiki is committed locally and pushed only after the operator approves. Nothing goes to
  `beta`, because each push to `beta` publishes.
- D-3. Logo: `images/branding/firestarter_logo_horizontal.png` in the meta repo, referenced by one
  absolute raw.githubusercontent.com URL. All other logo files in app and fw are deleted.
- D-4. Ko-fi: `https://ko-fi.com/E1E21I2WWW` only (operator-confirmed). It goes on the meta README,
  the app and fw READMEs, wiki Home and `_Sidebar`. The badge is a shields.io image.
- D-5. Wiki `Lockable-PROMs` is deleted. Nothing replaces it.
- D-6. The wiki is for users and the repos are for developers. Wiki Pin-Maps keeps the socket
  tables. `PINOUTS.md` keeps only the shield internals. `PROTOCOLS.md` becomes a short developer
  reference.
- D-7. In scope: delete app `val-results/`, clean `tools/DECODE-NOTES.md`, and clean the
  `platform/py32f071/` records together with the fw tests that pin them.
- D-8. The stable pages describe 3.1.0. Beta-only behaviour appears only on the beta page and in
  the change log.
- D-9. No internal process words in any doc in scope. Out of scope: `CLAUDE.md` files (except one
  stale release-hazard paragraph), `agent-os/`, `.claude/`, test fixtures.

- D-10. Every document in scope is written with the `asd-ste100` skill (operator request).
  STE-flavored mode for READMEs, the change log and wiki prose. Strict mode for install and
  programming procedures and for warnings. `ste-lint.py --disable synonym-rotation` reports 0 hard violations on each file. The
  synonym-rotation rule is lexical, so it is advisory in STE-flavored mode.

## Context

- **Visuals:** None.
- **References:** see `references.md`.
- **Product alignment:** `agent-os/product/mission.md` asks for "honest claims". The docs state
  what is validated on silicon, and they state limits. `roadmap.md` said stable was still 2.0.x.
  That is stale: 3.1.0 shipped on 2026-09-26.

### Inventory findings that shaped the work

- The pages disagree on which version is stable (Install says 3.x, Breaking-Changes says 2.0.9).
  Stable 3.1.0 shipped on 2026-09-26. Beta is at 3.1.0b5.
- Wiki Breaking-Changes uses internal milestone IDs (v1.32, v1.20, v1.10) as version headings.
- Both 3.1.0 GitHub releases have empty notes.
- The wiki hot-links the old pixel-art logo from `firestarter_app`.
- Two Ko-fi IDs were in use. `E1E21I2WWW` has been in both READMEs since 2025-07-18.
  `M4M2Z7VNE` replaced it at the end of the app README on 2026-08-31 in a docs-cleanup commit.
  The operator confirmed `E1E21I2WWW`.
- All 8 datasheet links were on the wiki Lockable-PROMs page.
- `firestarter_fw/PINOUTS.md` repeats the wiki Pin-Maps tables. `PROTOCOLS.md` has about 100
  phase and requirement references.
- No wiki page explains how to read a chip.
- fw tests pin the `platform/py32f071/*.md` records by path and content.
- `VALIDATED-EPROMS.md` is generated by `.claude/skills/devtest-triage/scripts/eprom_ledger.py`.

## Standards Applied

- host/help-docstrings — the same rule for user docs: no internal references.
- testing/non-vacuity — the fw tests that pin the py32f071 records change with the records.
- testing/standalone-checkout — the changed tests still read only their own repo.
- testing/no-source-introspection — no new test scans doc text for style; tests prove behaviour.
